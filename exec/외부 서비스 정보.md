# 외부 서비스 정보

> SSAFY 자율 프로젝트 A303 (Colosseum / BEANS) — 가입 및 활용에 필요한 외부 서비스 정리

본 프로젝트는 멀티플레이 네트워킹 / 게임 서버 호스팅 / 정적 페이지 배포 / 상태 저장소 / CI·CD 의 다섯 영역에서 외부 서비스를 사용한다.
**소셜 인증 / OAuth / 결제 / 푸시 등 서드파티 SaaS는 사용하지 않는다.**

---

## 1. Photon Fusion 2 (Photon Engine)

게임 클라이언트와 Dedicated Server 간 실시간 네트워킹에 사용. **본 프로젝트의 핵심 외부 의존성**이다.

| 항목 | 값 |
|---|---|
| 서비스 | Photon Engine — Fusion 2 |
| 콘솔 URL | https://dashboard.photonengine.com/ |
| 가입 방식 | 이메일 회원가입 (개인) |
| SDK 버전 | Fusion 2 (`com.exitgames.photonfusion` 1.1.0) |
| 라이센스 | 100 CCU 한도 |
| 사용 영역 | Lobby ↔ Game Server ↔ Client 실시간 통신, Tick-based Simulation |
| 발급 필요 키 | **App ID (Fusion)** 1종 — `93dd4431-...` 형식 UUID |
| 미사용 키 | App ID (Chat), App ID (Voice) — 빌드 시 빈 값으로 처리됨 |
| Region 설정 | `UseNameServer: 1` + `FixedRegion: ""` (자동 선택) |

### 가입 / 발급 절차
1. https://dashboard.photonengine.com/ 회원가입
2. **CREATE A NEW APP** → Photon Type **Fusion** 선택
3. 생성된 앱의 **App ID** 복사
4. App Version 문자열 결정 (예: `1.0.0-deploy`)
5. GitLab Project → Settings → CI/CD → Variables 에 등록
   - `PHOTON_APP_ID_FUSION` = (복사한 App ID)
   - `PHOTON_APP_VERSION` = `1.0.0-deploy`

### 활용 위치
- 빌드 시점: GitLab CI 파이프라인이 `PhotonAppSettings.local.asset` sidecar를 동적으로 생성하여 Unity 빌드에 주입 (빌드 종료 즉시 삭제).
- 런타임: 클라이언트와 Lobby/Worker 서버가 Photon Cloud의 NameServer를 통해 매칭되고, 게임 시작 후에는 Dedicated Server(Worker EC2)를 통한 인증형 Tick 통신 수행.

## 2. AWS EC2 (Amazon Web Services)

게임 서버 / API 서버 / 정적 페이지 호스팅에 사용. 총 **4개 인스턴스**.

| 인스턴스 | 역할 | 호스트 / IP | 노출 포트 | 비고 |
|---|---|---|---|---|
| Onboarding | Client.zip 다운로드 페이지 | `k14a303.p.ssafy.io` (Public) | 80 | Nginx Docker |
| Lobby | Unity Lobby Server + SSH Jump Host | `52.79.120.24` (Public Elastic IP) | 22, Photon UDP | nohup + PID 파일 |
| API | Spring Boot Room Registry | `10.0.2.189` (VPC Internal) | 8081 (VPC 내) | Docker Compose |
| Worker | Unity Game Server + Worker Agent | `10.0.2.112` (VPC Internal) | 8080 (VPC 내), Photon UDP | Docker Compose (host network) |

### 가입 / 발급 절차
1. AWS 계정 생성 (https://aws.amazon.com/)
2. 리전 선택: **ap-northeast-2 (Seoul)**
3. VPC + Subnet (Public 1, Private 1) 구성
4. EC2 인스턴스 4종 생성 (Ubuntu 22.04 LTS 권장)
5. Security Group 규칙 적용 — `버전 정보 및 배포 특이사항.md` §3-5 5번 항목 참조
6. SSH 키페어 생성 → GitLab CI/CD Variable에 등록 (3종)
   - `SSH_LOBBY_KEY` (Lobby 직접 접속)
   - `SSH_PRIVATE_SUB_KEY` (API/Worker — ProxyCommand 경유)
   - `SSH_ONBOARDING_KEY` (Onboarding 보조)
7. 각 인스턴스에 Docker 24+ / Docker Compose v2 설치 (Lobby 제외)
8. SSAFY 도메인 `k14a303.p.ssafy.io` 의 A 레코드를 Onboarding EC2의 Public IP로 매핑

### 활용 위치
- 빌드/배포 산출물 호스팅
- 게임 세션 실행 (Worker)
- 게임 방 메타데이터 API 제공 (API)
- 매칭/로비 (Lobby)

## 3. AWS ElastiCache for Redis

게임 방 상태 저장소. **본 프로젝트의 유일한 영속 저장소** (RDB 미사용).

| 항목 | 값 |
|---|---|
| 서비스 | AWS ElastiCache for Redis |
| Endpoint | `master.colosseumcache.toprbz.apn2.cache.amazonaws.com:6379` |
| Region | ap-northeast-2 (Seoul) |
| Engine 버전 | Redis 7.x |
| 암호화 | **TLS / In-Transit Encryption 활성화** (`REDIS_SSL_ENABLED=true`) |
| 인증 | 없음 (VPC Security Group으로만 격리) |
| 사용 키 패턴 | `rooms:all` (Set), `rooms:<roomId>` (Hash/JSON) |

### 가입 / 발급 절차
1. AWS Console → ElastiCache → Redis OSS → **Create**
2. Cluster Mode: Disabled (단일 마스터)
3. Engine version: Redis 7.x
4. Node type: 최소 `cache.t4g.micro` 권장
5. Encryption in-transit: **Enabled**
6. Subnet Group: API/Worker/Lobby EC2가 위치한 VPC의 Private Subnet
7. Security Group: API/Worker/Lobby EC2의 Security Group으로부터의 6379 TCP 인바운드 허용
8. 생성 후 **Primary Endpoint** 복사 → API/Worker EC2의 `~/<...>/.env`의 `REDIS_HOST` 에 등록

### 활용 위치
- API 서버(Spring Data Redis): 방 생성/조회/삭제 시 Redis 직접 read/write
- Worker 서버: 게임 세션 상태 동기화
- Lobby 서버: 방 목록 조회

### 로컬 개발 시 대체
로컬 환경에서는 `infra/localbuild/docker-compose.yml`이 자동으로 `redis:7-alpine` 컨테이너를 띄운다. `REDIS_SSL_ENABLED=false` 로 동작.

## 4. GitLab (SSAFY GitLab) — CI/CD

소스 저장소 + CI/CD 파이프라인 호스팅.

| 항목 | 값 |
|---|---|
| 서비스 | SSAFY GitLab |
| 프로젝트 URL | https://lab.ssafy.com/s14-final/S14P31A303 |
| Runner | Self-hosted Runner (Tag: `colosseum-deploy`) — 팀 소유 호스트 1대 |
| Runner 사전 설치 | Unity Editor 2022.3.62f3 + git-lfs + Docker + dotnet 8 SDK + JDK 21 |

### 가입 / 발급 절차
1. SSAFY 계정으로 GitLab 로그인
2. 프로젝트 Member로 초대 (팀장 권한)
3. GitLab Runner 등록
   ```bash
   sudo gitlab-runner register \
     --url https://lab.ssafy.com/ \
     --registration-token <PROJECT_TOKEN> \
     --executor shell \
     --tag-list colosseum-deploy
   ```
4. Project → Settings → CI/CD → Variables 에서 위 §1~§3 의 모든 시크릿 등록
   - File Variable로 등록할 항목: SSH 키 3종
   - Masked / Protected 옵션 활성화

### 활용 위치
- `master` 브랜치 push 시 자동 빌드/배포
- 수동 Web 트리거 (`TARGET` 변수로 부분 배포 가능)

## 5. Unity (Unity Technologies)

Unity Editor 라이센스. 게임 클라이언트 / Linux Dedicated Server 빌드에 필요.

| 항목 | 값 |
|---|---|
| 서비스 | Unity Hub / Unity Cloud |
| 콘솔 URL | https://id.unity.com/ |
| 라이센스 | **Unity Personal (Free)** — 매출 200K USD 미만 |
| Editor 버전 | **2022.3.62f3 LTS** (정확히 동일) |
| 추가 모듈 | Linux Dedicated Server Build Support, Windows IL2CPP, Linux Build Support (IL2CPP) |

### 가입 / 발급 절차
1. https://id.unity.com/ Unity ID 회원가입
2. Unity Hub 다운로드 및 설치
3. Personal 라이센스 활성화 (Hub → Preferences → Licenses → Add)
4. Unity Editor `2022.3.62f3 LTS` 설치 + Linux Dedicated Server 모듈 추가
5. GitLab Runner 호스트에서도 동일 Editor 설치 + manual license 활성화
   ```bash
   /opt/unity/Unity-2022.3.62f3/Editor/Unity \
     -batchmode -quit -nographics \
     -manualLicenseFile /path/to/Unity_v2022.x.ulf
   ```

### 활용 위치
- GitLab CI/CD `build:server-linux` / `build:client-windows` job
- 개발자 로컬 PC

## 7. 시크릿 보안 정책

| 시크릿 | 저장 위치 | 평문 노출 방지 |
|---|---|---|
| Photon App ID | GitLab CI/CD Variable (Masked) | 빌드 시점에 sidecar로만 주입, 빌드 후 즉시 삭제 |
| AWS Redis Endpoint | EC2 내부 `.env` (Git 미커밋) | `.gitignore` 등록 + Security Group으로 외부 차단 |
| SSH Private Key | GitLab CI/CD File Variable (Protected + Masked) | Job 종료 시 자동 폐기 |
| Unity 라이센스 파일 (`.ulf`) | GitLab Runner 호스트 로컬 (Git 미커밋) | 별도 권한 관리 |

> 동봉된 [`.env`](./.env) 파일은 채점 편의를 위한 통합 스냅샷이며, 실제 운영 환경에서는 위 표대로 분리 보관된다.
