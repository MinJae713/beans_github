## 3. 배포 시 특이사항

### 3-1. 인스턴스 구성도

```
[Player PC]
    │ (HTTPS 80)
    ▼
[Onboarding EC2]  k14a303.p.ssafy.io    ← Nginx 1.27 / Client.zip 정적 서빙
    │
    │ 게임 클라이언트 실행
    ▼
[Lobby EC2]   52.79.120.24 (Public)     ← Unity Linux Dedicated Server (mode=lobby)
                                          ↑ SSH Jump Host 역할도 수행
              ┌────────────┴────────────┐
              ▼                         ▼
[API EC2] 10.0.2.189:8081       [Worker EC2] 10.0.2.112:8080
  Spring Boot + Docker            Worker Agent + Unity Game Server
  (Room Registry)                 (mode=game, host network)
              │
              ▼
[AWS ElastiCache Redis]  master.colosseumcache.toprbz.apn2.cache.amazonaws.com:6379 (SSL)
```

### 3-2. CI/CD 파이프라인

- **트리거 조건**
  - `master` 브랜치 push (자동) — 변경 경로에 따라 자동 분기
  - Web 수동 실행 (`$CI_PIPELINE_SOURCE == "web"`) — `TARGET` 변수로 명시 선택
- **Stage**: `validate` → `build` → `deploy`
- **Job 분기 규칙**
  - `build:server-linux` — `unity/**` 또는 `worker-agent/**` 또는 `infra/remotebuild/**` 변경 시
  - `build:client-windows` — `unity/**` 변경 시 (Onboarding 타겟)
  - `deploy:api` — `server/**` 또는 `infra/remotebuild/APIServer/**` 변경 시
  - `deploy:lobby/worker/onboarding` — 각 인프라 디렉토리 변경 시
- **전체 빌드 + 배포 소요 시간: 약 8분**
- **GitLab Runner Tag**: `colosseum-deploy` (Self-hosted Runner 1대 사용)

### 3-3. 배포 방식 차이 (서버별)

| 서버 | 방식 | 비고 |
|---|---|---|
| API | Docker Compose | `colosseum-api` 컨테이너 + Bind Mount `.env` |
| Worker | Docker Compose (host network) | `colosseum-worker-agent` + Unity Server 바이너리 volume mount (`./Server-Linux:/gameserver:ro`) |
| Lobby | **nohup + PID 파일** (Docker 미사용) | `~/lobby.pid` / `~/lobby.log` / `~/lobby.out` |
| Onboarding | Docker Compose (Nginx) | `colosseum-onboarding`, `/downloads/Client.zip` 자동 zip 생성 |

### 3-4. SSH 접속 토폴로지

- **Lobby EC2** (`52.79.120.24`) — 공개 IP. `SSH_LOBBY_KEY`로 직접 접속.
- **API / Worker EC2** — 내부 IP만 보유. Lobby를 **SSH Jump Host (ProxyCommand)** 로 경유하여 `SSH_PRIVATE_SUB_KEY`로 접속.
- **Onboarding EC2** — `SSH_ONBOARDING_KEY` 사용 (현재 GitLab Runner가 Onboarding과 동일 호스트일 경우 SSH 미사용).

### 3-5. 빌드/배포 전 사전 조건

1. **GitLab Runner 호스트에 Unity Editor 설치 필수**
   - 경로: `/opt/unity/Unity-2022.3.62f3/Editor/Unity` (환경변수 `UNITY_EDITOR_PATH`로 오버라이드 가능)
   - 라이센스: Unity Personal Free 라이센스 활성화 필요 (`Unity -batchmode -quit -manualLicenseFile`)
2. **Git LFS 필수** — Unity 텍스처/스프라이트가 LFS로 관리됨. Runner에 `git lfs` 설치 필수.
3. **Docker / Docker Compose 필수** — 모든 EC2 인스턴스 (Lobby 제외)
4. **Photon AppSettings 보안 주의** — `PhotonAppSettings.local.asset`은 Git 커밋 금지 (`.gitignore` 등록됨). 빌드 시 sidecar 방식으로만 주입.
5. **방화벽 / Security Group**
   - Lobby: TCP 22, Photon 클라이언트 통신 포트 개방
   - API: 8081 (Worker/Lobby에서만), 22 (Lobby에서만)
   - Worker: 8080 (Lobby에서만), Photon 통신 포트, 22 (Lobby에서만)
   - Onboarding: 80, 22
   - Redis: 6379 (API/Worker/Lobby에서만, AWS Security Group)

### 3-6. 로컬 환경에서 빌드 (개발자용)

상세 가이드: [`infra/localbuild/LocalBuild.md`](../../projects/S14P31A303/infra/localbuild/LocalBuild.md) 참고.

요약:
1. Unity Hub에서 Server + Client 빌드 (Build Both)
2. `cd server && ./gradlew bootJar` → `infra/localbuild/server-0.0.1-SNAPSHOT.jar`로 복사
3. `infra/localbuild/` 에서 `docker compose up -d` (Spring Boot + Redis 7-alpine 동시 기동)
4. `worker-agent` 에서 `dotnet run -- --game-server-exe "<Server.exe 경로>" --listen-url "http://0.0.0.0:8080"`
5. `Builds/Server/Colosseum-Server.exe` 실행
6. `Builds/Client/Colosseum.exe` 실행 (플레이어 수만큼)

## 4. 프로젝트(ERD) 활용 주요 계정 및 프로퍼티 파일 목록

> **본 프로젝트는 RDB(MySQL / PostgreSQL / H2 등)를 사용하지 않는다.**
> 모든 게임 방(Room) 상태는 **AWS ElastiCache Redis** 에만 저장되며, Spring Data Redis 기반 단순 Key-Value 구조 (`rooms:all`, `rooms:<id>` 등)를 사용한다.
> 따라서 SSAFY 요구사항 중 "DB 덤프 파일"은 해당 사항 없음. ERD 또한 별도 제공하지 않는다.

### 4-1. 주요 프로퍼티 / 설정 파일 목록

| 파일 경로 | 역할 |
|---|---|
| `server/src/main/resources/application.yml` | Spring Boot 설정 (Redis 접속, port 8081, context-path /api/v1) |
| `server/build.gradle` | Spring Boot / Java 21 / 의존성 정의 |
| `worker-agent/Colosseum.WorkerAgent.csproj` | Worker Agent .NET 8 프로젝트 정의 |
| `unity/Packages/manifest.json` | Unity 패키지 의존성 |
| `unity/Assets/Photon/Fusion/Resources/PhotonAppSettings.asset` | Photon Fusion 기본 설정 (AppId는 빈 값, sidecar override 사용) |
| `infra/localbuild/Dockerfile` | 로컬 통합 실행용 Spring Boot 이미지 |
| `infra/localbuild/docker-compose.yml` | 로컬 통합 실행 (Spring + Redis) |
| `infra/remotebuild/APIServer/Dockerfile` | API EC2 배포용 Spring Boot 이미지 |
| `infra/remotebuild/APIServer/docker-compose.yml` | API EC2 Compose 정의 |
| `infra/remotebuild/WorkerServer/Dockerfile` | Worker EC2 배포용 .NET 8 + Unity 런타임 의존성 |
| `infra/remotebuild/WorkerServer/docker-compose.yml` | Worker EC2 Compose 정의 (host network, gameserver volume) |
| `infra/remotebuild/OnboardingPage/docker-compose.yml` | Onboarding EC2 Nginx 정의 |

### 4-2. 주요 계정 / 시크릿

| 항목 | 보관 위치 | 비고 |
|---|---|---|
| EC2 `ubuntu` 계정 SSH Key | GitLab CI/CD File Variable (3종) | `SSH_LOBBY_KEY`, `SSH_PRIVATE_SUB_KEY`, `SSH_ONBOARDING_KEY` |
| Photon Fusion App ID | GitLab CI/CD Variable | `PHOTON_APP_ID_FUSION` (sidecar 주입, 빌드 후 삭제) |
