# 관찰로그 최소 스키마

이 문서는 플레이테스트와 구현 리허설에서 남겨야 할 전투 관찰 로그의 최소 필드를 정의한다.

이 문서는 raw 로그 파일을 저장하는 위치나 실제 수치 임계값을 고정하지 않는다. raw 로그, 스크린샷, 영상은 팀이 합의한 레포 밖 또는 ignore된 로컬 artifact 경로에 두고, 기준문서에는 요약과 판단만 남긴다.

## 로그 목적

관찰 로그는 디버깅 로그가 아니라 전투 원인을 분리하기 위한 기록이다.

| 목적 | 의미 |
|---|---|
| 원인 추적 | 사망, 돌파, 카드 선택, 구조물 개입 원인 분리 |
| 네트워크 검증 | Host/Client가 같은 결과를 보는지 확인 |
| 밸런스 근거 | 수치 변경 전 어떤 양상이 반복되는지 확인 |
| 문서 검증 | 기준문서의 상태머신과 실제 구현이 맞는지 확인 |

## 이벤트 공통 필드

| 필드 | 의미 |
|---|---|
| event_id | 이벤트 식별자 |
| event_type | hit, death, breakthrough, card_offer, card_pick, respawn 등 |
| match_id | 매치 또는 세션 식별자 |
| tick_or_time | Fusion tick 또는 로컬 기록 시간 |
| authority | StateAuthority, InputAuthority, Local 중 기록 기준 |
| actor_player | 행동 또는 결과를 만든 플레이어 |
| target_player | 영향을 받은 플레이어. 없으면 비워둠 |
| segment_id | 현재 구간 식별자 |
| round_state | CombatActive, ChoicePending 등 상태머신 상태 |
| cause | 직접 피격, 위치 이탈, 구조물, 자원 고갈, 상태 전이 문제 등 |
| result | 피해, 사망, 돌파, 선택 확정, 요청 거절 등 |

필드명은 구현에서 조정할 수 있지만, 위 의미가 빠지면 플레이테스트 원인 분리가 어렵다.

## 전투 이벤트 추가 필드

| 이벤트 | 추가 필드 |
|---|---|
| hit | projectile_id, weapon_profile_id, card_tags, hit_position, knockback_direction |
| death | death_cause, last_hit_event_id, last_actor_player, boundary_context |
| breakthrough | breaker_player, defender_player, direction, is_final_segment |
| respawn | respawn_reason, segment_id, spawn_anchor_type |
| card_offer | eligible_player, offer_card_ids, offer_policy_id |
| card_pick | picker_player, selected_card_id, validation_result |
| card_reject | requester_player, reject_reason |

추가 필드는 수치값 자체보다 원인과 연결을 우선한다. 예를 들어 “피해량이 얼마였는가”보다 “어떤 카드 태그와 어떤 투사체 계열이 결과를 만들었는가”가 먼저다.

## 저장과 공유 기준

| 대상 | 기준 |
|---|---|
| raw 로그 | 팀이 합의한 레포 밖 또는 ignore된 로컬 artifact 경로 |
| 기준문서 | raw 로그가 아니라 요약, 판단, 후속 질문만 기록 |
| 플레이테스트 리포트 | 관찰된 event_type, cause, result를 요약 |
| 버그 리포트 | 재현 절차와 관련 event_id 또는 요약 로그만 첨부 |

Photon App ID, secret, 계정 정보, 개인 절대경로는 로그 요약에도 포함하지 않는다.

## 구현 연결

- `CombatObservationEvent` 같은 런타임 이벤트 구조를 둘 수 있다.
- 테스트 수집기나 파일 sink는 런타임 이벤트를 구독하는 방식이 좋다.
- StateAuthority가 확정한 결과와 local presentation 이벤트를 구분한다.
- 카드 선택 요청/확정/거절은 별도 이벤트로 남긴다.
- 구간 돌파와 사망은 같은 tick에서 충돌할 수 있으므로 상태머신 우선순위와 함께 기록한다.

## 금지

- raw 로그를 기준문서에 계속 누적하는 것.
- App ID, secret, 개인 절대경로가 들어간 로그를 공유 문서에 붙이는 것.
- Host 한쪽에서만 보인 local-only 이벤트를 authoritative 결과처럼 기록하는 것.
- 수치 임계값을 이 문서의 통과 기준처럼 고정하는 것.

## 미결정

- 실제 C# 이벤트 타입 이름과 필드명.
- 로그를 런타임 버퍼로만 둘지, 테스트 수집기와 파일 sink를 함께 둘지.
- card_offer 정책 id를 카드 프리셋에 둘지 별도 OfferPolicy에 둘지.
