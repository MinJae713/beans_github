# 관찰지표 정의

이 문서는 플레이테스트와 구현 리허설에서 무엇을 관찰해야 밸런스 판단을 할 수 있는지 정의한다.

이 문서는 수치 목표를 고정하지 않는다. 전투 시간, 피해량, 탄속, 쿨타임, 장탄수, 선택 제한 같은 값은 `BalanceProfile`, 무기/카드 프리셋, 플레이테스트 기록에서 관리한다.

## 목적

플레이테스트의 목적은 "재밌었다" 또는 "강했다" 같은 감상만 남기는 것이 아니라, 어떤 전투 양상이 발생했고 어떤 원인으로 승패가 갈렸는지 추적하는 것이다.

| 목적 | 의미 |
|---|---|
| 원인 분리 | 사망, 돌파, 구조물, 카드, 무기 원인을 구분 |
| 반복 관찰 | 같은 문제가 여러 테스트에서 반복되는지 확인 |
| 수치 변경 근거 | BalanceProfile 변경 이유를 감상이 아니라 관찰로 남김 |
| 전투 양상 보호 | 위치 기반 킬각과 반격 여지가 유지되는지 확인 |
| 구현 리스크 노출 | 네트워크 truth, 입력 충돌, 프리팹 충돌을 조기 발견 |

## 관찰 단위

| 단위 | 기록 목적 |
|---|---|
| 매치 | 최종 승패, 전장 전체 밀고 밀림, 누적 카드 영향 |
| 구간 | 구간 돌파, 방어 성공, 카메라 압박, 구조물 영향 |
| 라운드 | 사망/돌파/카드 선택/리스폰 상태 전이의 자연스러움 |
| 교전 | 피격, 탄 소모, 재장전, 넉백, 경직, 회피 판단 |
| 이벤트 | 마지막 피격, 마지막 넉백, 구조물 작동, 경계 이탈 |

플레이테스트 리포트는 가능하면 매치 단위 감상과 이벤트 단위 원인을 함께 기록한다.

## 핵심 관찰축

| 관찰축 | 확인 질문 |
|---|---|
| 전투 체감 | 전투가 선택/리스폰보다 충분히 중심 경험인가 |
| 위치 킬각 | 체력 삭제보다 벽 몰이, 카메라 압박, 경계 이탈이 살아있는가 |
| 반격 가능성 | 맞은 뒤에도 이동, 엄폐, 반격, 탄 소모 유도 중 하나가 가능한가 |
| 카드 영향 | 패배 보상이 전투 양상을 바꾸되 확정 승리가 되지 않는가 |
| 무기 역할 | 각 무기 후보가 서로 다른 압박 방식과 대응법을 만드는가 |
| 구조물 영향 | 구조물이 역전 창구와 위험을 만들되 억울하지 않은가 |
| 네트워크 일관성 | Host/Client가 같은 결과를 보고 같은 상태로 전이하는가 |
| 가독성 | 관전자와 플레이어가 사망/돌파 원인을 이해할 수 있는가 |

## 사망 원인 분류

사망이나 라운드 결과는 아래 범주로 먼저 분류한다.

| 원인 | 의미 |
|---|---|
| 직접 피격 | 투사체 피해나 직접 공격 결과 |
| 위치 이탈 | 넉백, 벽 몰이, 경계 이탈, 카메라 압박 |
| 구조물 | 위험 지형, 압사, 반사체, 이동 발판, 상호작용 오브젝트 |
| 자원 고갈 | 탄약, 재장전, 점프/대시 소모, 회피 실패 |
| 상태 전이 문제 | 사망/돌파/선택/리스폰 순서가 불명확하거나 충돌 |
| 표현 부족 | 실제 판정은 맞지만 신호가 부족해 억울하게 느껴짐 |

사망 원인을 분리하지 못하면 피해량이나 체력 수치를 먼저 바꾸지 않는다.

## 좋은 신호

- 패배자가 다음 구간에서 다른 반격 플랜을 시도한다.
- 승자가 단순 화력보다 위치, 재장전, 구조물, 카메라 압박을 활용한다.
- 돌파와 사망이 모두 전투 결과로 납득된다.
- 무기 후보별로 대응 방식이 다르게 나온다.
- 구조물 때문에 생긴 결과를 플레이어가 이해하고 다음 시도에서 대응한다.
- 카드 선택 후에도 상대가 대응 가능한 창구를 가진다.

## 위험 신호

| 신호 | 우선 확인할 원인 |
|---|---|
| 첫 피격 후 사실상 사망 | TTK, 넉백, 회복 입력, 피드백 부족 |
| 카드 선택 후 일방 승리 | 카드 효과 분류, 누적 제한, 카운터 부재 |
| 구조물 사망이 억울함 | 사전 신호, 회피 경로, 카메라 가시성 |
| 구간이 한 무기만 유리 | 구간 패턴, 엄폐/고저차/반사체 배치 |
| 돌파보다 킬만 중요함 | 경계 압박, 카메라 압박, 리스폰/전선 구조 |
| Host/Client 결과 불일치 | network truth, StateAuthority, local-only 처리 |

위험 신호가 보여도 즉시 수치를 바꾸지 않는다. 먼저 해당 신호가 규칙 문제인지, 레벨 구조 문제인지, 피드백 문제인지, 프리셋 문제인지 분리한다.

## 리포트에 남길 항목

플레이테스트 또는 리허설 기록은 최소한 아래 정보를 남긴다.

| 항목 | 기록 내용 |
|---|---|
| 사용 프리셋 | BalanceProfile, WeaponProfile, CardDefinition 후보 |
| 사용 구간 | 구간 패턴, 구조물 유형, 카메라/경계 특이점 |
| 사용 무기/카드 | 후보 계열과 선택 이유 |
| 주요 결과 | 사망, 구간 돌파, 방어 성공, 매치 승리 |
| 결과 원인 | 직접 피격, 위치 이탈, 구조물, 자원 고갈, 상태 전이 문제 |
| 관찰자 판단 | 좋은 신호, 위험 신호, 다음 실험 가설 |
| 후속 작업 | 프리셋 실험, 문서 수정, 구현 버그, 미결정 등록 |

원본 로그, 영상, 스크린샷은 팀이 합의한 레포 밖 또는 ignore된 로컬 artifact 경로에 두고, 기준문서에는 요약과 판단만 남긴다.

## 구현 연결

- 사망 원인, 마지막 피격, 마지막 넉백, 구간 돌파 원인은 로그로 남길 수 있어야 한다.
- 로그 필드의 실제 이름과 저장 방식은 구현 세션에서 결정하되, 최소 의미는 `20_전투_밸런스_기준/05_관찰로그_최소_스키마.md`와 연결되어야 한다.
- 전투 결과에 영향을 주는 관찰값은 StateAuthority 기준 결과를 따른다.
- VFX, 카메라 셰이크, 사운드 같은 presentation 반응은 원인 추적을 보조하지만 network truth가 아니다.

## 금지

- 감상만으로 기본 프리셋을 바꾸는 것.
- 기준문서에 목표 수치나 통과 임계값을 최종값처럼 고정하는 것.
- 사망 원인을 분리하지 않고 체력/피해량부터 조정하는 것.
- Host/Client 결과 불일치를 단순 연출 문제로 처리하는 것.
- 발표/시연용 프리셋을 플레이테스트 없이 기본값으로 승격하는 것.

## 미결정

- 플레이테스트 리포트에서 어떤 항목을 필수로 강제할지.
- 관찰지표를 Unity 에디터 툴로 자동 수집할지.
