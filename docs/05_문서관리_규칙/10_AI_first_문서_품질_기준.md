# AI-first 문서 품질 기준

> 상태: candidate. 이 문서는 팀원 AI(Claude/Codex/Gemini 등)가 `docs/` 기준문서를 소스로 작업할 때의 품질 기준을 정의한다. 인간 onboarding용이 아니라 AI-first 관점의 품질 기준이다.

## 배경

팀원 각자의 AI가 같은 `.md` 파일을 읽고 작업하므로, 문서 품질의 정의가 일반 기술 문서와 다르다. 인간 독자가 한 눈에 읽을 수 있는가보다, LLM이 일관된 해석을 내는가가 우선한다.

## 6대 원칙

### 원칙 1. SOT(Single Source of Truth) 단일화

- 같은 개념이 여러 파일에 중복 정의되면 LLM이 상충 정보를 읽고 할루시네이션을 낸다.
- 한 개념은 반드시 한 파일에 단일 정의를 둔다. 다른 파일은 마크다운 링크로 연결한다.
- 중복 감지 시 [90_백로그/05_SOT_통합_제안](../90_백로그/05_SOT_통합_제안.md) 패턴을 따라 통합.

### 원칙 2. 명시적 크로스 레퍼런스

- "~을 따른다", "~에 정의된 대로", "앞서 언급한" 같은 산문형 참조 금지.
- 반드시 `[표시](상대경로)` 형태의 마크다운 링크 사용.
- LLM은 명시 링크는 추적하지만 산문 언급은 놓치거나 오해한다.

| 반례 | 정례 |
|---|---|
| "카드 선택은 네트워크 핸드셰이크 문서를 따른다" | "카드 선택은 [40/30/01_카드_선택_네트워크_핸드셰이크](../40_카드_무기_설계/30_구현가이드/01_카드_선택_네트워크_핸드셰이크.md) 를 따른다" |
| "앞서 정의된 상태 규칙에 따라" | "[08_문서_상태_인덱스](08_문서_상태_인덱스.md) 에 따라" |

### 원칙 3. 표·리스트 우선

- 산문보다 표·bullet 리스트가 LLM이 정확하게 소화한다.
- 규칙·기준·금지사항은 표로, 절차는 번호 리스트로 작성.
- 긴 문단 하나보다 여러 표가 낫다.

### 원칙 4. 원칙 + 예/반례 쌍

- 원칙만 쓰지 말고 do/don't 쌍을 함께 제시.
- LLM이 경계 사례에서 원칙을 적용할 때 예/반례가 결정적 단서가 된다.

예시 포맷:
```markdown
### 규칙: X

- 정례: 이렇게 한다. 예: `good_example`
- 반례: 이렇게 하지 않는다. 예: `bad_example`
- 근거: 왜 이 규칙이 필요한가
```

### 원칙 5. 결정 공백 금지

- "미결정", "TBD", "추후 결정" 같은 표현을 본문에 두지 않는다.
- 미결정 항목은 모두 [90_백로그/04_미결정_질문_레지스터](../90_백로그/04_미결정_질문_레지스터.md) 에 등록.
- 본문에는 현재 유효 결정만 남긴다.
- 예외: 뼈대 문서(예: `SCHEDULE.md`, `05_파일경로별_DRI.md`)처럼 팀 회의 대기 중인 것은 상단 `> 상태:` 블록에 명시.

### 원칙 6. 상태 블록 + audience 명시

모든 기준문서 상단에 상태 블록을 붙인다.

```markdown
# 문서 제목

> 상태: governance | accepted | accepted_candidate | candidate | reference | backlog | archive 중 하나.
> 이 문서는 [구체적 용도]에 한해 [구체적 범위]에서 기준으로 사용한다.
> 문서 상태와 binding 범위는 `05_문서관리_규칙/08_문서_상태_인덱스.md`를 우선한다.
```

- audience 선언: 이 문서 전체가 AI-first라는 암묵 전제가 있으므로 파일별 audience 표기는 선택. 단 인간 전용 섹션이 있으면 명시(`<!-- audience: human -->` 주석).

## PR 리뷰 체크리스트

문서 추가·수정 PR 리뷰 시 아래 7개를 확인한다.

| no | 확인 항목 |
|---|---|
| 1 | 같은 개념이 다른 파일에 이미 정의되어 있지 않은가(SOT 중복) |
| 2 | 모든 타 문서 참조가 마크다운 링크 형태인가 |
| 3 | 규칙·기준·금지는 표 또는 bullet로 작성되었는가 |
| 4 | 각 규칙에 예/반례가 붙어 있는가 |
| 5 | "미결정" 또는 "TBD"가 본문에 남아 있지 않은가 (뼈대 문서 예외 제외) |
| 6 | 상단 `> 상태:` 블록이 있는가 |
| 7 | 개인 절대경로 · secret · App ID가 포함되지 않았는가 |
