# 문서 계층 규칙

이 문서는 기준문서, 세부설계, 구현가이드, 수치 프리셋이 어디에 위치해야 하는지 정의한다.

목적은 기준문서가 잦은 후보 변경과 수치 조정으로 흔들리지 않게 하고, 구현자가 어느 문서를 현재 규칙으로 봐야 하는지 혼동하지 않게 하는 것이다.

## 기본 원칙

| 계층 | 역할 | 위치 |
|---|---|---|
| 1뎁스 | 도메인 구분 | `10_게임플레이_기준`, `30_전장_레벨디자인`, `40_카드_무기_설계` |
| 2뎁스 파일 | 기준문서 | 도메인 루트의 `30_전장_레벨디자인/01_전장_구간_기준.md` 같은 기준 문서 |
| 2뎁스 디렉토리 | 문서 성격별 하위분류 | `10_세부설계`, `20_검수`, `30_구현가이드` |
| 3뎁스 파일 | 세부설계, 검수 기준, 구현가이드 | 각 하위 디렉토리 내부 문서 |

도메인 루트에는 원칙, 금지선, 판단 기준만 둔다. 후보 목록, 카탈로그, 수치, 구현 절차는 하위 디렉토리로 내린다.

| 카드 후보 전체 목록 | `40_카드_무기_설계/10_세부설계` |

| Unity 구현 핸드셰이크 | 해당 도메인의 `30_구현가이드` |
| 화면/카메라 검수 체크 | 해당 도메인의 `20_검수` |

## 예외 규칙

기준문서에 수치가 필요한 경우에는 확정값이 아니라 “예시” 또는 “프리셋 후보”라고 명시한다.

기준문서에 후보 목록이 필요한 경우에는 목록 전체를 넣지 않고, 후보가 지켜야 할 원칙과 금지선만 적는다. 실제 후보 목록은 `10_세부설계`로 분리한다.

구현가이드는 기술 문서지만 코드 소유권을 대체하지 않는다. 구현가이드는 “어떤 계약을 지켜야 하는가”를 설명하고, 실제 파일 소유권과 MR 규칙은 `50_기술_구조_기준`과 `80_Jira_Git_운영_원칙`을 따른다.

## 추가 문서 생성 기준

새 문서를 만들 때는 아래 질문을 먼저 확인한다.

| 질문 | 판단 |
|---|---|
| 원칙과 금지선을 설명하는가? | 도메인 루트 기준문서 |
| 후보, 카탈로그, 전투 양상 예시를 설명하는가? | `10_세부설계` |
| 화면에서 확인해야 하는가? | `20_검수` |
| 구현 시스템 간 계약을 설명하는가? | `30_구현가이드` |
| 숫자나 조정값인가? | `85_밸런스_프리셋` |

위 질문으로도 위치가 애매하면 도메인 루트에 바로 만들지 말고 `90_백로그`에 문서 생성 제안으로 먼저 남긴다.
