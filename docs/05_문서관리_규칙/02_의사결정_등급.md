# 의사결정 등급

이 문서는 Colloseum 기준문서와 구현 작업에서 어떤 결정을 어느 수준으로 기록하고 검토할지 정의한다.

핵심 목적은 모든 판단을 회의 안건으로 만들지 않되, 되돌리기 어려운 결정이 개인 판단이나 개별 작업으로 조용히 바뀌는 것을 막는 것이다.

## 등급

| 등급 | 의미 | 예시 |
|---|---|---|
| P0 | 되돌리기 매우 어려움 | 엔진, 넷코드, 물리 구조, 승패 구조 |
| P1 | 변경 비용이 큼 | 주요 피처 범위, 카드 체계, 아트 방향 |
| P2 | 낮은 비용으로 조정 가능 | UI 배치, 프리셋 수치, 이펙트 강도 |

## 등급별 처리

| 등급 | 처리 규칙 |
|---|---|
| P0 | 기준문서 또는 decision 기록 필수. 임의 구현 금지 |
| P1 | DRI 또는 해당 영역 책임자의 검토 기록 필요 |
| P2 | 작업 기록, 커밋, 프리셋 변경 로그 중 하나로 충분 |

## 기록 위치

| 등급 | 기록 위치 |
|---|---|
| P0 | 기준문서 본문 또는 별도 decision 기록 |
| P1 | 관련 기준문서의 변경 기록, 기능 스펙, 스프린트 리뷰 중 하나 |
| P2 | BalanceProfile, 테스트 리포트, PR/작업 기록 중 하나 |

P0/P1은 이유와 대안을 함께 남긴다. "그냥 그렇게 하기로 함"은 결정 기록으로 취급하지 않는다.

## 작업에서의 적용

작업자는 작업 중 결정 등급을 아래처럼 판단한다.

- P0 또는 P1로 보이면 구현 전에 기준문서 충돌 여부를 확인한다.
- `accepted` 문서를 바꾸어야 하면 `BLOCKED`로 보고한다.
- P2 수치 실험은 기준문서가 아니라 `85_밸런스_프리셋/` 또는 Unity 프리셋 구현체에서 다룬다.
- 등급이 애매하면 P1로 올려서 기록하고 진행 여부를 판단한다.

## 기준문서 반영 원칙

기준문서에는 P0/P1 결정의 이유와 금지선을 남긴다.

P2 결정은 기준문서에 고정하지 않는다. 예를 들어 체력, 피해량, 쿨타임, 탄속, 장탄수, 리스폰 시간 같은 값은 프리셋이나 플레이테스트 기록에서 관리한다.

## 완료 판정

의사결정 기록은 아래 조건을 만족하면 완료로 본다.

- 결정 내용이 한 문장으로 요약되어 있다.
- 왜 이 결정을 했는지 이유가 적혀 있다.
- 폐기한 대안 또는 보류한 대안이 적혀 있다.
- 영향을 받는 기준문서, 기능 스펙, 구현 영역 중 하나 이상과 연결되어 있다.
- P2 수치는 기준문서가 아니라 프리셋 또는 테스트 기록으로 분리되어 있다.
