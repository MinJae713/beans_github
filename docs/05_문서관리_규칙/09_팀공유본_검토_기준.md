# 팀공유본 검토 기준

이 문서는 팀 공유 기준문서를 다른 담당자나 AI 세션이 검토할 때 사용할 기준이다.

검토 목적은 문장을 예쁘게 다듬는 것이 아니라, 이 문서만 읽고 같은 게임을 만들 수 있는지 확인하는 것이다.

## 검토 결론 형식

검토자는 아래 중 하나로 결론을 낸다.

| verdict | 의미 |
|---|---|
| PASS | 팀 공유 가능 |
| PASS_WITH_CONDITIONS | 공유 가능하지만 함께 고지해야 할 조건이 있음 |
| NEEDS_FIX | 공유 전 수정 필요 |
| BLOCKED | 핵심 규칙 충돌 또는 보안/비밀값 노출로 공유 중단 |

## 필수 검토 항목

| 항목 | 질문 |
|---|---|
| 맥락 복구 | 처음 읽는 팀원도 게임의 핵심 루프, 승리조건, 카드 지급 조건을 이해하는가 |
| 확정/보류 구분 | 구현해도 되는 것, 임시 가정, 보류 항목이 구분되는가 |
| 기준/세부설계 분리 | 원칙 문서와 후보/카탈로그/프리셋 문서가 섞이지 않았는가 |
| 구현 금지선 | 3D 물리, secret 노출, Host 전용 규범화 같은 금지선이 명확한가 |
| 네트워크 truth | StateAuthority가 확정해야 하는 판단이 UI 로컬 처리로 설명되지 않는가 |
| 수치 관리 | 피해량, 탄속, 장전 시간 같은 값이 확정 기준처럼 박혀 있지 않은가 |
| 팀 운영 | Jira/Git/MR/소유권 기준이 실제 팀 협업에 사용할 수 있는 수준인가 |
| AI 협업 | 특정 AI 도구 강제가 아니라 작업 위임 공통 원칙으로 읽히는가 |
| 보안/로컬 정보 | 개인 경로, App ID, secret, 토큰, 내부 산출물 경로가 없는가 |

## 도메인별 검토 질문

| 도메인 | 검토 질문 |
|---|---|
| 프로젝트 비전 | ROUNDS/Nidhogg 참고와 Colosseum 차별점이 구분되는가 |
| 게임플레이 | 7구간(S2~S6 전투, S1·S7 최종), 전투 구간, 최종 구간, 이동 주도권이 일관되는가 |
| 전투/밸런스 | TTK 철학과 카드 선택 빈도 문제가 연결되어 설명되는가 |
| 전장/레벨디자인 | 구간 돌파, 카메라, 경계 패배, 최종 구간이 모순 없이 설명되는가 |
| 카드/무기 | 카드가 총기 교체가 아니라 총알 성질과 발사 리듬 중심으로 설명되는가 |
| 피드백/UI | 딱밤, 혹, 이모트, 승리감 연출이 카드 효과와 분리되어 있는가 |
| 기술 구조 | Unity 2D 물리, Photon Fusion, Host Mode 1차 범위가 명확한가 |
| 검증 | 플레이어블 slice, 스모크테스트, 부하 리허설의 목적이 구분되는가 |
| 운영 | Jira/Git 규칙이 문서 변경과 코드 변경을 모두 커버하는가 |

## BLOCKED 기준

아래 항목이 있으면 공유를 멈춘다.

| 조건 | 이유 |
|---|---|
| 개인 PC 절대경로가 남아 있음 | 팀원이 그대로 사용할 수 없고 외부 노출 위험이 있음 |
| Photon App ID, secret, 토큰이 포함됨 | 보안 문제 |
| 2D 물리 기준과 3D 물리 기준이 동시에 확정처럼 적힘 | 구현 방향 충돌 |
| 카드 지급 조건이 문서마다 다르게 설명됨 | 핵심 게임루프 충돌 |
| `ChoicePending` 중 전투 입력 잠금이 빠져 있음 | 카드 선택과 전투 입력 충돌 |
| 구체 수치가 기준문서 확정값처럼 기록됨 | 플레이테스트 전 수치 고착 위험 |

> BLOCKED verdict의 태그 분류(`BLOCKED_TECH`/`BLOCKED_DECISION`/`BLOCKED_EXTERNAL`)는 [05/01#blocked-태그-분류-정본](01_문서_상태와_변경_규칙.md#blocked-태그-분류-정본) 참조. 본 문서는 공유본 배포 중단 판정의 맥락만 다룬다.

## 검토 결과 작성 양식

```text
verdict:
검토 범위:
핵심 판단:
수정 필요:
백로그 권장:
공유 시 함께 고지할 조건:
BLOCKED 여부:
```

## 공유 시 고지할 기본 조건

- 이 문서는 현재 팀 기준을 맞추기 위한 상세 명세서다.
- `확정`, `임시 가정`, `보류`를 구분해서 읽어야 한다.
- 수치값은 기준문서가 아니라 프리셋과 플레이테스트 로그에서 조정한다.
- 문서 변경은 논의 후 변경 로그를 남긴다.
- 구현 중 기준문서와 충돌하면 담당자 확인 없이 임의로 규칙을 바꾸지 않는다.
