# 5인 작업 구조와 역할 소유권

> 2026-04-21 T2(D49)에서 DRI 이름·책임 축 확정. 2026-04-30 A303-256에서 M2 전투 플레이어블 협업 구조를 반영해 역할 경계를 보강했다. 파일 경로별 DRI 매트릭스(RACI·RSA)는 [50_기술_구조_기준/05_파일경로별_DRI.md](../50_기술_구조_기준/05_파일경로별_DRI.md) (accepted)가 정본이다.

## A303-256 승인 근거

- 승인 출처: 2026-04-30 M2 전투 플레이어블 역할 분담 회의.
- 승인 범위: 서버 판정 로직, 클라이언트 표현, 공통 계약, 맵/카메라, 인프라/빌드, QA R/A 경계.
- 영향 리뷰어: docs DRI 박병준, 계약/QA DRI 김범승, 전투/네트워크 DRI 최진우, 표현 DRI 우수연, 인프라/빌드·QA(A) DRI 유민재.
- MR 검토 조건: 본 역할 변경은 A303-256 MR에서 박병준과 김범승 교차 검토를 거치며, 런타임 소유권이 바뀌는 항목은 해당 영역 DRI를 리뷰어로 추가한다.

이 문서는 5인 팀이 같은 Unity 프로젝트와 기준문서를 병렬로 수정할 때 작업 충돌을 줄이기 위한 역할과 소유권 기준이다.

현재 문서는 팀 공유 기준문서 안의 작업 라우팅 문서다. 최종 인사 배치표가 아니라, Jira 이슈, 작업 브리핑, MR 리뷰에서 “누가 DRI이고 누구에게 확인해야 하는가”를 판단하기 위한 기준으로 사용한다.

## 작성 배경

- Unity 코드와 기준문서가 같은 공식 레포에서 병렬로 변경된다.
- 기존 임시 R&R은 실제 구현된 네트워크/전투 코드와 일부 맞지 않는다.
- 네트워크, 카드, 전투, HP/리스폰, UI/VFX가 서로 강하게 엮여 있어 작업 소유권이 없으면 같은 파일과 시스템을 동시에 건드릴 위험이 크다.
- MVP 카드 범위는 우선 총알 성질과 발사 리듬 중심으로 좁히고, 총기 교체/이동기/리스폰 계열 카드는 확장 백로그로 둔다.

## 적용 범위

| 항목 | 적용 방식 |
|---|---|
| Jira 이슈 | 한 이슈에는 DRI 1명을 둔다 |
| 구현 담당자 전달 | 작업 소유자, 협업자, 금지 영역을 함께 전달한다 |
| MR 리뷰 | 게이트키퍼가 필요한 변경을 명시한다 |
| 스프린트 운영 | 작업 브리핑, Jira 라우팅, MR 검토 요청의 기본값으로 사용한다 |
| 역할 변경 | 역할 변경이 생기면 50/05 DRI 정본과 의사결정 로그를 함께 갱신한다 |

## 기본 원칙

- 이 문서는 사람을 고정 배치하는 문서가 아니라 작업 충돌을 줄이기 위한 라우팅 문서다.
- 이미 작성된 코드가 있으면 기존 구현 소유자와 실제 코드 구조를 먼저 확인한다.
- 같은 Jira 제목을 담당자만 바꿔 중복 생성하지 않는다.
- 공동 작업은 허용하지만, 최종 판단과 MR 설명 책임을 지는 DRI는 1명으로 둔다.
- 파일 소유권이 아직 확정되지 않은 공용 씬, 프리팹, NetworkProjectConfig, Player 관련 프리팹은 해당 DRI 확인 전 수정하지 않는다.
- 구현 수치, 카드 세부값, 무기 세부값은 이 문서에 적지 않는다.
- `인벤토리`라는 표현은 현재 게임 구조와 맞지 않으므로 쓰지 않는다.
- 전투/네트워크 판정 로직과 클라이언트 표현/연출은 같은 GameObject에 붙을 수 있지만, 코드 책임은 분리한다. 판정 로직은 사건과 상태를 만들고, 표현 코드는 그 사건과 상태를 소비한다.
- 공통 계약은 편의성 유틸 모음이 아니라 로직과 표현이 공유해야 하는 타입·이벤트 payload·읽기 전용 정보의 경계다.

## 네트워크 책임 분리

네트워크는 한 명이 전부 맡기보다 계층을 나눠야 한다.

| 영역 | R | A | C/S | 승인 규칙 |
|---|---|---|---|---|
| Fusion Runner, 세션 | 최진우 | 최진우 | 유민재 | 세션 생성, Host/Client 시작, Runner 생명주기 (T2 D49 단일화) |
| NetworkProjectConfig | 최진우(변경 요청) | 유민재(게이트키퍼) | 박병준 | 변경 시 게이트키퍼 리뷰 필요 |
| 서버 모드 전환 | 유민재(인프라) · 최진우(런타임) | 유민재 | 박병준 | 2차 릴리스의 Server Mode 전환 + 배포 |
| 전투 입력/보간 | 최진우 | 최진우 | 김범승, 우수연 | 이동, 조준, 발사, 투사체, 재장전 동기화 |
| 카드 RPC/RNG | 최진우 | 최진우 | 김범승(정책 검증), 우수연(표현 연동) | 런타임 RNG·카드 선택 RPC 변경은 최진우 승인. 카드 풀·드래프트 정책 변경은 김범승 리뷰 필수. 두 범위가 함께 바뀌면 최진우와 김범승 모두 리뷰한다 |
| 드래프트 검증 | 김범승 | 김범승 | 최진우 | 카드 선택 흐름, 사망/리스폰과의 연결 검증 |
| 네트워크 최적화 (W4) | 최진우 + 김범승 공동 | 최진우 | 유민재 | Jira 스토리 2개 split, T13 페어 세션 후 경계 확정 |

2026-04-21 T2(D49) 결정으로 **게임 네트워크(Runner·세션·전투 동기화)는 최진우가 단일 담당**한다. 유민재는 인프라·빌드·QA와 배포 쪽을 맡으며, NetworkProjectConfig 게이트키퍼 역할만 유지한다.

| 유민재 | NetworkProjectConfig(변경 게이트키퍼), 배포 설정, 빌드 파이프라인, 도메인, Spring Boot/Redis 실행 환경, `infra/localbuild` |
| 최진우 | Fusion Runner, 세션, NetworkInputData, 전투 네트워크 |
| 우수연 | art/*, 캐릭터/공통 비주얼/UI 룩, 발표용 비주얼 산출물 |
| 김범승 | Contracts, 카드/전투 정책, GameplayProfile 수치 의미, QA 판정 기준 |
| 박병준 | 기준문서 운영 구조, map 디자인, 맵/카메라 기준, CODEOWNERS/DRI 운영 기준 |

게이트키퍼는 모든 코드를 직접 작성한다는 뜻이 아니다. 해당 영역의 구조가 깨지지 않았는지 확인하는 최종 리뷰 책임자다.

## MVP 카드 범위

MVP 단계에서는 총기 자체를 계속 바꾸기보다 총알 성질과 발사 리듬을 우선 설계한다.

| 범위 | 판단 |
|---|---|
| 총알 크기/속도 | MVP 후보 |
| 탄퍼짐/추가 탄환 | MVP 후보 |
| 반사/관통/넉백 | MVP 후보 |
| 재장전/장탄/연사 | MVP 후보 |
| 총기 외형/종류 교체 | 확장 백로그 |
| 점프 높이/이동속도 | 확장 백로그 |
| 대시/2단점프 | 확장 백로그 |
| 리스폰 시간 감소 | 확장 백로그 |

이동기와 리스폰 계열은 전장 압박, TTK, 구간 돌파 밸런스를 크게 바꾸므로 첫 MVP 카드 범위에서 제외한다.

## 마일스톤별 의존성

| Gate | 의존성 |
|---|---|
| Gate 1 | 유민재 빌드 파이프라인 -> 박병준 구조/맵·카메라 기준 -> 최진우/김범승/우수연 기능 통합 |
| Gate 2 | 김범승 카드/전투 정책·계약 -> 최진우 런타임 적용 -> 우수연 UI/VFX -> 유민재 실행 환경 |
| Gate 3 | 최진우 Fusion Host Mode 세션 안정화 + 전투 동기화 -> 김범승 계약/카드 정책 검증 -> 우수연 표현 연동 -> 유민재 리허설 환경 |
| Gate 4 | 최종 빌드(유민재), 성능(최진우+김범승), UI/연출(우수연), 맵/카메라(박병준), 문서 정리(박병준) |

Server Mode, WebGL, 리더보드는 1차 시연 이후 2차 릴리스 후보로 분리한다.

## Jira 작성 규칙 보정

- 네트워크 최적화와 성능 최적화는 같은 제목으로 중복 생성하지 않는다.
- 대신 하위 영역으로 쪼갠다.
- 예: `NETWORK-ProjectileSync`, `NETWORK-Interpolation`, `PERF-Pooling`, `PERF-GC`.
- 공동 책임이 필요한 이슈는 DRI 1명과 collaborator를 분리해서 적는다.
- MR 설명에는 어떤 기준문서와 어떤 게이트키퍼가 관련되는지 적는다.
