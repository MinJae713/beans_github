# 라운드 상태머신

> 상태: accepted. 이 문서는 사망, 구간 돌파, ChoicePending, 리스폰, 최종 승리 전이의 현재 구현 기준이다. 문서 상태와 binding 범위는 `05_문서관리_규칙/08_문서_상태_인덱스.md`를 우선한다.

이 문서는 사망, 구간 돌파, 카드 선택, 리스폰이 어떤 순서로 처리되는지 정의한다.

구체적인 제한 시간, 리스폰 위치 비율, 카드 선택 시간, 체력값은 이 문서에 고정하지 않는다. 해당 값은 `BalanceProfile`, 레벨 프리셋, 카드 프리셋에서 관리한다.

## 현재 적용 범위

이 문서는 내부 기준문서 중 현재 구현 판단에 사용할 수 있는 `accepted` 상태다.

| 구분 | 기준 |
|---|---|
| 고정하는 것 | 상태 이름, 전이 순서, 선택권 발생 조건, 최종 구간 처리 |
| 고정하지 않는 것 | 시간, 거리, 체력, 피해량, 보호 시간, 카드 선택 제한 시간 |
| 구현자가 따라야 할 것 | 사망/돌파/선택/리스폰을 임의 순서로 섞지 않음 |
| 변경 절차 | 게임루프, 카드 보상, 네트워크 truth에 영향이 있으면 의사결정 로그와 질문 레지스터를 함께 갱신 |

## 상태 목록

| 상태 | 의미 |
|---|---|
| MatchSetup | 매치 시작 전 플레이어, 전장, 구간 정보를 준비 |
| SegmentSetup | 현재 구간의 스폰, 카메라, 전투 조건을 초기화 |
| RoundIntro | 입력 가능 전 짧은 준비 상태 |
| CombatActive | 이동, 공격, 피격, 구조물 상호작용이 가능한 전투 상태 |
| DeathResolving | 체력 소진 또는 위험 판정에 따른 사망 결과 정리 |
| BreakthroughResolving | 구간 돌파 결과와 전선 이동을 정리 |
| ChoicePending | 구간 돌파 패배자/방어자가 다음 전투 선택을 진행 |
| RespawnResolving | 양 플레이어 위치, 자원, 카메라를 재정렬 |
| VictoryRun | 최종 구간에서 승리 예정 캐릭터만 끝 지점까지 이동 |
| MatchEnding | 최종 구간 끝 지점 도달 후 최종 연출과 매치 종료 처리 |

## 기본 전이

```text
MatchSetup
-> SegmentSetup
-> RoundIntro
-> CombatActive
-> 일반 사망이면 DeathResolving -> RespawnResolving -> CombatActive
-> 전투 구간 돌파이면 BreakthroughResolving -> ChoicePending -> RespawnResolving -> SegmentSetup
-> 최종 구간 진입이면 BreakthroughResolving -> VictoryRun
-> 최종 구간 끝 지점 도달이면 MatchEnding
```

전투 구간 돌파와 최종 구간 진입은 서로 다른 결과다. 전투 구간 돌파는 방어자 카드 선택과 다음 구간 전투로 이어지고, 최종 구간 진입은 카드 선택 없이 `VictoryRun`으로 이어진다.

최종 구간 진입은 `ChoicePending` 또는 `RespawnResolving`을 열지 않는다. 패배자는 더 이상 리스폰하지 않고, 승리 예정 캐릭터만 `VictoryRun`으로 전이한다. 최종 구간 끝 지점에 도달하면 조작 불가능한 최종 연출과 함께 `MatchEnding`으로 전이한다.

## 상태별 책임

| 상태 | authoritative 판단 | presentation 처리 |
|---|---|---|
| MatchSetup | 매치 참가자와 전장 선택 | 로딩, 대기 UI |
| SegmentSetup | 구간 인덱스와 스폰 기준 | 카메라 위치, 인트로 연출 |
| RoundIntro | 입력 잠금/해제 조건 | 카운트다운, 준비 피드백 |
| CombatActive | 입력, 이동, 발사, 피격 | VFX, SFX, 화면 흔들림 |
| DeathResolving | 사망자와 승자 판정 | 사망 연출 |
| BreakthroughResolving | 돌파자와 방어자 판정 | 전선 이동 연출 |
| ChoicePending | 구간 돌파 패배자의 선택권과 선택 결과 | 카드/선택 UI |
| RespawnResolving | 위치, 자원, 상태 초기화 | 리스폰 이펙트, 카메라 재정렬 |
| VictoryRun | 최종 구간 진행자와 승리 확정 조건 | 승리 예정 연출, 카메라 추적 |
| MatchEnding | 최종 승자 | 결과 UI, 리매치 UI |

## 결과 판정 우선순위

한 tick 안에서 여러 이벤트가 동시에 발생할 수 있으므로 결과 판정 순서를 고정한다.

| no | 결과 후보 | 처리 기준 |
|---|---|---|
| 1 | 최종 구간 끝 지점 도달 | 매치 종료로 처리 |
| 2 | 최종 구간 진입 | VictoryRun으로 처리 |
| 3 | 구간 돌파 | 구간 결과로 처리 |
| 4 | 사망 | 라운드 결과로 처리 |
| 5 | 카메라/경계 이탈 패배 | 구간 규칙에 따라 패배 후보로 판정한 뒤 `DeathResolving`으로 정규화 |
| 6 | 일반 피격/넉백/경직 | 전투 상태 유지 |

최종 구간 진입, 최종 구간 끝 지점 도달, 구간 돌파는 단순 위치 이동이 아니라 승패 결과다. 따라서 일반 피격보다 먼저 처리한다.

## 사망 처리

- 체력 소진, 위험 지형, 구간 규칙에 따른 패배는 사망 결과로 정리한다.
- 카메라/경계 이탈 패배는 별도 카드 지급 결과가 아니라 `DeathResolving`으로 정규화한다.
- MVP 기준 일반 사망자는 즉시 카드 선택권을 얻지 않는다.
- 일반 사망을 만든 플레이어는 이동 주도권을 얻는다.
- 이동 주도권 보유자는 뒤로 이동할 수 없으며, 진행 방향은 확정된 주도권 상태를 읽어 상단 방향 UI로 표시한다.
- 사망자는 리스폰 기준 자원으로 초기화된다.
- 승자는 가능한 한 현재 전투 자원을 유지한다.
- 사망 연출은 authoritative 결과가 확정된 뒤 presentation에서 재생한다.
- 상대가 만든 일반 전투 사망에 카드 지급을 줄지는 별도 미결정으로 관리한다.

## 구간 돌파 처리

- 공격자가 현재 구간의 상대 방향 끝을 넘으면 구간 돌파로 처리한다.
- 방어자는 사망과 동일한 패배 결과로 취급한다.
- 방어자가 다음 전투 선택권을 얻는다.
- 돌파자는 전선 이득을 유지하되, 즉시 다음 구간도 자동 돌파되지 않도록 리스폰/카메라를 재정렬한다.
- 상대 최종 구간에 진입하는 돌파라면 즉시 매치 승리로 확정하지 않고 `VictoryRun`으로 전이한다.
- 매치 최종 승리는 `VictoryRun`에서 승리 예정 캐릭터가 최종 지점에 도달한 뒤 확정한다.
- 전투 구간 돌파 시 카드 보상은 방어자에게 주는 방향을 기본으로 하되, 카드 보유 제한과 등급 제한을 함께 적용한다.

## 최종 구간 처리

- 최종 구간은 상대 최종 진영 끝까지 달려가는 과정을 연출하고 매치 승리를 확정하는 구간이다.
- 최종 구간에 진입하는 순간 패배자는 리스폰하지 않는다.
- 최종 구간에는 승리 예정 캐릭터만 등장한다.
- 승리 예정 캐릭터가 최종 구간 끝 지점에 도달하면 조작 불가능한 최종 연출이 시작된다.
- 매치 최종 승리는 최종 연출 시작 시점에 확정한다.
- 최종 구간은 전투 재개 구간이 아니므로 카드 선택과 리스폰 루프를 열지 않는다.

## 선택 대기 처리

- 선택권은 MVP 기준 구간 돌파 패배자에게 부여한다.
- 모든 일반 사망에 선택권을 부여하지 않는다.
- 선택 UI는 전투 상태를 멈춘 별도 상태로 취급한다.
- 선택 결과는 다음 `SegmentSetup` 또는 `RespawnResolving` 전에 authoritative 상태에 반영한다.
- 선택 제한 시간의 구체값은 프리셋 또는 UI 정책에서 관리한다.
- 시간 만료 시에는 제시된 후보 중 랜덤 자동 선택으로 확정한다.

## 리스폰 처리

- 리스폰은 구간 절대 중앙이 아니라 공격 방향과 카메라 기준으로 정렬한다.
- 리스폰 직후 입력 전에 즉시 피격되거나 낙사하면 안 된다.
- 돌파자는 공격 방향을 유지하고, 방어자는 반격 가능한 거리와 공간을 가져야 한다.
- 정확한 리스폰 위치, 보호 시간, 자원 초기화 값은 프리셋에서 관리한다.

## 네트워크 권위 원칙

- 상태 전이는 `StateAuthority`가 확정한다.
- 플레이어 입력은 `InputAuthority`가 제출하지만, 결과 판정은 authoritative tick에서 확정한다.
- 클라이언트는 predicted presentation을 보여줄 수 있으나, 사망/돌파/카드 선택/리스폰 결과는 authoritative 상태를 따른다.
- VFX, 카메라, UI는 상태 결과를 읽어 재생하는 presentation이며 상태 전이를 직접 소유하지 않는다.

## 상태머신과 코드 소유 매핑

아래 표는 최종 클래스명을 고정하지 않는다. 구현자는 현재 코드의 실제 컴포넌트를 이 책임 단위에 매핑한 뒤 작업해야 한다.

| 책임 단위 | 소유해야 하는 상태/행동 | 소유하면 안 되는 것 |
|---|---|---|
| 매치/라운드 흐름 관리자 | MatchSetup, SegmentSetup, RoundIntro, CombatActive, MatchEnding 전이 | 카드 효과 세부 수치, UI 연출 |
| 전투 결과 판정자 | 사망, 구간 돌파, 동시 결과 우선순위 확정 | 카메라 연출, 사운드 |
| 카드 선택 관리자 | 선택권 보유자, 제시 카드, 선택 검증, 선택 확정 | UI 클릭 자체, 로컬 임시 선택 |
| 리스폰 관리자 | 스폰 기준, 자원 초기화 범위, 입력 재개 시점 | 카드 후보 생성, 무기 수치 |
| 플레이어 입력 브리지 | CombatActive에서 제출할 이동/조준/공격 입력 | ChoicePending의 UI 선택 확정 |
| 플레이어 전투/체력 컴포넌트 | 피격, 체력, 사망 후보 발생 | 라운드 최종 전이 결정 |
| UI/카메라 presentation | 상태 결과 표시, 선택 화면, 카메라 이동 | 사망/돌파/선택 결과의 authoritative 확정 |

프로토타입에서 한 컴포넌트가 여러 책임을 임시로 갖고 있더라도, 기준문서상 소유권은 위 책임 단위로 분리한다. 특히 `ChoicePending` 중 전투 입력 잠금과 카드 선택 확정은 같은 UI 클릭으로 끝내지 않고 상태머신과 네트워크 검증을 거친다.

## 미결정

- 카메라/경계 이탈 패배는 MVP 기준 일반 사망으로 정규화하되, 특수 보정이 필요한지는 플레이테스트 후 재검토한다.
- 상대가 만든 일반 전투 사망을 제한적 카드 지급 대상으로 볼지는 MVP 이후 재검토한다.
- 동시 구간 돌파처럼 드문 경계 상황의 세부 타이브레이크는 StateAuthority 결과 우선순위를 따르되, 구현 전 브리핑에서 재확인한다.
