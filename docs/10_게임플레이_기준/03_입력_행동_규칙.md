# 입력 행동 규칙

이 문서는 이동, 점프, 공격, 기믹 행동, 감정 표현이 어떤 책임 경계로 처리되는지 정의한다.

실제 키 매핑, 입력 지연 허용값, 쿨타임 수치, 점프 높이 수치는 이 문서에 고정하지 않는다. 해당 값은 Input Actions, `BalanceProfile`, 캐릭터/무기 프리셋에서 관리한다.

## 입력 범주

| 범주 | 예시 |
|---|---|
| 이동 입력 | 좌우 이동, 점프, 하강, 도입된 경우 대시 |
| 조준 입력 | 방향 조준, 마우스/스틱 기반 방향 |
| 전투 입력 | 기본 공격, 재장전 |
| 기믹 입력 | 딱밤, 확장 후보인 슬라이딩 태클 같은 승리감/도발/짧은 방해 행동 |
| 선택 입력 | 카드/무기 선택, 확인, 취소 |
| 표현 입력 | 감정 표현, 도발, 비전투 피드백 |
| 시스템 입력 | 일시정지, 설정, 리매치, 나가기 |

## 권위 경계

| 항목 | 입력 주체 | 결과 주체 |
|---|---|---|
| 이동/점프/도입된 경우 대시 | InputAuthority | StateAuthority |
| 조준 방향 | InputAuthority 제출 | StateAuthority 확정 |
| 기본 공격 | InputAuthority 제출 | StateAuthority 검증/생성 |
| 기믹 행동 | InputAuthority 제출 | 결과 영향이 있으면 StateAuthority 검증 |
| 카드 선택 | InputAuthority 제출 | StateAuthority 선택 결과 확정 |
| 감정 표현 | InputAuthority 제출 | 결과 영향 없으면 presentation |

입력은 플레이어가 제출하지만, 게임 결과는 authoritative tick에서 확정한다. 감정 표현처럼 게임 결과를 바꾸지 않는 입력은 로컬 연출 또는 가벼운 네트워크 이벤트로 처리할 수 있다.

## Fusion 입력 원칙

- 플레이어 조작은 `INetworkInput` 구조체로 수집한다.
- 입력 수집은 `GetInput()` 경계를 따른다.
- 이동, 점프, 공격, 재장전, 기믹 행동 결과는 `FixedUpdateNetwork()`에서 처리한다.
- 입력 상태와 presentation 상태를 같은 변수에 섞지 않는다.
- 카드 선택처럼 전투 상태를 멈추는 입력은 라운드 상태머신의 `ChoicePending`과 연결한다.
- 카드 선택 결과는 UI 로컬 입력이 직접 확정하지 않고 `40_카드_무기_설계/30_구현가이드/01_카드_선택_네트워크_핸드셰이크.md`의 요청/검증/확정 흐름을 따른다.

## 입력 충돌 방지

| 충돌 | 처리 기준 |
|---|---|
| 조준과 카드 선택 | ChoicePending에서는 반투명 카드 오버레이 입력만 받는다 |
| 공격과 재장전 | StateAuthority가 무기 상태에 따라 하나만 확정한다 |
| 대시와 점프 | 프리셋이 허용한 조합만 결과로 반영한다 |
| 사망 중 입력 | presentation은 받을 수 있어도 결과 상태는 무시한다 |
| 라운드 전환 중 입력 | RoundIntro/RespawnResolving에서는 잠금 규칙을 따른다 |

카드 선택 UI의 상세 플로우·네트워크 핸드셰이크는 [40/30/01 카드 선택 네트워크 핸드셰이크](../40_카드_무기_설계/30_구현가이드/01_카드_선택_네트워크_핸드셰이크.md) 정본 참조. 본 문서는 **입력 충돌 방지 관점**(카드 선택 중 이동·발사 입력 차단 규칙)만 다룬다.

## 행동별 설계 기준

### 이동

- 이동은 위치 기반 킬각과 구간 돌파를 만들기 위한 핵심 조작이다.
- 이동 수치는 프리셋으로 조정하되, 기본 조작감이 카드 한 장으로 무너지면 안 된다.
- 네트워크 보정이 어렵게 만드는 순간이동형 이동은 MVP에서 보수적으로 다룬다.

### 점프

- 점프는 고저차 압박과 회피 수단이다.
- 점프 높이, 공중 제어, 착지 후 회복은 프리셋에서 관리한다.
- 발판을 밟을 수 없는 기본 점프는 레벨디자인 또는 프리셋 문제로 본다.

### 대시와 2단점프

- 대시와 2단점프는 액션성 확장 후보지만, MVP 기본 전투를 흔드는 기능이다.
- 도입 시 입력/쿨타임/무적/충돌 판정이 함께 정의되어야 한다.
- 네트워크 truth와 prediction 비용을 검토한 뒤 추가한다.
- 회의 기준으로 대시는 ROUNDS와의 차별성을 만들 수 있는 후보지만, 지속 성장 카드가 아니라 짧은 일시적 액션 요소로 우선 검토한다.
- 이동기를 카드 누적 성장으로 만들면 위치 싸움과 구간 설계가 무너질 수 있으므로, 기본 이동기/일시 액션/카드 효과 중 어디에 둘지 먼저 결정한다.

### 기본 공격

- 기본 공격은 전투의 기준점이다.
- 기본 공격만으로 모든 상황을 해결하면 카드와 구조물이 의미 없어지므로, 위치와 장전 판단이 남아야 한다.
- 발사 가능 조건, 탄약, 재장전 상태는 StateAuthority가 확정한다.

### 기믹 행동

- 이 프로젝트에서 “특수공격”이라는 표현은 MVP 기준으로 “기믹 행동”으로 정리한다.
- MVP 기믹 행동은 딱밤만 포함한다.
- 딱밤은 피해를 주는 킬 도구가 아니라 상대를 놀리고 승리감을 만드는 단순 기믹이다.
- 딱밤이 혹, 짧은 피드백, 시각적 누적 표현을 만들 수는 있지만 TTK를 직접 줄이면 안 된다.
- 슬라이딩 태클은 확장 후보로 보류한다.
- 슬라이딩 태클을 도입할 경우 피해 없는 짧은 경직/위치 방해 정도로 설계하고, 무한 경직이나 확정 돌파를 만들면 안 된다.
- 기믹 행동은 카드 해금이 아니라 기본 행동으로 시작하되, 결과 영향이 있는 경우 StateAuthority가 검증한다.

### 감정 표현

- 감정 표현은 승리감과 도발의 장치다.
- 게임 결과를 바꾸는 충돌, 경직, 피해를 포함하면 감정 표현이 아니라 전투 행동으로 분류한다.
- MVP에서는 전투 판정과 분리된 presentation 기능으로 시작하는 것이 안전하다.

## 작업 브리핑에 포함할 항목

입력 관련 작업 브리핑에는 아래 항목을 명시한다.

| 항목 | 작성 기준 |
|---|---|
| 입력 범주 | 이동/조준/전투/기믹/선택/표현/시스템 중 어디인지 |
| authority | InputAuthority 제출, StateAuthority 확정 여부 |
| 상태 조건 | CombatActive, ChoicePending 등 허용 상태 |
| 충돌 입력 | 동시에 들어올 수 있는 입력과 우선순위 |
| 수치 위치 | Input Actions, BalanceProfile, 카드/무기 프리셋 |
| 테스트 관찰점 | 로컬 2인, Fusion Host Mode, UI 입력 모드 전환 |

## 금지

- 실제 키 값을 기준문서에 최종값처럼 고정하는 것.
- 조준 입력과 UI 선택 입력을 같은 모드에서 충돌하게 두는 것.
- 클라이언트 로컬에서만 확정되는 공격, 기믹 결과, 카드 선택.
- 대시/2단점프를 네트워크 비용 검토 없이 기본 행동으로 넣는 것.
- 감정 표현에 숨겨진 전투 판정을 넣는 것.

## 미결정

- MVP에서 대시를 기본 조작으로 포함할지, 카드/기믹 행동으로 둘지.
- 2단점프를 MVP에 포함할지, 액션 확장 후보로 보류할지.
