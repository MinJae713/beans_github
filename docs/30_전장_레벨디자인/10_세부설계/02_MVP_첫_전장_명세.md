## 2. 카메라 sliding 정량 규칙

본 절은 W2 회의 결정에 따라 카메라 viewport와 구간의 비율을 잠근다. 절대 좌표·픽셀·Unity unit은 본 문서가 아니라 **카메라 프리셋**과 **`SegmentProfile`**에 둔다. 본 문서는 비율(ratio)만 잠근다.

### 2.1 비율 정의

한 구간(전투 구간 S2~S6 기준)의 횡축 길이를 **5 단위**로 잡았을 때 카메라 viewport의 횡축 폭은 **2 단위**다. 즉:

| 항목 | 값 | 비고 |
|---|---|---|
| 화면 비율 | **16:9** 고정 | 2026-04-29 W2 회의 |
| viewport : 구간 횡축 | **2 : 5 (40%)** | viewport는 한 구간의 40%를 비춘다 |
| 한 구간 내 카메라 이동 폭 | **5 − 2 = 3 단위** | 구간 좌단 정렬 ~ 구간 우단 정렬 사이의 횡축 가용 sliding 폭 |
| 종축(Y) | **고정** | 카메라가 위아래로 따라가지 않는다. 고저차 구간에서 점프 시에도 기본 카메라는 종축 sliding을 하지 않는다. |
| 횡축(X) | **sliding 가능** | 이동 주도권 보유자의 전진 흐름과 압박 방향을 따른다([30/01 §카메라 원칙]). |

> "5/2/3"은 단위가 아니라 **비율**이다. 실제 1 단위가 몇 Unity unit / 몇 픽셀에 해당하는지는 카메라 프리셋과 `SegmentProfile`이 결정한다.

### 2.2 종축 고정의 의미

| 사항 | 처리 |
|---|---|
| 점프 | 캐릭터가 화면 안에서 위로 이동하되 카메라는 따라가지 않는다. 점프 정점이 화면 안에서 읽혀야 하므로 점프 높이는 viewport 종축 안에 들어와야 한다(점프 수치는 `GameplayProfile`). |
| 고저차 패턴(S3·S5 후보) | 단차는 viewport 종축 안에서 표현한다. 화면을 벗어나는 단차는 본 명세 1차 범위에서 도입하지 않는다. |
| 낙사 trigger(S6) | 낙사 trigger 위치 자체는 viewport 종축 안에 두어야 한다([30/20/01 §검수 체크리스트 no.1·2]). |

### 2.3 횡축 sliding 거동

| 사건 | 거동 |
|---|---|
| 이동 주도권이 없거나 초기 정렬 상태 | 카메라는 구간 중심 또는 두 플레이어 중심점(midpoint)을 기준으로 정렬하되, 구간 좌단·우단을 넘지 않게 clamp. `LastKiller`가 없는 라운드 시작/중립 상태에서는 플레이어 전진도 구간 중심 16:9 viewport 안으로 clamp한다. 한 구간 내 sliding 폭은 위 §2.1의 3 단위. |
| 이동 주도권 보유자가 한 구간 내에서 전진 | 카메라는 고정 맵 중앙보다 이동 주도권 보유자의 전진 흐름을 우선한다. 단, 킬 직후 선제 당김 없이 현재 기준을 유지하다가 주도권 보유자가 진행 방향 전방 85%/15% anchor를 넘으면 해당 방향으로만 sliding한다. 후방으로 되감지 않는다. 현재 A303-331 후보 수치는 [85/20/03 §A303-331 카메라 후보 값](../../85_밸런스_프리셋/20_수치프리셋/03_MVP_구간_수치_프리셋.md#a303-331-카메라-후보-값-2026-05-15)에 둔다. |
| 구간 돌파 | `BreakthroughResolving` 동안 카메라가 새 구간으로 전이한다. 돌파 주체는 새 구간의 진입 edge 안쪽 clearance와 실제 지형 착지점에 정렬되어 이전 구간 좌표나 카메라 Y 공식으로 즉시 out-of-bounds/낙사하지 않는다. 구간 변경이 동기화된 프레임에는 양 클라이언트가 같은 의미를 보도록 새 구간 중심으로 즉시 정렬하고, 이후 SmoothDamp와 이동 주도권 sliding을 재개한다. 새 구간 settled 상태에서는 구간 중심 재정렬을 유지하고, 주도권 보유자가 진행 방향 전방 anchor를 넘은 뒤에만 이동 주도권 sliding을 적용한다. sliding 시간은 카메라 프리셋. |
| `VictoryRun` (S1·S7) | 카메라가 승리 예정 캐릭터를 추적해 끝 지점까지 sliding. |
| `RespawnResolving` | 리스폰 위치 정렬에 맞춰 sliding. 즉시 cut은 사용하지 않는다(억울함 방지, [30/20/01 §허용되는 압박]). 사망자는 `IsDead` 상태로 입력이 멈추지만, 생존자는 리스폰 대기 시간 동안 계속 이동할 수 있다. 리스폰 완료는 authoritative respawn revision으로 확정하고, 양 클라이언트는 같은 revision을 관측해 midpoint로 한 번 재정렬한 뒤 이동 주도권 전방 anchor 규칙을 다시 적용한다. |

### 2.4 검수 메모

본 절의 비율을 어기면 [30/20/01 §검수 체크리스트 no.1·2·3·6]을 통과할 수 없다. 카메라 프리셋이 본 명세의 비율과 다른 값을 가지면 프리셋이 우선 BLOCKED 처리되어야 한다.

### 4.4 넉백 경계와의 결합

D45(넉백 경계 이탈 무효)는 **세그먼트 경계 콜라이더**에 적용된다. 낙사는 별도의 위험 지형 메커닉이며 D45 무효화 대상이 **아니다**([10/02 §사망 처리]). 즉, 넉백으로 S5↔S6 또는 S6↔S7 경계에 닿으면 clamp되지만, 넉백으로 S6의 낙사 trigger 영역에 도달하면 정상 사망 판정이 들어간다. 이 구분이 시각적으로 읽히게 낙사 영역과 세그먼트 경계는 같은 좌표에 겹치지 않게 배치한다 → Q48.

### 5.2 양끝 비대칭 운용 (Q49 재검토)

본 명세에서 낙사 압박 구간은 **S6 단일**이다. 좌측 플레이어 입장에서는 마지막 전투 구간(S6)이 낙사 압박이지만, 우측 플레이어 입장에서는 첫 전투 구간(S6)이 낙사 압박이 된다. 이는 [30/01 §구간 길이 기준] "모든 구간 동일 길이 강제 금지"와 함께 구간 압박 비대칭을 허용한다는 입장이다.

다만 양 플레이어의 매치 승리 경로 압박 곡선이 비대칭이 되면 밸런스 이슈로 번질 수 있어 **Q49**(기존 등록)로 계속 추적한다. 5구간 → 7구간 변경에도 Q49의 요지는 동일하다(낙사 압박이 한쪽에는 마지막, 한쪽에는 첫 전투).

[10/02 §최종 구간 처리]·[30/01 §최종 구간 규칙]를 그대로 따른다. 본 명세에서 추가 결정하지 않는다.
