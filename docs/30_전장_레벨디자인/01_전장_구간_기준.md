# 전장 구간 설계

> 상태: accepted_candidate. 이 문서는 5구간 구조, 가운데 3개 전투 구간, 양끝 최종 승리 구간, 이동 주도권 방향에 한해 임시 구현 기준으로 사용한다. 문서 상태와 binding 범위는 `05_문서관리_규칙/08_문서_상태_인덱스.md`를 우선한다.

이 문서는 전장, 구간, 카메라, 리스폰, 공간 압박의 설계 기준을 정의한다.

구간 길이, 카메라 커버리지, 리스폰 비율, 위험 지형 빈도 같은 구체 수치는 이 문서에 고정하지 않는다. 해당 값은 레벨 프리셋이나 `BalanceProfile`에 둔다.

## 용어

| 용어 | 의미 |
|---|---|
| 전장 | 여러 구간이 이어진 전체 진행 공간 |
| 구간 | 한 번의 라운드 전투가 벌어지는 공간 단위 |
| 구간 돌파 | 공격자가 상대 방향 끝을 넘어 전선을 미는 행위 |
| 전투 구간 | 실제 교전과 구간 돌파가 발생하는 가운데 구간 |
| 최종 구간 | 승리 예정 캐릭터가 끝 지점까지 달려가며 매치 승리를 확정하는 양끝 구간 |
| 최종 진영 | 매치 최종 승패가 결정되는 끝 지점 |
| 이동 주도권 | 직전 킬 또는 구간 결과로 전진 방향을 얻은 플레이어의 권한 |

## 전장 구조 원칙

- 전장은 한 번의 전투 공간이 아니라 여러 구간을 밀고 밀리는 진행 구조다.
- 각 구간은 단순 킬보다 위치 압박과 돌파 판단을 만들 수 있어야 한다.
- 구간은 카메라보다 넓어야 하며, 화면 밖 압박이 전술 선택지가 되어야 한다.
- 구간 끝을 넘는 행위는 단순 이동이 아니라 라운드 결과와 연결된다.
- 상대 최종 진영까지 밀어내는 것이 매치 최종 승리 조건이다.
- MVP 기준 전장은 5개 구간으로 구성한다.
- 가운데 3개 구간은 전투 구간이다.
- 양끝 2개 구간은 최종 승리를 보여주는 playable 컷신/승리 예정 구간이다.
- 최종 구간은 리스폰 루프가 아니라 매치 종료를 위한 구간으로 다룬다.
- 테스트 구현의 구간 수와 최종 설계의 구간 수는 분리한다. 테스트에서 많은 방을 만들 수 있어도, 기준 기획은 5개 구간 구조를 우선한다.

## 구간 수와 길이 기준

| 항목 | 기준 |
|---|---|
| 전체 구간 수 | MVP 기준 5개 |
| 전투 구간 | 가운데 3개. 교전, 사망, 구간 돌파, 구간 돌파 패배 카드 지급이 발생 |
| 최종 구간 | 양끝 2개. 상대 리스폰 없이 승리 예정 캐릭터만 진행 |
| 전투 구간 길이 | 카메라 viewport보다 넓게 설계하되 정확한 배율은 전장/카메라 프리셋에서 관리 |
| 최종 구간 길이 | 승리를 만끽할 수 있는 달리기 구간으로 설계하되 정확한 배율은 전장/카메라 프리셋에서 관리 |
| 구간 길이 | 모든 구간 동일 길이 강제 금지. 양상과 가독성 기준으로 조정 |
| 테스트용 다구간 | 무기/카드 누적 폭주 여부를 관찰하기 위한 실험 가능 |

구간이 많아질수록 카드 누적, 무기 강화, 경기 시간, UI 이해도가 모두 영향을 받는다. 따라서 테스트용 다구간은 가능하지만, 실제 기획 기준은 5개 구간과 제한적 카드 지급을 함께 본다.

## 최종 구간 규칙

- 최종 구간에 진입하면 상대방 캐릭터는 리스폰하지 않는다.
- 최종 구간에는 승리 예정 캐릭터만 등장한다.
- `VictoryRun` 동안은 승리 예정 캐릭터만 조작 가능하며, 끝 지점 도달 후 조작 불가능한 최종 연출로 전환된다.
- 예시 연출은 UFO 납치, 괴물에게 잡아먹힘처럼 명확하고 가벼운 승리 연출이다.
- 매치 최종 승리는 최종 구간 진입 순간이 아니라, 끝 지점에 도달해 조작 불가능한 연출이 시작될 때 확정한다.
- 최종 구간은 Nidhogg의 승리 구간과 유사하게 “상대가 없는 승리 확인 구간”으로 다룬다.

## 표시 방식 기준

- 전장은 논리적으로 5개 구간으로 나누되, 플레이어에게는 현재 전선이 이어져 밀리고 밀리는 흐름으로 읽혀야 한다.
- 각 구간은 완전히 분리된 방 전환처럼 끊어 보이지 않아야 한다.
- 화면은 현재 교전 구간과 이동 주도권 방향을 중심으로 보여준다.
- 플레이어가 “지금 어느 구간에서 어느 방향으로 밀고 있는지”를 읽을 수 있어야 한다.
- 같은 화면에 전투를 보여주는 방향이 기본 가독성에는 유리하다.
- 화면 상단에는 전체 구간 진행도와 현재 viewport 위치를 표시하는 방식을 우선 검토한다.
- 최종 구간은 전투 구간과 달리 상대가 없는 승리런으로 읽혀야 하며, 전투 재개 가능성이 있는 공간처럼 보이면 안 된다.

## 카메라 원칙

| 원칙 | 의미 |
|---|---|
| 전투 가독성 | 두 플레이어와 주요 위협이 읽혀야 함 |
| 압박 허용 | 화면 밖 압박이 가능하되 억울한 즉사로 보이면 안 됨 |
| 주도권 중심 | 카메라는 고정된 맵 중앙보다 이동 주도권 보유자의 전진 흐름을 따라감 |
| 이탈 처리 | 맵 경계 이탈은 명확한 라운드 결과로 처리함 |

## 이동 주도권과 진행 방향 UI

- 직전에 상대를 사망시킨 플레이어가 이동 주도권을 얻는다.
- 이동 주도권 보유자는 상대 진영 방향으로 전진할 수 있지만 뒤로 움직일 수 없다.
- 이동 주도권이 없는 플레이어는 뒤로 움직일 수 있으나, 후방 경계나 카메라 규칙을 벗어나면 낙사/경계 사망으로 처리한다.
- 플레이어가 자신의 현재 주도권과 진행 방향을 즉시 읽을 수 있어야 한다.
- 화면 상단에는 예를 들어 `=> GO` 또는 `GO <=` 같은 방향 신호로 이동 주도권 보유자의 진행 방향을 표시한다.
- 이 구조는 Nidhogg식 전선 압박과 구간 돌파 구조를 기준으로 한다.

## 리스폰 원칙

- 리스폰은 구간의 절대 중앙이 아니라 카메라와 공격 방향 기준으로 정렬한다.
- 돌파자는 공격 흐름을 유지할 수 있어야 한다.
- 방어자는 불리한 전선에서 시작하되 즉시 사망하지 않을 시간과 공간을 가져야 한다.
- 리스폰 직후 양쪽 모두 전략을 선택할 최소 여유가 있어야 한다.
- 리스폰 위치의 정확한 비율은 문서가 아니라 프리셋에서 조정한다.

## 압박 우선순위

| 순위 | 압박 방식 | 설계 의도 |
|---|---|---|
| 1 | 벽 몰이/구석 압박 | 위치를 뺏긴 플레이어에게 위험을 줌 |
| 2 | 카메라/화면 밖 압박 | 전선이 밀리는 감각을 강화함 |
| 3 | 고저차 압박 | 점프와 탄도 선택을 요구함 |
| 4 | 낙사/위험 지형 | 강한 변수를 주되 남용하지 않음 |

## 구간 설계 체크

구간을 만들 때는 아래 질문에 답할 수 있어야 한다.

| no | 질문 |
|---|---|
| 1 | 이 구간은 어느 방향으로 압박이 쌓이는가? |
| 2 | 돌파자가 이득을 얻는 이유가 명확한가? |
| 3 | 방어자가 반격할 공간과 타이밍이 남는가? |
| 4 | 카드나 무기 계열에 따라 다른 선택지가 생기는가? |
| 5 | 카메라 이탈과 맵 경계 처리가 직관적인가? |
| 6 | 5개 구간 구조에서 카드 누적과 무기 강화 폭주가 통제되는가? |
| 7 | 최종 구간과 일반 구간의 승패 의미가 분리되어 있는가? |

## 금지

- 플레이어가 이유를 이해하기 전에 즉시 사망하는 구조.
- 특정 무기나 카드 계열만 유효한 단일 해법 구간.
- 전투보다 이동 시간이 대부분을 차지하는 과도하게 긴 구간.
- 리스폰 직후 입력 전에 피격되거나 낙사하는 위치.
- 수치 조정 없이 문서만으로 구간 크기와 카메라 값을 확정하는 방식.

## 미결정

- 최종 구간의 최종 연출을 UFO, 괴물, 다른 연출 중 무엇으로 잡을지.
