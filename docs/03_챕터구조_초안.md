# 챕터 구조 초안

## 설계 원칙
- 초반부터 DAG를 보여준다.
- 챕터마다 새 개념 1개만 크게 추가한다.
- 학생은 같은 `decide(state)` 함수를 계속 개선한다.
- 난이도는 `가능한 작업 판별 -> 시간 고려 -> 공유 작업 -> assignment 확장` 순으로 오른다.

## Chapter 1. 첫 번째 레시피
- 목표
  - 코드 기반 플레이 구조 이해
  - 단일 주문의 DAG 읽기
- 구성
  - 직원 1명
  - 주문 1개
  - 단순한 3노드 레시피
- 학습 포인트
  - 가능한 작업만 선택 가능
  - 선행조건을 만족해야 후속 작업이 가능 상태가 된다
- 교육생 접근 전략
  - `available_assignments`에서 유효한 후보가 하나뿐인 상황을 안정적으로 처리하는 최소 정책을 작성한다.
  - 주문 하나를 끝까지 완주시키는 단순 순차 정책으로도 통과 가능하게 설계한다.
  - 이 챕터의 목적은 최적화가 아니라 `state를 읽고 유효한 Assignment를 반환하는 감각`을 익히는 데 있다.

## Chapter 2. 여러 주문, 여러 선택지
- 목표
  - 독립 DAG가 동시에 존재할 때 작업 우선순위 생각하기
- 구성
  - 직원 1명
  - 주문 2~3개
  - 주문 도착 시점 약간 차이
- 학습 포인트
  - 유효한 선택지가 여러 개일 때 어떤 정책이 안정적인가
  - 단순 FIFO가 항상 최선은 아님
- 교육생 접근 전략
  - 가장 먼저 도착한 주문을 계속 밀어주는 `FIFO`류 정책을 먼저 시도하게 된다.
  - 이후 `현재 가능한 작업이 더 적은 주문`이나 `먼저 끝내기 쉬운 주문`을 우선하는 간단한 우선순위 규칙으로 개선할 수 있다.
  - 이 챕터는 복잡한 자료구조보다 `정책을 바꾸면 결과가 달라진다`는 사실을 체감시키는 구간이다.

## Chapter 3. 긴 작업과 짧은 작업
- 목표
  - 작업 시간 차이를 고려한 정책 설계
- 구성
  - 1틱, 2틱, 3틱 작업 혼합
- 학습 포인트
  - 긴 작업을 잘못 시작하면 뒤 주문을 연쇄적으로 놓칠 수 있음
  - 현재 가능한 작업의 가치가 시간에 따라 달라짐
- 교육생 접근 전략
  - 단순 FIFO에서 벗어나 `짧게 끝나는 작업을 먼저 처리하는` 그리디 기준을 떠올리게 된다.
  - `현재 노드 duration`만 볼지, `이 주문의 남은 총 작업 시간`까지 볼지에 따라 성능 차이가 생긴다.
  - 이 시점부터 `정렬 기반 후보 선택`이나 간단한 우선순위 계산 함수가 의미를 갖기 시작한다.

## Chapter 4. 마감시간과 손님 인내심
- 목표
  - 주문 deadline을 반영한 우선순위 설계
- 구성
  - 짧은 마감과 긴 마감 주문 혼합
- 학습 포인트
  - 가능한 작업 중 무엇이 더 급한가
  - 단순히 빨리 끝나는 작업보다 마감 임박 주문이 더 중요할 수 있음
- 교육생 접근 전략
  - 가장 먼저 시도할 대표 전략은 `EDF (Earliest Deadline First)`처럼 deadline이 가장 가까운 주문을 우선하는 정책이다.
  - 이후 더 나은 성능을 위해 `deadline_tick`만이 아니라 `남은 총 작업 시간`, `현재 작업 duration`, `예상 마감 여유 시간`까지 함께 보는 점수식을 설계하게 된다.
  - 구현 관점에서는 `후보를 점수화하고 가장 작은 값을 뽑는` 구조가 필요해지므로 우선순위 큐나 힙의 도입이 자연스럽다.

## Chapter 5. 공유 준비작업
- 목표
  - 공통 선행작업의 전략적 가치를 체감
- 구성
  - 여러 주문이 같은 준비 노드를 공유
- 예시
  - 육수 준비 -> 우동, 라면
  - 채소 손질 -> 버거, 샌드위치
- 학습 포인트
  - 한 작업이 끝나면 여러 주문의 후속 스케줄링 후보가 동시에 늘어날 수 있다
  - 공유 노드를 늦게 처리하면 병목이 커진다
- 교육생 접근 전략
  - `지금 당장 급한 주문`만 보는 정책이 무너지고, 공유 준비작업이 끝났을 때 이후 스케줄링 선택지가 얼마나 확장되는지를 계산해야 한다.
  - 교육생은 후보 하나가 `몇 개 주문의 후속 작업 후보를 늘려주는지`를 휴리스틱으로 반영하는 방향으로 코드를 확장하게 된다.
  - 이 챕터는 단순 deadline 그리디에서 `공유 준비작업의 후속 선택지 확장 가치`를 보는 정책으로 넘어가는 첫 분기점이다.

## Chapter 6. 러시 아워
- 목표
  - 주문 도착 파이크에 견디는 정책 설계
- 구성
  - 특정 구간에 주문이 몰림
- 학습 포인트
  - 평상시에는 괜찮던 정책이 피크에서 무너질 수 있음
  - 안정성과 순간 효율 사이의 선택이 생김
- 교육생 접근 전략
  - 평균적인 상황에서만 잘 동작하던 정책 대신 `피크 구간에서도 무너지지 않는 안정적 기준`을 고민하게 된다.
  - 도착 직후 긴 작업을 바로 잡는 것이 위험할 수 있으므로, 주문 폭주 직전에는 짧은 작업이나 병목 해소 작업을 우선하는 방어적 정책이 등장한다.
  - 이 챕터는 온라인 상황에서의 `정책 강건성`을 평가하는 구간이다.

## Chapter 7. 역할이 다른 직원
- 목표
  - assignment 문제를 확장 개념으로 도입
- 구성
  - 직원 2명 이상
  - 역할 또는 스킬 차이 존재
- 학습 포인트
  - 어떤 직원을 어떤 작업에 붙일지 판단
  - 이 시점부터 `위상정렬 기반 스케줄링`이 `assignment`로 확장됨
- 교육생 접근 전략
  - 이제는 `무슨 작업을 할지`뿐 아니라 `누가 그 작업을 맡을지`를 함께 결정해야 한다.
  - 초기에는 역할이 맞는 첫 idle 직원을 배정하는 단순 규칙으로 시작하고, 이후 직원별 스킬과 라인 점유 시간을 고려한 매칭으로 고도화할 수 있다.
  - 이 챕터는 기존의 단일 우선순위 정책을 `작업 선택 + 자원 배정` 문제로 확장시키는 역할을 한다.

## Chapter 8. 캡스톤 서비스
- 목표
  - 전체 시스템을 종합한 최종 정책 완성
- 구성
  - 공유 준비작업
  - 다양한 작업 시간
  - 촉박한 마감
  - 피크 타임
  - 다수 직원
- 학습 포인트
  - 하나의 `decide(state)` 정책을 지속적으로 개량하는 경험 완성
- 교육생 접근 전략
  - 특정 규칙 하나만으로는 통과가 어려우므로, `deadline`, `duration`, `공유 작업 가치`, `직원 적합도`를 합친 복합 점수식을 설계하게 된다.
  - 상위권은 단순 규칙 나열이 아니라 예외 상황을 덜 만드는 일관된 우선순위 체계를 만들도록 유도된다.
  - 최종적으로는 `짧고 설명 가능한 그리디 정책`과 `복잡하지만 강한 휴리스틱 정책` 사이의 균형을 고민하게 된다.

## 난이도 상승 방식
- DAG 노드 수 증가
- 동시 주문 수 증가
- 긴 작업 비율 증가
- 마감시간 단축
- 공유 작업 비중 증가
- 직원 수 및 역할 제약 증가

## MVP와 전체 캠페인의 구분
- MVP 범위
  - Ch1~5 중심
  - 직원 1명
  - 공유 작업까지
- 확장 범위
  - Ch6~8
  - 러시 아워, 복수 직원, assignment

## 승인 및 의사결정 체크포인트
- Checkpoint A. Ch1~3 완료 후
  - 확인 질문: `교육생이 DAG 기반 가능 작업 판별과 duration 차이를 코드 정책으로 설명할 수 있는가`
  - 통과 조건: 단일 직원 기준 기본 정책으로 초반 챕터가 안정적으로 재생되고, Ch3에서 FIFO 대비 개선 전략이 문서와 데모 양쪽에서 설명 가능해야 한다.
  - 의사결정: 통과 시 deadline 기반 Ch4 설계를 유지하고, 미통과 시 Ch3 난도를 낮추거나 상태 표현을 단순화한다.
- Checkpoint B. Ch4~5 완료 후
  - 확인 질문: `deadline-aware 그리디와 공유 작업 가치가 분리된 학습 포인트로 보이는가`
  - 통과 조건: Ch4에서 `EDF`와 `마감 여유 시간` 계열 전략이 자연스럽게 등장하고, Ch5에서 공유 준비작업 가치 때문에 기존 정책의 한계가 명확히 드러나야 한다.
  - 의사결정: 통과 시 현재 MVP 범위를 고정하고 시뮬레이터 및 리플레이 UI 설계로 넘어간다. 미통과 시 Ch4와 Ch5의 요소를 재배치하거나 공유 작업 도입 시점을 늦춘다.
- Checkpoint C. Ch6~8 확장 진입 전
  - 확인 질문: `러시 아워와 복수 직원이 기존 학습축을 확장하는가, 아니면 다른 게임처럼 보이게 만드는가`
  - 통과 조건: Ch1~5만으로도 하나의 완성된 학습 경험이 성립해야 하며, Ch6~8은 명확한 상위권/확장 콘텐츠로 분리되어야 한다.
  - 의사결정: 통과 시 확장 챕터를 유지한다. 미통과 시 MVP를 공식 범위로 확정하고 Ch6~8은 후속 과제로 격리한다.

## 챕터 설계 결론
- 초반은 `위상정렬 기반 판단`을 명확히 보여줘야 한다.
- 후반으로 갈수록 `스케줄링과 assignment`가 얹히는 구조가 적합하다.
- 이 구성이 현재 프로젝트의 학습 목표와 발표 설득력을 가장 잘 맞춘다.
- 각 챕터에서 교육생이 떠올릴 대표 전략이 자연스럽게 다음 챕터의 한계로 이어져야 레벨디자인이 교육 목적과 맞물린다.
