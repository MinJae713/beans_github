# 작업 브리핑 양식

> 문서 상태: candidate
> binding 범위: 작업 범위, 허용 파일, 검증 기준을 고정하기 위한 양식이다. 새 게임 규칙 또는 기술 기준을 직접 확정하지 않는다.
> 실행 중단 조건: 브리핑 없이 코드, 에셋, 공용 프리팹, 네트워크 설정을 수정해야 하는 경우 먼저 담당자 확인을 받는다.
> 상태 기준: 문서 상태와 binding 범위는 `05_문서관리_규칙/08_문서_상태_인덱스.md`를 우선한다.

작업자에게는 아래 양식을 기본으로 전달한다. 작업자는 사람 또는 AI 도구를 사용할 수 있다.

목적은 특정 도구에 맞추는 것이 아니라, 작업 범위와 검증 기준을 명확히 고정해 게임 규칙, 아키텍처, 공유 에셋이 임의로 바뀌지 않게 하는 것이다.

## 문서의 위치

작업 브리핑은 새로운 게임 규칙을 정하는 문서가 아니다. 이미 합의된 기준문서와 기능 스펙을 바탕으로, 이번 작업에서 실제로 무엇을 수정하고 어떻게 검증할지 정리하는 작업 단위 문서다.

| 구분 | 역할 |
|---|---|
| 기능 스펙 | 기능의 목적, 플레이어 경험, 포함/제외 범위를 잠근다 |
| 작업 브리핑 | 해당 기능 또는 수정 작업을 누가, 어떤 범위에서, 어떤 기준으로 수행할지 잠근다 |
| 결과 보고 | 작업 후 변경 내용, 검증 결과, 남은 리스크를 다음 작업자가 복구할 수 있게 남긴다 |

작은 버그 수정, 단순 문서 수정, 수치 프리셋 조정은 기능 스펙 없이 작업 브리핑만으로 진행할 수 있다. 반대로 전투 양상, 카드 지급, 구간 돌파, 네트워크 truth, 공용 프리팹에 영향을 주면 기능 스펙 또는 기준문서를 먼저 확인한다.

## 기본 원칙

```text
게임 규칙, 아키텍처, 공유 에셋, 네트워크 구조를 바꾸는 충돌이면 구현하지 말고 BLOCKED로 보고한다.
단순 구현 디테일은 가정을 명시하고 진행한 뒤 Handoff Summary에 기록한다.
```

## 브리핑 없는 작업 금지

Jira 이슈 또는 작업 브리핑 없이 코드, 에셋, 공용 프리팹, 네트워크 설정을 수정하지 않는다. 브리핑이 없으면 먼저 이 문서 양식으로 작업 브리핑 초안을 만들고 담당자 확인을 받는다.

단순 문서 오탈자, 깨진 링크, 개인 로컬 메모 정리처럼 게임 규칙과 구현 산출물에 영향이 없는 초소형 작업만 예외로 둔다.

## 기술스택 준수 게이트

기술 구조 기준이 `accepted` 상태라면 작업자는 구현 전에 사용 API가 기준과 충돌하지 않는지 확인한다.

현재 기준은 `Unity 2022.3 LTS + Photon Fusion 2 + Rigidbody2D/Collider2D/NetworkRigidbody2D`다.

| 구분 | 기준 |
|---|---|
| 허용 | Rigidbody2D, Collider2D, NetworkRigidbody2D |
| 허용 | NetworkBehaviour, FixedUpdateNetwork, INetworkInput |
| 금지 | 신규 3D Rigidbody, 3D Collider, ConfigurableJoint |
| 금지 | 액티브 래그돌 전제, 3D 물리 기반 캐릭터 확장 |
| BLOCKED 조건 | 기존 코드가 금지 API에 의존해 목표 구현이 불가능함 |

기존 코드에 금지 API가 남아 있으면 무조건 삭제부터 하지 않는다. 이번 작업 범위에서 확장해야 하는 경우 `BLOCKED`로 보고하고, 단순 관찰이면 기술 부채로 기록한다.

## Unity 기본값

별도 지시가 없으면 아래 값을 사용한다.

| 항목 | 기본값 |
|---|---|
| Unity 버전 | Unity 2022.3 LTS 계열 |
| 구현 레포 루트 | 팀이 합의한 Unity 구현 레포의 clone 루트 |
| Unity 프로젝트 루트 | `Assets/`, `Packages/`, `ProjectSettings/`가 있는 경로. 브리핑에는 repo-relative path로 명시 |
| Jira 이슈 키 | A303-{번호} |
| Git 브랜치 형식 | 코드/에셋은 `{타입}/A303-{번호}-{간단한-설명}`, 문서는 `docs/A303-{번호}-{도메인}-{기능}` |
| MR 기본 방향 | 팀 GitLab 확인 후 결정. 현재 관찰 기준은 feat/fix/hotfix -> develop, develop -> master 후보 |
| smoke checklist | `70_검증_체크리스트/01_스모크테스트.md` |
| raw artifact 위치 | 팀이 합의한 레포 밖 또는 ignore된 로컬 artifact 경로 |
| 공유 요약 위치 | `docs/` 아래 요약 문서 또는 MR 본문 |

Jira/Git 컨벤션은 `80_Jira_Git_운영_원칙/01_Jira_Git_컨벤션.md`를 따른다. 단, 해당 Git 컨벤션 원문이 팀 합의 전 상태라면 실제 GitLab 설정과 담당자 안내를 우선 확인한다.

브랜치 생성, MR 대상 브랜치 확정, protected branch 수정은 담당자 또는 GitLab 설정 확인 전에는 실행하지 않는다. 템플릿의 예상 브랜치와 MR 대상 브랜치는 계획값이며 실행 권한이 아니다.

## 설계 연결 규칙

- 전투/밸런스 작업은 `20_전투_밸런스_기준/04_관찰지표_정의.md`의 관찰축과 사망 원인 분류 중 무엇을 검증하는지 적는다.
- 구간/맵 작업은 `30_전장_레벨디자인/10_세부설계/01_구간_패턴_카탈로그.md`의 패턴 이름과 핵심 압박을 적는다.
- 카드/무기 작업은 `40_카드_무기_설계/02_카드_효과_분류_기준.md`의 효과 분류와 누적 방식을 적는다.
- 수치 변경 작업은 기준문서가 아니라 `BalanceProfile`, `WeaponProfile`, `CardDefinition` 또는 동등한 프리셋 산출물을 지정한다.
- 미결정 질문이 있으면 `90_백로그/04_미결정_질문_레지스터.md`의 ID를 적고, `blocked` 상태의 P0 질문은 구현하지 않는다.
- 관련 기준문서가 `accepted` 또는 `accepted_candidate` 상태라면 작업자는 충돌 여부를 먼저 보고한다.

## 완료 판정

작업 결과는 다음이 있어야 완료로 본다.

- Jira 이슈 또는 이슈가 없는 이유.
- 브랜치/커밋/MR 컨벤션 준수 여부.
- 변경 파일 목록.
- 실행한 테스트 또는 실행하지 못한 이유.
- 플레이어 체감 변화 요약.
- 기준문서와 충돌한 지점이 있는지 여부.
- 테스트 결과 XML 또는 대체 로그 증빙 위치.
- 패키지/import warning이 있었는지와 계속 진행한 이유.
- 다음 작업자가 이어받을 때 필요한 주의사항.

```markdown
# 작업 브리핑

## Jira/Git Linkage
- Jira 이슈: A303-00
- Jira 구분자: [PHYSICS]
- Jira Component: Physics
- Priority: High
- 예상 브랜치: feat/A303-00-jump-tuning
- 커밋 타입: feat
- MR 대상 브랜치: develop(팀 GitLab 설정 확인 후)
- 관련 컨벤션: 80_Jira_Git_운영_원칙/01_Jira_Git_컨벤션.md

## Environment
- Unity 버전: Unity 2022.3 LTS 계열
- Unity 프로젝트 루트: <Assets/Packages/ProjectSettings가 있는 repo-relative path>
- 작업 브랜치/워크트리: 현재 브랜치, 기존 dirty 파일은 되돌리지 말 것
- 실행 방식: Unity Editor PlayMode
- 테스트 결과 저장 위치: <local-artifacts-root>/<timestamp>-jump-tuning/

## Context
- 관련 기준문서: docs/10_게임플레이_기준/01_핵심_게임루프.md
- 현재 구현 위치: Assets/_LoopDuel/Presentation 또는 Input 관련 파일
- 이전 결정: 전투는 위치 기반 킬각을 우선한다

## Stack Compliance
- 목표 기술스택: Rigidbody2D/Collider2D/NetworkRigidbody2D
- 허용 API: 2D 물리와 Fusion 입력/네트워크 API
- 금지 API: 신규 3D Rigidbody, ConfigurableJoint, 액티브 래그돌 확장
- 기존 충돌 코드: 발견 시 파일/라인 기록
- 충돌 시 처리: 목표 구현이 금지 API 확장을 요구하면 BLOCKED

## Goal
- 플레이어가 체감해야 하는 변화: 점프가 구간 구조를 안정적으로 오를 수 있을 만큼 높아진다
- 이번 작업에서 끝낼 범위: 점프 수치 조정과 smoke 확인

## Layer Scope
- Domain: 변경 없음
- Presentation: 이동 파라미터 반영 가능
- Input: 변경 없음
- Config: 점프 관련 수치 변경 가능

## File Permission
- 수정 가능: 점프/이동 설정 파일
- 읽기 전용 참고: smoke checklist
- 동시 수정 금지: 공용 씬/프리팹
- 생성 가능 산출물 위치: 팀이 합의한 레포 밖 또는 ignore된 로컬 artifact 경로

## Do Not Change
- 공격, 카드, 승패 규칙은 변경하지 말 것

## Acceptance Test
- Manual Smoke: P1/P2 이동, 점프, 기본 발판 이동 확인
- 통과 기준: 두 플레이어 모두 동일하게 발판 도달 가능
- 관찰 체크포인트: 위치 킬각과 반격 가능성이 사라지지 않는지 확인

## Artifact Policy
- raw 로그/스크린샷/영상 위치: <local-artifacts-root>/<timestamp>-jump-tuning/
- 테스트 결과 XML 위치: 생성되면 raw artifact logs 또는 results 아래 기록
- XML 미생성 시 대체 증빙: Unity 로그 파일 경로와 프로세스 종료코드 기록
- 패키지/import warning 처리: 플레이 차단 여부를 판단해 계속/중단 사유 기록
- docs 요약 필요 여부: 불필요
```
