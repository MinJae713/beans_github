## Q39 — 이동 주도권 후진 금지 구현 경계

### 현재 문서 상태

- [10_게임플레이_기준/02_라운드_상태머신.md:88](../10_게임플레이_기준/02_라운드_상태머신.md) — "이동 주도권 보유자는 뒤로 이동할 수 없으며, 진행 방향은 확정된 주도권 상태를 읽어 상단 방향 UI로 표시"
- [10_게임플레이_기준/03_입력_행동_규칙.md](../10_게임플레이_기준/03_입력_행동_규칙.md) — "이동"을 InputAuthority/StateAuthority 구분만 하고 후진 reject 규칙 없음

### 문제

Nidhogg 정체성의 **가장 중요한 메카닉**인데, 이 제약을 **어디서 enforce할지**가 세 문서 어디에도 없다.

- 팀원 A의 AI: local input을 0으로 clamp → Fusion prediction에서 문제없어 보임
- 팀원 B의 AI: StateAuthority에서 reject + 결과 상태에 반영
- 팀원 C의 AI: 둘 다

세 방식 모두 "구현 가능"하지만 네트워크 정합성이 다르다.

### 영향

- 이동 컨트롤러의 책임 경계
- 후진 입력 시 클라이언트 UI 피드백 (잠금? 무시? 시각 경고?)
- resimulation 시 후진 의도가 로깅되는가

### 의사결정 옵션

| Option | 내용 | 장단 |
|---|---|---|
| A | InputAuthority 측 local clamp (클라이언트 input에서 차단) | 단순. 클라이언트 UI 피드백 즉각. 하지만 cheat 클라이언트 우회 가능 |
| B | StateAuthority 측 reject (tick 결과로 반영) | authoritative. cheat 방지. 그러나 클라이언트 예측과 차이 → 시각 보정 필요 |
| C | 양쪽 (local clamp + StateAuthority 최종 검증) | 가장 안전. 코드 중복 |

권장: **C** (MVP 안전성 우선). 후진 입력은 local에서 즉시 0 clamp하되 StateAuthority도 한 번 더 확인.

## Q41 — 방어자 넉백 공격자 경계 초과

### 현재 문서 상태

- [10_게임플레이_기준/02_라운드_상태머신.md:156](../10_게임플레이_기준/02_라운드_상태머신.md) — "동시 구간 돌파처럼 드문 경계 상황의 세부 타이브레이크는 StateAuthority 결과 우선순위를 따르되, 구현 전 브리핑에서 재확인한다" (미정)
- [20_전투_밸런스_기준/02_전투_판정_규칙.md:62-66, 87](../20_전투_밸런스_기준/02_전투_판정_규칙.md) — "동시 판정"은 동시 사망만 다루고 돌파 동시성 미정의

### 문제

공격자 A가 주도권을 갖고 방어자 B를 넉백시켰을 때, **B가 A의 공격 방향 경계(= A의 목표)를 넘는 경우**가 가능. Nidhogg식 펜싱 + ROUNDS 넉백 카드 조합에서 쉽게 발생하는 상황.

- A의 구간 돌파로 처리? → 돌파자는 B인데 A가 카드를 받음 (모순)
- B의 경계 이탈 패배? → 넉백이 방어자에게 유리한 결과가 되어 Nidhogg 정체성 파괴
- 넉백 카드 한 장이 **전투 결과를 역전**시키는 버그

### 영향

- 넉백 카드 설계 전반
- 구간 돌파 판정 로직 (Q40과 연동)
- 카드 가치 밸런스

### 의사결정 옵션

| Option | 처리 | 장단 |
|---|---|---|
| A | 주도권 보유자만 경계 통과로 돌파 처리. 비주도권자 경계 통과는 **경계 이탈 패배(사망 정규화)** | Nidhogg 정체성 보존. 넉백 역전 방지. B가 자살한 것으로 해석 |
| B | 누가 넘었는지 무관하게 공격자가 구간을 차지 (공격자 카드 수령) | 공격자에게 유리. 그러나 B가 넉백당한 상황에서 A가 보상 받는 게 정당한가 의문 |
| C | 넉백으로 인한 경계 초과는 **무효 처리** (B를 경계 직전으로 되돌림) | 가장 관대. 구현 복잡 |

권장: **A**. 이미 [10/01 핵심 게임루프:37](../10_게임플레이_기준/01_핵심_게임루프.md) 의 "주도권 없는 플레이어의 후방 이탈 = 낙사/경계 패배" 규칙과 정합.

## Q42 — 카드 선택 핸드셰이크 race condition

### 현재 문서 상태

- [10_게임플레이_기준/02_라운드_상태머신.md:120](../10_게임플레이_기준/02_라운드_상태머신.md) — "시간 만료 시 제시된 후보 중 랜덤 자동 선택으로 확정"
- [40_카드_무기_설계/30_구현가이드/01_카드_선택_네트워크_핸드셰이크.md](../40_카드_무기_설계/30_구현가이드/01_카드_선택_네트워크_핸드셰이크.md) — 요청/검증/확정 흐름은 있지만 자동 선택 ↔ 마지막 순간 플레이어 선택의 동시 도착 해소 없음
- Q35 (closed): "InputAuthority one-shot request -> StateAuthority 검증 -> Networked 결과 확정"은 기본 방향 확정. 그러나 동시 도착 race는 미해소

### 문제

타임아웃 랜덤 자동 선택과 플레이어의 마지막 클릭이 **동일 tick에 도착**할 수 있다. 두 이벤트의 우선순위가 명시되지 않으면 Host/Client 사이에 확정 결과가 다를 수 있다.

또한 자동 선택의 **랜덤 seed**가 Host/Client 간 동기화되는 방식도 비어 있음. Fusion에서 결정론을 보장하려면 tick-based seed 또는 Networked seed 필요.

### 영향

- 카드 시스템 전반의 결정론
- ChoicePending → RespawnResolving 전이의 안정성
- MVP 이후 관전 기능 추가 시 다시 터짐

### 의사결정 옵션

| Option | 처리 | 장단 |
|---|---|---|
| A | 타임아웃 우선 — 만료 tick 이후에 도착한 플레이어 입력은 무시 | 단순. 플레이어 클릭이 "간발의 차"로 무효되는 UX 사고 가능 |
| B | 플레이어 입력 우선 — 타임아웃 tick +1 이내에 도착한 입력은 확정 채택 | UX 호의. grace window 크기 추가 정의 필요 |
| C | StateAuthority가 도착 순서(tick + 서브-tick)로 해결 | 엄밀. 구현 복잡. Fusion tick 해상도 범위 내에서 tie-break 정의 필요 |

Seed 방식: **Networked seed를 StateAuthority가 ChoicePending 진입 시 뿌리는 방식** 권장. 또는 `Runner.Tick`을 seed로 파생.

권장: **B (grace 1 tick) + StateAuthority seed 브로드캐스트**.

## Q43 — 카드 누적 vs "1탄창 처치 금지" 철학 충돌

### 현재 문서 상태

- [10_게임플레이_기준/01_핵심_게임루프.md:86](../10_게임플레이_기준/01_핵심_게임루프.md) — "기본 무기는 한 탄창만으로 풀피 대상을 확정 처치하면 안 된다"
- [20_전투_밸런스_기준/01_밸런스_철학.md:20](../20_전투_밸런스_기준/01_밸런스_철학.md) — 동일 선언
- [20_전투_밸런스_기준/03_TTK_판단_프레임.md:24, 34](../20_전투_밸런스_기준/03_TTK_판단_프레임.md) — "카드 한 장으로 삭제 = 나쁜 TTK 신호", "카드가 강해져도 전투가 즉사전으로 붕괴하지 않는다"
- [10_게임플레이_기준/01_핵심_게임루프.md:57-58](../10_게임플레이_기준/01_핵심_게임루프.md) — 카드는 패배자에게 누적 지급 (ROUNDS 방식)

### 문제

ROUNDS의 재미는 **카드 누적으로 화력이 극적으로 증폭**되는 것. 그러나 이 프로젝트는 동시에 "한 탄창 내 처치 금지" + "카드 한 장 삭제 금지"를 선언한다.

3구간 × 1~2장 카드 = **최대 6장 누적**. 각 카드가 약하면 선택의 재미가 없고, 강하면 선언된 원칙이 수학적으로 깨진다. Q36의 "에픽 2 / 레전더리 1" 티어 제한으로 **부분 완화**되나 본질 해소 아님.

### 영향

- 카드 수치 프리셋 전체
- 카드 카탈로그 설계 (화력 증폭 vs 상호작용 변형 비율)
- TTK 판단 프레임의 실효성

### 의사결정 옵션

| Option | 방향 | 결과 |
|---|---|---|
| A | "한 탄창 처치 금지" 원칙 철회, 카드 누적 3장부터는 TTK 급락 허용 (ROUNDS 우선) | 후반부 즉사전이 재미가 됨. Nidhogg 긴 교전감 일부 포기 |
| B | 카드는 **상호작용 변형만** (넉백/반사/곡사/관통). 화력 증폭 카드 자체를 MVP 배제 (Nidhogg 우선) | 긴 교전감 유지. ROUNDS 화력 카드의 재미는 버림 |
| C | 상한 수치 가이드 추가 — 3장 누적 시 TTK 50% 이상 단축 금지 | 양쪽 절충. 카드 효과 설계 시 상한 체크 의무화 |

권장: **C**. 수치 상한을 GameplayProfile 설계 원칙에 추가하고, 카드 카탈로그에서 화력 증폭 카드 수량을 제한.

## Q45 — 리스폰 무적 방식

- [10_게임플레이_기준/02_라운드_상태머신.md:125](../10_게임플레이_기준/02_라운드_상태머신.md) — 동일 원칙
- [20_전투_밸런스_기준/02_전투_판정_규칙.md:89](../20_전투_밸런스_기준/02_전투_판정_규칙.md) — "경직/무적 프레임을 MVP에 포함할지, 피드백 연출로만 둘지" **미결정** (Q4 deferred와 연동)

### 문제

"즉시 피격되지 않아야 한다"는 목표만 있고 **구현 방식이 비어 있다**. 세 가지 방식이 가능하고 각각 결과가 다르다.

- 무적 프레임: 피격 판정 자체가 무시됨
- 리스폰 위치를 충분히 멀게: 거리로 보호
- 입력 잠금 + 상대 입력 잠금: `RoundIntro`처럼 양쪽 잠금

### 영향

- 전투 판정 규칙
- 리스폰 연출 (피격자 시각 신호 필요 여부)
- 플레이테스트 관찰지표 "반격 가능성"의 해석

### 의사결정 옵션

| Option | 방식 | 장단 |
|---|---|---|
| A | 무적 플래그 (Networked bool) 1~2초 | 표준. VFX로 시각 신호 필요 |
| B | 리스폰 위치를 공격자로부터 충분히 멀게 | 플래그 없이 단순. 좁은 구간에서 동작 안 함 |
| C | 양쪽 입력 잠금 (RoundIntro 재사용) | 양쪽 모두 행동 못 함. UX 갑갑 |

권장: **A** (무적 플래그 + 시각 신호). GameplayProfile에 무적 지속 시간 프리셋화.
