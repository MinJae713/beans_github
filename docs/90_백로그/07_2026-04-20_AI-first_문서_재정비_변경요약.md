# 2026-04-20 AI-first 문서 재정비 — 변경 요약

> 상태: reference. 이 문서는 담당 팀원에게 2026-04-20 작업으로 바뀐 내용을 공유하는 1회성 핸드오프 노트다. 팀 검토 후 결정 사항이 반영되면 archive로 이동한다.

## 왜 이 작업을 했는가

기존 `docs/` 기준문서가 "팀원이 AI를 활용해 작업하기 위한 AI-first 기준문서"라는 정체성에 비춰 빈 틈이 있어 보였다. 5개 AI 에이전트(analyst / architect / designer / code-reviewer / critic)에게 독립 딥 리뷰를 시켜 공통 지적을 추려냈고, 그중 **결정 공백을 요구하지 않는 부분만** 이번에 반영했다. 결정이 필요한 항목은 전부 별도 제안 문서로 분리해 팀 리뷰를 남겼다.

AI-first 관점 재평가에서 확인된 바로는:
- 문서 63개가 많다·README 읽는 순서가 과하다 같은 비판은 **인간 onboarding 전제였으므로 무효**.
- 반면 **결정 공백 · SOT 분산 · drift · Fusion 실전 함정 공백**은 AI가 읽어도 동일하게 할루시·오구현을 유발하므로 유효.
- 추가로 AI 도구 체인 / 작업 유형별 참조 경로 / AI-first 품질 기준처럼 **AI 활용 관점에서만 부각되는 취약점**이 드러났다.

이번 작업은 **(a) 내용 손실이 없는 추가** + **(b) 결정 없이 가능한 뼈대 생성** + **(c) 팀 회의 안건용 제안 문서**로 한정했다. 기존 문서 재작성·삭제·병합은 수행하지 않았다.

## 일괄 변경 (⚠ 주의 필요)

### frontmatter 일괄 삽입 — 65개 파일

`docs/**/*.md` 전체 65개 파일 맨 위에 아래 블록을 일괄 삽입했다.

```yaml
---
last_updated: 2026-04-20
audience: ai-first
---
```

#### ⚠ 알려진 부작용

**기존 상태 표기(`> 상태: ...` 인용 블록)와 중복**이다. 예: Fusion 가드레일은

```markdown
---
status: candidate              ← 신규 frontmatter
last_updated: 2026-04-20
audience: ai-first
---

# Fusion 구현 가드레일

> 상태: accepted_candidate.    ← 기존 인용 블록
```

두 군데가 상태를 서로 다르게 표기할 수 있다(`candidate` vs `accepted_candidate`). 이는 **AI가 두 값을 읽고 혼란**을 줄 수 있으므로 빠른 해소가 필요하다.

#### 해소 옵션 (팀 결정 필요)

- **Option X (권장)**: 기존 `> 상태:` 인용 블록을 **정본**으로 유지하고, 모든 frontmatter에서 `status:` 를 제거해 frontmatter에는 `last_updated`와 `audience`만 남긴다.
- **Option Y**: frontmatter를 정본으로 삼고 기존 `> 상태:` 인용 블록을 전부 제거. 인용 블록의 추가 설명(binding 범위 등)은 본문 하위 섹션으로 이동.
- **Option Z**: 둘 다 유지하되 `08_문서_상태_인덱스.md` 의 값을 정본으로 선언하고 나머지는 참고 표기로 격하.

의사결정이 필요한 Q로 [미결정 질문 레지스터](04_미결정_질문_레지스터.md) 에 추가 검토.
