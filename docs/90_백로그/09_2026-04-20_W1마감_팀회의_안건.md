#### Q39 — 이동 주도권 "후진 금지" 어디서 막을 것인가

**상황**
이 게임은 주도권자(돌파 중인 쪽)가 전진만 가능하고, 주도권을 잃은 쪽은 밀려나야 한다. 플레이어가 주도권을 잃은 상태에서 "뒤로 가기" 방향 키를 누르면 무엇으로 막을 것인가.

**선택지**

| 옵션 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A | StateAuthority 입력 clamp만 | 서버 권위 단일 | 원격 환경에서 "입력했는데 반영 안 됨" 체감 |
| B | InputAuthority local clamp만 | 즉각 피드백 | 치팅 우회(조작된 클라이언트로 후진 가능) |
| **C (권장)** | **A + B 이중** | 즉각 피드백 + 치팅 방어 | 두 곳에 로직 쓰는 부담 |

**Jun 권장: Option C**. 이유: 격투/대전 게임 관행. local clamp로 UX 유지 + authoritative 검증으로 desync·치팅 방어.

**미결정 시**: W2 ① "Fusion Host 2P 연속매치" 착수 불가 (이동 컨트롤러 리팩토링 금지).

**결정 후 반영**: `10_게임플레이_기준/03_입력_행동_규칙.md`에 한 줄 추가 + D-번호 발급.

#### Q40 — 구간 돌파를 "넘었다"고 누가 판정할 것인가

**상황**
전장 5구간 중 한 구간에서 다음 구간으로 플레이어가 넘어갔는지 authoritative하게 판정해야 한다. 기준을 무엇으로 삼을 것인가.

**선택지**

| 옵션 | 기준 | 장점 | 단점 |
|---|---|---|---|
| **A (권장)** | **`SegmentBoundary` 콜라이더** | Unity 표준, 디자이너가 시각적으로 배치 | 콜라이더 누락 시 버그 |
| B | 카메라 경계 | 별도 설정 불필요 | 카메라 이동 로직과 결합 → 의존성 순환 |
| C | 프리셋 x좌표 | 수치만으로 제어 | 하드코드, 구간 수치 변경 때마다 재컴파일 |

**Jun 권장: Option A**. 이유: 디자인-엔지니어 경계가 깔끔(디자이너가 콜라이더 배치, 엔지니어는 OnTriggerEnter만). 카메라 로직 독립성 유지.

**미결정 시**: W2 돌파 로직, 최종 구간 전이, 카드 지급 트리거 모두 구현 금지.

#### Q41 — 방어자가 공격자 넉백으로 공격자 경계를 넘은 경우

**상황**
공격자(주도권자)가 방어자에게 Buckshot/Shove를 맞고 뒤로 밀려, 방어자가 앞으로 밀려 **공격자 방향 경계**를 넘어간 엣지 케이스. 이건 방어자의 돌파로 처리할 것인가, 경계 이탈 사망인가.

**선택지**

| 옵션 | 처리 | 결과 |
|---|---|---|
| **A (권장)** | **경계 이탈 사망**(방어자 사망) | 주도권자만 돌파 가능, 주도권 역전은 후속 공격으로 |
| B | 돌파 처리(방어자가 공격자 카드 수령) | 주도권 뒤집힘, 넉백 카드가 돌파 수단으로 변질 |

**Jun 권장: Option A**. 이유: "주도권자의 밀어붙임"이라는 돌파 정의와 정합. Nidhogg도 동일 로직(앞으로 달리다 경계 넘으면 죽음).

**미결정 시**: Shove/Buckshot 등 넉백 계열 카드 구현 금지 → W2 카드 10종 확정 불가.

**결정 후 반영**: `10/02 라운드 상태머신` 사망 트리거 섹션 + `40/10/02 카운터 상성 매트릭스`.

#### Q42 — ChoicePending race condition + seed 동기화

**상황**
카드 선택 화면에서 타이머(예: 10초) 만료 직전에 플레이어가 클릭했을 때, **플레이어 선택**과 **타임아웃 랜덤 자동 선택**이 동일 tick에 도착할 수 있다. Host/Client가 다른 결과를 확정하면 원격 세션에서 카드가 desync된다. 또 랜덤 자동 선택의 **seed**를 어떻게 동기화할 것인가.

**선택지**

| 옵션 | race 처리 | seed 동기화 |
|---|---|---|
| A | 플레이어 선택 절대 우선(타임아웃 무시) | 로컬 각각 → Host 최종값이 강제 동기화 |
| **B (권장)** | **Grace 1 tick**(선택 후 1 tick 내 타임아웃은 버림) | **Networked seed 브로드캐스트**(매치 시작 시 Host가 송신) |
| C | 타임아웃 우선 | (고려 안 함) |

**Jun 권장: Option B**. 이유: Grace tick으로 UX 방어 + Networked seed로 결정론 보장. Fusion 표준 패턴.

**미결정 시**: W3 원격 2P 카드 선택에서 desync 발생 위험. 디버깅에 며칠 소요 가능.

**결정 후 반영**: `40/30/01 카드 선택 핸드셰이크` seed 섹션 신설 + `10/02 ChoicePending` 섹션에 race 정책 한 줄.

예시(`85_밸런스_프리셋/10_데이터스키마/01_BalanceProfile_스키마.md`가 가이드):
```yaml
# 85/20/01 전투 수치 프리셋 스키마 v0 (수치는 모두 TBD)
maxHealth: float      # HP
baseDamage: float     # 탄당 피해량
fireRate: float       # 초당 발사 (Hz)
magazineSize: int     # 장탄수
reloadTime: float     # 재장전 시간 (초)
bulletSpeed: float    # 탄속 (units/s)
```

구체 수치는 W3~W4 플레이테스트 결과로 채움.

#### 선택지

| 옵션 | 결정 |
|---|---|
| **A (권장)** | **스키마-only 커밋을 W2 Exit에 추가**. 담당: 최진우 또는 김범승 |
| B | 스키마+수치 세트를 W3까지 미룸 (현재 계획) |

**미결정 시**: Unity 쪽에서 ScriptableObject 생성 불가 → 수치 변경 때마다 코드 수정.

**결정 후 반영**: `SCHEDULE.md W2 Exit Criteria`에 ⑥ 추가 + 담당자 배정.
