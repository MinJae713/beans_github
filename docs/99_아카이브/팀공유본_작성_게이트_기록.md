# 팀 공유본 작성 게이트

> 상태: archived
>
> 보관 이유: 내부 기준문서를 팀 공유본으로 정제할 때 사용한 제작 게이트 기록이다. 현재 팀원이 읽어야 하는 운영 기준은 `05_문서관리_규칙/09_팀공유본_검토_기준.md`와 `README.md`를 따른다.
>
> 사용 금지: 이 문서를 현재 작업 기준, 팀 공유본 작성 의무, 구현 판단 근거로 사용하지 않는다.

이 문서는 내부 기준문서를 팀 공유본으로 정리하기 전에 확인해야 하는 미결사항 정리 기준이다.

팀 공유본은 흩어진 메모를 그대로 복사한 묶음이 아니다. 팀원이 맥락 없이 읽어도 현재 기준, 보류 항목, 구현 금지선, 세부설계 위치를 구분할 수 있게 정리한 상세 명세서다.

## 공유본 착수 조건

| 조건 | 기준 |
|---|---|
| P0 open/blocked 없음 | 구현 구조, 승패 규칙, 네트워크 truth를 막는 질문이 열려 있으면 공유본 작성 중단 |
| P0 assumed 명시 | 임시 가정으로 진행 가능한 P0는 재확인 시점과 책임 영역을 적음 |
| closed 결정 반영 | 이미 닫힌 질문이 개별 문서의 미결정 섹션에 남아 있지 않음 |
| deferred 분리 | 지금 결정하지 않을 항목은 공유본에서 “보류/확장”으로 표시 |
| 수치 비고정 | 피해량, 탄속, 쿨타임, 제한 시간 같은 값은 프리셋 후보로만 설명 |
| 로컬 맥락 제거 | 개인 경로, 세션명, 내부 실행 산출물 경로, secret, App ID를 제거 |

## 미결사항 분류

| 분류 | 공유본 처리 |
|---|---|
| P0 closed | 확정 기준으로 설명 |
| P0 assumed | 구현 주의사항으로 설명하고, 작업 브리핑에서 재확인하도록 표시 |
| P0 open/blocked | 공유본 작성 중단 |
| P1 open/assumed | 해당 기능 구현 전 재확인 질문으로 표시 |
| P1 deferred | MVP 이후 또는 플레이테스트 이후 보류 항목으로 표시 |
| P2 open/deferred | 공유본 말미의 백로그 또는 미확정 항목에 짧게 기록 |

## 현재 공유 전 판정

2026-04-20 기준 내부 문서는 팀 공유본 초안을 만들 수 있는 상태다.

| 항목 | 판정 | 근거 |
|---|---|---|
| P0 open/blocked | 없음 | `90_백로그/04_미결정_질문_레지스터.md` 기준 |
| P0 assumed | 있음 | 동시 사망, 투사체 네트워크 처리 |
| 팀 공유 전 필수 결정 | 없음 | 남은 P0는 임시 가정과 재확인 시점이 있음 |
| 공유본에 보류로 표시할 항목 | 있음 | 대시, 관전, 2v2, 일반 전투 사망 카드 지급, 브랜딩 |

## 공유본에 확정으로 넣을 내용

- MVP는 1v1이다.
- 기술 기준은 Unity 2022.3 LTS, URP, Photon Fusion 2, 2D 물리 기반이다.
- 전장은 5개 구간이다.
- 가운데 3개는 전투 구간, 양끝 2개는 최종 승리 구간이다.
- MVP 카드 지급 기본 트리거는 구간 돌파 패배다.
- 일반 사망마다 카드를 지급하지 않는다.
- 카드는 총기 교체가 아니라 총알 성질과 발사 리듬을 바꾸는 방향을 우선한다.
- 카드 선택은 전장 위 오버레이에서 진행하고, 선택 중 전투 입력은 잠근다.
- 수치값은 기준문서가 아니라 프리셋과 플레이테스트 기록에서 관리한다.
- AI 협업 문서는 특정 도구 강제가 아니라 팀원이 AI에게 일을 맡길 때의 공통 운영 원칙이다.

## 공유본에 보류로 표시할 내용

- 상대가 만든 일반 전투 사망에 제한적으로 카드를 지급할지.
- 카메라/경계 이탈 패배의 특수 보정 필요 여부.
- 대시, 2단점프, 점프 강화 같은 이동 액션 확장.
- 관전, 2v2, WebGL, 리더보드.
- 최종 게임 이름.
- 최종 승리 연출의 구체 소재.
- Host Mode 이후 Server Mode 전환 게이트.
- 카드 선택 요청 구현 방식의 세부안.

## 공유본 작성 금지

- 내부 문서의 frontmatter와 세션 운영 표현을 그대로 복사하지 않는다.
- 개인 PC 경로, 다운로드 경로, 로컬 작업 폴더명을 쓰지 않는다.
- App ID, secret, 토큰, 계정 정보를 쓰지 않는다.
- 후보 수치값을 확정값처럼 쓰지 않는다.
- `candidate` 문서를 팀 확정 기준처럼 표현하지 않는다.
- 구현 프로토타입의 임시 구조를 최종 규범으로 설명하지 않는다.

## 공유본 작성 후 검토 기준

공유본을 만든 뒤 다른 세션 또는 담당자에게 아래 기준으로 검토를 요청한다.

| 검토 항목 | 질문 |
|---|---|
| 맥락 복구 | 이 문서만 읽고 어떤 게임인지 이해되는가 |
| 확정/보류 구분 | 구현해도 되는 것과 아직 결정하지 않은 것이 구분되는가 |
| 로컬 정보 제거 | 개인 경로, 세션명, secret, 내부 산출물 경로가 없는가 |
| 기준 충돌 | 내부 accepted 문서와 다르게 설명한 곳이 없는가 |
| 구현 가능성 | 담당자가 다음 작업 브리핑를 만들 수 있을 만큼 구체적인가 |
