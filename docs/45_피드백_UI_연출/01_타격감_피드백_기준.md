# 타격감 피드백 기준

이 문서는 히트, 넉백, 사망, 구간 돌파, 카드 선택 같은 순간을 플레이어가 이해하고 감정적으로 받아들이게 만드는 피드백 기준이다.

히트스톱 시간, 카메라 흔들림 세기, 파티클 개수, 사운드 볼륨 같은 구체 수치는 이 문서에 고정하지 않는다. 실제 값은 feedback preset, VFX/SFX preset, `GameplayProfile` 또는 Unity 에셋 설정에서 관리한다.

## 목적

ddakbomb의 재미는 단순 승패가 아니라 “내가 밀었다”, “상대가 당황했다”, “반격 기회를 얻었다”는 감각에서 나온다. 피드백은 이 감각을 과장하되, 전투 판정을 흐리면 안 된다.

| 목적 | 의미 |
|---|---|
| 판정 이해 | 맞았는지, 밀렸는지, 죽었는지 즉시 읽히게 함 |
| 승리감 강화 | 돌파, 넉백, 반격 성공의 감정을 키움 |
| 억울함 감소 | 사망 원인과 위험 신호를 명확히 전달 |
| 네트워크 분리 | authoritative 결과와 local-only 연출을 혼동하지 않음 |
| 계약 소비 | 전투 사건 payload와 읽기 전용 상태를 소비해 피드백을 재생 |
| 에셋 활용 경계 | Feel/Corgi/MMFeedbacks는 presentation 중심으로 사용 |

## 피드백 계층

| 계층 | 역할 |
|---|---|
| 판정 피드백 | 피격, 넉백, 사망, 돌파처럼 게임 결과를 알림 |
| 위험 예고 | 탄착, 반사각, 경계 위험, 구조물 작동을 미리 알림 |
| 감정 연출 | 딱밤, 혹, 이모트, 승리감 표현 |
| 상태 UI | 체력, 탄약, 쿨타임, 선택 결과를 읽게 함 |
| 환경 반응 | 구조물, 벽, 바닥, 파편 같은 공간 반응 |

판정 피드백은 게임 결과 truth와 연결되고, 감정 연출은 가능하면 local-only presentation으로 분리한다.

## 핵심 순간별 기준

| 순간 | 피드백 기준 |
|---|---|
| 피격 | 누가 맞았고 어떤 방향에서 맞았는지 읽혀야 함 |
| 넉백 | 위치 손실과 벽 몰이 위험이 과장되어 보여야 함 |
| 반사탄 | 반사 경로와 피격 원인이 납득되어야 함 |
| 사망 | 사망 원인이 이해되어야 하며, 일반 사망은 즉시 카드 선택으로 오해되지 않아야 함 |
| 구간 돌파 | 단순 이동이 아니라 전선을 민 결과로 보여야 함 |
| 카드 선택 | 다음 전투 플랜이 바뀌었다는 기대를 만들어야 함 |

## 허용되는 연출

- 피격 방향을 강조하는 짧은 충격 연출.
- 넉백과 벽 몰이를 읽히게 하는 화면/캐릭터 반응.
- 반사탄 경로를 이해시키는 트레일 또는 충돌 표시.
- 구간 돌파 순간에는 확정된 `SegmentBoundaryAdvanced` 사건을 기준으로 전선이 밀린 위치에 짧은 sweep VFX와 local SFX one-shot을 재생한다.
- 딱밤, 혹, 이모트처럼 승리감을 강화하는 presentation형 연출.
- 서버 결과가 늦게 도착해도 로컬에서 의미를 잃지 않는 보조 연출.

## 금지되는 연출

- 실제 판정과 다른 결과를 암시하는 연출.
- 로컬 클라이언트마다 전투 결과가 달라 보이는 연출.
- 화면 흔들림이나 이펙트가 투사체/플레이어 가독성을 지우는 연출.
- 히트스톱 또는 슬로우가 입력 지연처럼 느껴지는 연출.
- 감정 표현이 전투 판정이나 네트워크 truth를 침범하는 구조.

## Corgi/Feel/MMFeedbacks 활용 경계

- presentation feedback, VFX, SFX, camera impulse, UI feedback에 우선 사용한다.
- 캐릭터 컨트롤러, 무기 시스템, Health/Damage 시스템을 그대로 가져와 핵심 구조를 대체하지 않는다.
- 게임 결과 truth는 `NetworkBehaviour`, `StateAuthority`, 도메인 규칙이 소유한다.
- 연출 preset은 수치 실험 대상이며 기준문서에 값을 고정하지 않는다.
- Feel 별도 구매 없이 Corgi에 포함된 MMFeedbacks를 우선 활용한다.

## VFX 에셋 스파이크 기준

- VFX 에셋은 즉시 확정하지 않고 후보 비교 스파이크를 거친다.
- 후보는 MMFeedbacks와 함께 재생 가능한지, ROUNDS식 미니멀 톤을 해치지 않는지, 전투 가독성을 해치지 않는지로 비교한다.
- 스파이크 결과는 에셋명보다 “어떤 순간의 피드백을 해결했는가”를 중심으로 기록한다.
- AD 역할자는 최종 비주얼 톤을 검수하되, 게임 결과 truth에는 관여하지 않는다.

## 카드 VFX 이벤트 계약 기준

카드 효과 VFX의 상세 계약 후보는 [03_카드_VFX_이벤트_계약.md](03_카드_VFX_이벤트_계약.md)를 참고한다. 본 문서는 타격감의 상위 원칙만 둔다.

- 카드 효과 VFX는 전투 결과를 보조하는 presentation 사건이다.
- 전투 truth는 `NetworkGameplay`/StateAuthority가 소유하고, VFX는 `Contracts`의 사건 payload 또는 동등한 읽기 전용 DTO를 소비한다.
- 카드 효과 발동, 투사체 충돌, 반사, 관통, 폭발, 상태이상 적용, 오버차지 같은 순간은 presentation이 이해할 수 있는 event로 노출할 수 있다.
- 구간 돌파는 `SegmentBoundaryAdvanced`/`segment_advance` 사건으로 노출하고, sweep VFX와 SFX one-shot은 전투 결과를 바꾸지 않는 presentation feedback으로 제한한다.
- Fusion rollback/resimulation 상황에서는 같은 사건의 VFX가 중복 재생되지 않도록 payload 식별자와 dedupe 기준을 둔다.
- 상태이상 tick마다 toast나 particle을 계속 생성하지 않고, 적용/종료 또는 낮은 빈도 표시로 제한한다.
- VFX 실패나 prefab 누락은 전투 진행, 라운드 전환, 카드 선택 후 전투 복귀를 막으면 안 된다.

## 구현 연결

- 전투 결과 이벤트와 피드백 이벤트를 분리한다.
- 피격, 사망, 돌파, 선택 완료는 관찰 로그와도 연결한다.
- local-only 연출은 authoritative 결과를 보조해야 하며 결과를 결정하면 안 된다.
- 표현 코드는 `Contracts`의 사건 payload 또는 Domain의 읽기 전용 상태를 소비한다.
- 피드백 profile은 어떤 사건 종류, 표면 타입, 카드 효과 태그, 대상 식별자에 반응하는지 명확해야 한다.
- particle prefab, sound clip, animator trigger, camera shake profile은 presentation 설정에서 선택하고, 전투 판정 로직이 직접 소유하지 않는다.
- 구간 돌파 sweep VFX는 `segment_advance` effect key, payload의 world position, `VfxFeedbackProfile.asset`의 duration/radius 값을 표현값으로 소비한다. SFX one-shot은 `SegmentAdvanceSfxPresentationManager`가 같은 event/effect key, dedupe key, world position을 기준으로 별도 처리하며, segment 전환 판정이나 카드 선택 흐름을 결정하지 않는다.
- SFX/오디오 표현 작업은 `05_팀_작업구조와_역할_소유권`과 `05_파일경로별_DRI`의 R/A를 따른다. 인게임 SFX와 오디오 표현은 우수연 책임이고, 빌드/플랫폼 오디오 출력 문제는 유민재 책임이다.
- 카드 효과 VFX와 VFX 한정 UI는 `03_카드_VFX_이벤트_계약.md`의 candidate 역할 경계를 참고한다. 광범위 UI/캐릭터/공통 비주얼 톤은 우수연, 카드 효과 VFX event/preset/toast/indicator 계약 후보는 김범승, map 디자인과 전장 구조는 박병준 범위로 라우팅한다.
- 딱밤, 혹, 이모트 같은 승리감 연출은 카드 효과가 아니라 기본 기믹 행동 또는 presentation 이벤트로 관리한다.
- 첫 playable slice에서는 피격, 넉백, 사망 원인, 구간 돌파 패배, 카드 선택 완료 피드백을 우선 검수한다.
