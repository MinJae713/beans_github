# UI HUD 정보구조

이 문서는 전투 중 HUD, 카드 선택 UI, 결과 표시가 어떤 정보를 어떤 우선순위로 보여줘야 하는지 정의한다.

UI 좌표, 폰트 크기, 색상값, 애니메이션 시간, 카드 선택 제한 시간 같은 구체 수치는 이 문서에 고정하지 않는다. 실제 값은 UI 프리셋, 디자인 시스템, Unity UI 설정, 플레이테스트 기록에서 관리한다.

## 목적

UI는 화려한 장식보다 전투 판단을 돕는 정보 구조가 먼저다. 플레이어는 체력, 탄약, 재장전/쿨타임, 카드 선택 결과, 구간 진행 상태를 빠르게 읽어야 한다.

| 목적 | 의미 |
|---|---|
| 전투 판단 보조 | 지금 쏠 수 있는지, 밀리는지, 죽을 위험인지 알려줌 |
| 선택 결과 이해 | 카드 선택이 다음 전투 플랜을 어떻게 바꿨는지 보여줌 |
| 구간 진행 표시 | 현재 전선과 최종 승리까지의 진행감을 전달 |
| 가독성 유지 | 이펙트가 많아져도 핵심 정보가 묻히지 않게 함 |
| 네트워크 상태 분리 | gameplay 상태와 접속/동기화 상태를 혼동하지 않게 함 |

## 전투 중 HUD 정보 우선순위

| 순위 | 정보 | 이유 |
|---|---|---|
| 1 | 생존/피격 상태 | 전투 지속 여부를 판단해야 함 |
| 2 | 발사 가능 상태 | 탄약, 재장전, 쿨타임 판단이 전투 리듬을 만듦 |
| 3 | 위치/경계 위험 | 구간 돌파와 카메라 압박의 핵심 정보 |
| 4 | 현재 무기/카드 효과 | 선택 결과를 전투 중 이해해야 함 |
| 5 | 매치/구간 진행 | 장기 목표와 전선 흐름을 보여줌 |

첫 playable slice에서는 모든 HUD를 완성하지 않아도 되지만, 발사 가능 상태와 사망/구간 돌파 패배/선택 흐름은 읽혀야 한다.

## 화면 배치 후보

회의 기준의 UI 정보 배치는 아래 후보를 우선 검토한다. 좌표와 크기는 확정하지 않는다.

| 위치 | 표시 정보 |
|---|---|
| 화면 상단 | 전체 구간 진행도, 현재 구간, 현재 viewport 범위 |
| 화면 상단 좌/우 | 이동 주도권 방향 필수 표시. 예: `=> GO` 또는 `GO <=` |
| 캐릭터 머리 위 | 체력바, 피격/상태 이상의 짧은 표시 |
| 화면 하단 좌/우 | 각 플레이어에게 적용된 카드 요약 |
| 무기 주변 또는 하단 | 장전 중 원형 진행 표시, 발사 가능 상태 |
| 카드 선택 화면 | 카드 정보, 등급, 탄환 변화, 배타/중복 제한 설명 |

전투 중에는 총을 쏠 때마다 총알 개수를 계속 크게 보여주기보다, 장전 중인지와 발사 가능한지를 읽히게 하는 쪽을 우선한다.

## VFX 한정 UI와 기본 HUD 경계

카드 효과 VFX 한정 UI는 기본 HUD를 대체하지 않는다. 상세 계약 후보는 [03_카드_VFX_이벤트_계약.md](03_카드_VFX_이벤트_계약.md)를 참고한다.

| 구분 | 담당 범위 | 기준 |
|---|---|---|
| 기본 HUD | 체력, 탄약, 장전, 라운드, 구간 진행, 카드 선택 화면의 지속 정보 | 우수연 UI/HUD 범위. 플레이어가 계속 읽어야 하는 정보 |
| VFX 한정 UI 후보 | 카드 적용 toast, 상태이상 적용/종료 marker, 오버차지 순간 indicator, 폭발/반사/관통 순간 marker | A303-298 후보 범위에서는 김범승으로 라우팅. 짧게 나타났다 사라지는 효과 설명 |
| 전장/map 표시 | 전장 구조, map 디자인, 카메라/구간 기준과 연결된 표시 | 박병준 map/카메라 범위 |

VFX 한정 UI는 `Contracts`의 사건 payload 또는 presentation event를 소비할 수 있지만, 전투 수치나 카드 효과를 직접 계산하지 않는다. 상태이상 `StatusTick`처럼 반복 발생하는 사건은 HUD noise를 만들지 않도록 적용/종료 중심으로 표시한다.

## HUD 수치 출처 (GameplayProfile.combat.baseline)

HUD가 보여주는 전투 수치는 하드코딩하지 않고 `GameplayProfile.combat.baseline`을 기준으로 읽는다.

| HUD 항목 | baseline 기준 필드 | 런타임 표시값 예시 |
|---|---|---|
| 체력바 최대치 | `baseline.maxHealth` | `PlayerHealth.MaxHealth` |
| 탄약 최대치 | `baseline.ammoCapacity` | `Gun.CurrentAmmo / Gun.MagazineCapacity` |
| 장전 기준시간 | `baseline.reloadTime` | `Gun.ReloadDuration`, `Gun.ReloadProgress` |
| 리스폰 무적 표시 | `baseline.respawnInvulnerableSeconds` | 리스폰 직후 무적 남은 시간 UI |
| 카드 적용 후 이동/점프 체감 설명 | `baseline.moveSpeed`, `baseline.jumpForce` | 카드 요약 UI에서 증감 방향 표시 |

## 카드 선택 UI 기준

카드 선택 UI의 네트워크 핸드셰이크·드로우 로직 정본은 [40/30/01](../40_카드_무기_설계/30_구현가이드/01_카드_선택_네트워크_핸드셰이크.md). 본 문서는 **HUD 배치·정보구조**(화면상 위치·크기·가독성·전환 연출) 관점만 다룬다.

- 카드 UI는 ROUNDS식 외형 복제가 아니라 반격 플랜 선택을 설명해야 한다.
- 카드 설명은 수치보다 전투 양상 변화 중심으로 적는다.
- 카드 설명은 “총알이 어떻게 바뀌는가”를 먼저 보여준다.
- 에픽/레전더리 카드는 등급과 보유 제한, 배타 관계를 읽을 수 있어야 한다.
- 탄환 변화형과 발사 리듬형 또는 이동/액션 확장형을 같은 풀에 섞는 경우는 별도 검증 후 허용한다.
- 선택 결과는 다음 구간 시작 전에 명확히 확인되어야 한다.
- 선택하지 못한 경우에는 시간 만료 후 제시된 후보 중 랜덤 자동 선택으로 확정한다.
- 랜덤 자동 선택 결과도 플레이어가 직접 선택한 결과와 같은 방식으로 확인되어야 한다.

### Figma 기반 카드 선택 화면 적용 기준

A303-272 이후 카드 선택 화면의 시각 방향은 `45/00 디자인 참조 SOT`에 등록된 Figma 카드 선택 화면을 따른다. 단, Figma는 시각 기준이며 카드 제안/확정 규칙은 상태머신과 카드 네트워크 핸드셰이크 문서가 우선한다.

| 항목 | 기준 |
|---|---|
| 제시 구조 | MVP 기준 3장 카드 제시 |
| 화면 톤 | dark tactical HUD, neon accent, 카드 중심 레이아웃 |
| 선택 상태 | 선택 카드 border/glow/badge로 명확히 표시 |
| 희귀도 | Common/Rare/Epic/Legendary를 배지와 색상으로 구분 |
| 타이머 | "리스폰까지 N초" 또는 동등 문구로 ChoicePending 남은 시간 표시 |
| 확정 | 선택 후 confirm affordance를 보여주되 StateAuthority 확정 전제를 흐리지 않음 |
| 데이터 출처 | 카드명, 설명, 희귀도, 내부 일러스트는 `CardData` 계열 데이터에서 읽음 |
| 금지 | UI가 전투 수치나 카드 효과를 자체 계산하거나 전투 컴포넌트를 직접 변경 |

A303-350 기준 카드 선택 UI는 희귀도별 카드 프레임 4종과 카드별 내부 일러스트를 분리 조립한다. MVP16의 기존 `CardData.cardIcon` 직렬화 참조는 데이터 호환성을 유지하기 위해 그대로 두되, 카드 선택 화면에서는 내부 일러스트 레이어로 소비한다. `Assets/_Project/Sprites/CardFrames/MVP16/`의 1024x1536 프레임 sprite는 카드 외관 레이어, `Assets/_Project/Sprites/CardIcons/MVP16/`의 1:1 generated illustration candidate는 내부 일러스트 레이어로만 취급한다. 현재 Unity 카드 rect는 270x360, 내부 일러스트 슬롯은 150x130이며 preserve aspect 기준으로 1:1 후보가 130x130에 가깝게 보이도록 둔다. 두 sprite 그룹 모두 실제 상업용 리소스가 확정되기 전까지 정보 식별용 시각 자료이며, 카드 효과의 truth나 밸런스 수치로 해석하지 않는다.

A303-350 후속 시각 검수 기준으로 카드 선택 화면의 3장 카드는 모두 정방향으로 세운다. 카드 등급은 좌측 상단 배지에, 카드명은 하단 내부 프레임 상단의 중앙 정렬 박스에, 설명은 하단 큰 내부 프레임 안의 설명 박스에 표시한다. 텍스트 박스는 위치/레이아웃만 담당하고 배경과 외곽선은 투명하게 두며, 등급/카드명/설명 글자는 흰색으로 표시해 카드 프레임 위에서 읽히게 한다. 선택 가능한 카드의 하단에는 "READY TO ENGAGE" 같은 별도 상태 문구를 표시하지 않고, 선택 확정/빈 슬롯처럼 상태 구분이 필요한 경우에만 짧은 상태 문구를 쓴다. 이 텍스트들은 `CardData.rarity`, `CardData.cardName`, `CardData.description`을 읽기 위한 presentation 레이어이며 카드 효과나 전투 수치를 자체 계산하지 않는다.

Figma 예시에는 시각 설명을 위해 MVP16 밖의 무기명이나 카드명이 포함될 수 있다. 구현, MR 본문, QA 캡처에서는 실제 제안 풀과 혼동되지 않도록 MVP16 카드명과 `CardData` 기준 설명을 사용한다.

### 카드 선택 deadline 표현 (Q42 D46)

카드 선택 타임아웃은 **2-deadline 구조**로 표현한다. 필드 정본과 tick 계산식은 [40/30/01 §선택 deadline 정책](../40_카드_무기_설계/30_구현가이드/01_카드_선택_네트워크_핸드셰이크.md) 참조.

- **플레이어 카운트다운**: `visibleChoiceDuration`(기준값 10s) 동안 남은 시간을 시각적으로 표시한다. 0초 시점에 UI는 카운트다운 표시를 멈추고 "확정 중" 상태로 전환한다.
- **"확정 중" 잠금 상태**: `visibleChoiceDuration` 만료 후 `serverAcceptPadding`(기준값 0.3s, RTT 흡수 버퍼) 구간에는 UI가 카드 버튼을 비활성화하고 "확정 중"(또는 동등한 짧은 상태 텍스트)을 표시한다. 플레이어 재선택·취소 입력을 받지 않는다.
- **선택 로컬 이펙트**: 플레이어가 카드 버튼을 누른 즉시 로컬 이펙트(선택 강조·사운드·버튼 확정 연출)를 재생한다. Host 결과 수신까지 대기하지 않으며, Host reject 시 로컬 이펙트를 롤백하고 재선택 UI를 제시한다. 정본 정의는 [`40/30/01 §선택 이펙트 타이밍`](../40_카드_무기_설계/30_구현가이드/01_카드_선택_네트워크_핸드셰이크.md).
- **race 처리 피드백**: `hardDeadline` 내부에서 플레이어 선택과 서버 랜덤 선택이 동시에 도착한 경우 **플레이어 선택이 우선**으로 확정된다. UI는 race 사실을 별도로 표시하지 않고 플레이어 선택 결과만 "카드 선택 완료"로 보여준다.
- **타임아웃 확정 결과**: `hardDeadline` 초과 시 서버가 `Networked seed` 기반으로 랜덤 자동 선택을 확정하며, 랜덤 자동 선택 결과도 플레이어가 직접 선택한 결과와 동일한 확인 흐름으로 표시한다.
- **구체 시간값**: `visibleChoiceDuration`, `serverAcceptPadding`의 최종 수치는 `85/20/02 MVP 카드 가중치 프리셋` 스키마에서 관리한다. 본 문서는 의도만 적는다.

## 결과 표시 기준

| 결과 | 표시 기준 |
|---|---|
| 사망 | 사망 원인을 표시하되, 일반 사망이 곧 카드 선택권이라는 오해를 만들지 않음 |
| 구간 돌파 | 어느 방향으로 전선이 밀렸는지 표시 |
| 매치 최종 승리 | 단일 라운드 승리와 명확히 다르게 표시 |
| 카드 선택 완료 | 다음 전투에서 바뀐 플랜을 짧게 확인 |
| 네트워크 문제 | 게임 규칙 결과와 분리된 시스템 메시지로 표시 |

## 정보 과부하 방지

- 전투 중에는 설명문보다 아이콘, 색, 짧은 상태 표시를 우선한다.
- 카드 선택 화면에서는 전투 중보다 더 많은 설명을 허용한다.
- 모든 카드 효과를 HUD에 항상 펼쳐 보이지 않는다.
- presentation형 승리감 연출은 전투 핵심 정보를 가리면 안 된다.
- 네트워크 상태나 디버그 정보는 플레이어 HUD와 분리한다.

## 구현 연결

- HUD는 authoritative 상태를 읽되, 가능하면 presentation 레이어에서 표현한다.
- 카드 선택 UI는 카드 데이터의 태그와 설명 필드를 재사용하는 것이 좋다.
- 관찰 로그에는 플레이어가 선택한 카드/무기와 결과 흐름을 연결할 수 있어야 한다.
- UI 실험은 디자인 수치보다 정보 우선순위가 맞는지 먼저 검수한다.
