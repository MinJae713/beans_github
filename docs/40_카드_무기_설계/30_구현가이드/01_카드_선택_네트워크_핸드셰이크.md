# 카드 선택 네트워크 핸드셰이크

> 상태: accepted_candidate. 이 문서는 카드 선택의 요청, StateAuthority 검증, Networked 결과 확정, UI 표시 책임 분리와 ChoicePending 입력 잠금에 한해 임시 구현 기준으로 사용한다. 구체 API/RPC 세부는 작업 브리핑에서 잠근다.

이 문서는 카드 선택이 UI 클릭으로 바로 적용되지 않고, 네트워크 검증을 거쳐 확정되는 흐름을 정의한다.

카드 제시는 3장을 기본으로 한다. 카드 선택 제한 시간, 카드별 수치, 희귀도 가중치의 정확한 값은 이 문서에 고정하지 않고 카드 프리셋, `BalanceProfile`, 플레이테스트 기록에서 관리한다.

## 핵심 원칙

| 원칙 | 의미 |
|---|---|
| 요청과 확정 분리 | 클라이언트는 선택 의도를 보내고 StateAuthority가 확정 |
| ChoicePending 전용 | 카드 선택은 전투 상태와 분리된 라운드 상태에서만 처리 |
| 전투 입력 잠금 | 선택 중 이동/발사/재장전 입력은 결과 상태에 반영하지 않음 |
| 검증 가능성 | 제시 카드, 선택권자, 선택 인덱스, 보유 제한을 검증 |
| 로그 연결 | 선택 요청/확정/거절은 관찰 로그와 연결 |

## 권장 흐름

| 단계 | 주체 | 처리 |
|---|---|---|
| 1. 선택권 확정 | StateAuthority | MVP 기준 구간 돌파 패배 결과로 선택권자를 정함 |
| 2. 후보 생성 | StateAuthority | 현재 카드 풀과 제한 규칙으로 후보를 만듦 |
| 3. UI 표시 | Local presentation | 후보를 읽어 전장 위 반투명 정지 오버레이로 선택 UI를 표시 |
| 4. 선택 요청 | InputAuthority | 선택 인덱스 또는 카드 id를 요청으로 제출 |
| 5. 요청 검증 | StateAuthority | 상태, 선택권자, 후보 목록, 제한 규칙을 검증 |
| 6. 선택 확정 | StateAuthority | 카드 효과 상태를 반영하고 ChoicePending을 종료 |
| 7. 리스폰 전이 | StateAuthority | RespawnResolving 또는 SegmentSetup으로 넘김 |
| 8. 피드백 표시 | Local presentation | 선택 완료, 다음 전투 변경점을 표시 |

현재 프로토타입처럼 UI가 로컬에서 카드 적용 함수를 직접 호출하는 방식은 임시 브리지로 볼 수 있다. 기준 구현에서는 UI가 결과를 소유하지 않는다.

카드 선택 오버레이가 열린 동안에는 `ChoicePending` 상태가 전투 입력을 잠근다. 오버레이는 전장을 배경으로 유지하되, 이동/조준/발사/재장전/기믹 행동 입력은 authoritative 결과에 반영하지 않는다.

## MVP 요청 방식 기본안

MVP 기본안은 `InputAuthority`가 선택 의도를 one-shot request로 보내고, `StateAuthority`가 검증한 뒤 Networked 선택 결과와 카드 효과 상태를 확정하는 방식이다.

구현 API 이름은 현재 코드 구조에 맞춰 정할 수 있지만, 아래 책임은 바꾸지 않는다.

| 책임 | 기준 |
|---|---|
| 요청 | 선택권자의 입력에서 한 번만 발생하는 카드 선택 의도 |
| 검증 | `StateAuthority`가 상태, 선택권자, 후보 목록, 제한 규칙을 확인 |
| 확정 | Networked 상태 또는 동등한 authoritative 상태에 선택 결과 반영 |
| 표시 | UI는 확정된 결과를 읽어 표현. UI가 카드 효과를 직접 소유하지 않음 |

RPC는 이 흐름을 구현하는 기본 후보로 본다. Networked request state 또는 하이브리드 방식은 현재 코드 구조나 테스트 편의상 필요할 때 작업 브리핑에 이유를 적고 사용한다.

`INetworkInput`에는 카드 상세 데이터 전체를 매 tick 싣지 않는다. 카드 선택은 `ChoicePending` 상태의 one-shot request로 분리하고, 일반 전투 입력과 같은 슬롯에서 계속 흘러가지 않게 한다.

## 검증해야 하는 조건

| 조건 | 검증 이유 |
|---|---|
| 현재 상태가 ChoicePending인가 | 전투 중 카드 변경 방지 |
| 요청자가 선택권자인가 | 상대 카드 조작 방지 |
| 선택 카드가 제시 후보 안에 있는가 | 임의 카드 주입 방지 |
| 이미 최대 보유/최대 스택인가 | 누적 폭주 방지 |
| 배타 태그와 충돌하지 않는가 | 상성/희귀 카드 충돌 방지 |
| 최종 구간 종료 상태가 아닌가 | 매치 종료 후 선택 방지 |

같은 제시 내 중복 카드, 이미 maxed인 카드, 티어 제한을 초과하는 카드는 후보에서 제외한다. 희귀도 가중치의 정확한 값은 프리셋에서 관리한다.

## 실패 처리

| 실패 유형 | 처리 |
|---|---|
| 상태 불일치 | 요청 거절, UI는 현재 authoritative 상태를 다시 표시 |
| 권한 불일치 | 요청 거절, 보안/디버그 로그 후보 |
| 후보 불일치 | 요청 거절, 후보 재동기화 |
| 제한 규칙 충돌 | 요청 거절 또는 대체 후보 제시 |
| 시간 만료 | 제시된 후보 중 StateAuthority가 랜덤 자동 선택 |

시간 만료 시 랜덤 자동 선택은 선택권자가 고르지 않았을 때만 사용한다. 랜덤 대상은 실제로 제시된 후보 목록으로 제한하며, 후보 생성 때 이미 중복, maxed, 티어 제한 초과 카드는 제외되어 있어야 한다. 선택 제한 시간과 랜덤 seed/가중치의 구체값은 이 문서에 고정하지 않고 프리셋 또는 구현 정책에서 관리한다.

## 상태머신 연결

카드 선택은 라운드 상태머신과 아래처럼 연결한다.

```text
BreakthroughResolving
-> ChoicePending
-> RespawnResolving
-> SegmentSetup
```

일반 사망은 MVP 기준 `ChoicePending`으로 들어가지 않는다. 최종 구간 진입 또는 최종 승리가 확정된 경우에도 `ChoicePending`으로 들어가지 않는다.

## 구현 브리핑 체크

| no | 확인 항목 |
|---|---|
| 1 | 카드 선택 요청 경로가 UI 직접 적용이 아닌가 |
| 2 | StateAuthority 검증 조건이 명시되어 있는가 |
| 3 | ChoicePending 중 전투 입력 잠금 위치가 명시되어 있는가 |
| 4 | 선택 확정 후 어떤 Networked 상태가 바뀌는지 적혀 있는가 |
| 5 | 실패/거절 시 UI fallback이 있는가 |
| 6 | 선택 이벤트가 관찰 로그와 연결되는가 |

## 금지

- Host 클라이언트의 UI 클릭만으로 카드 효과를 확정하는 것.
- 카드 선택 결과를 local-only UI 상태로만 저장하는 것.
- `INetworkInput`에 카드 상세 데이터 전체를 매 tick 싣는 것.
- 선택 중 전투 입력이 계속 결과 상태를 바꾸게 두는 것.
- 선택 시간, 희귀도 확률, 카드 수치값을 기준문서에 최종값처럼 고정하는 것.

## 구현 유연성

- 구체 API 이름과 클래스 배치는 현재 코드 구조에 맞출 수 있다.
- 단, 요청-검증-확정-표시 책임 분리는 유지한다.
- Host Mode 임시 브리지는 허용하더라도 Server Mode 전환을 막는 Host-only shortcut은 기준 구현으로 남기지 않는다.
