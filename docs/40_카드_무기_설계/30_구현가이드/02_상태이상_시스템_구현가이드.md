# 상태이상 시스템 구현 가이드

> 문서 상태: candidate (2026-05-02 A303-261 도입)
> 대상: 새 상태이상 카드를 추가하는 작업자 (주로 김범승 R, Card System).
> binding 범위: 새 상태이상 효과를 시스템에 등록하고 카드와 wiring하는 절차.
> 시스템 자체 구조는 [50_기술_구조_기준/06_Status_Effect_시스템.md](../../50_기술_구조_기준/06_Status_Effect_시스템.md) 참조.

## 0. 한 줄 요약

새 상태이상 카드 추가 = **`StatusEffectDefinition` 상속한 SO 클래스 1개 작성 → .asset 인스턴스 생성 → 카드.asset에 드래그**. PlayerHealth / PlayerController / BulletController 코드 수정 0건.

## 1. 새 상태이상 추가 절차 (5단계)

### Step 1. SO 클래스 작성

`unity/Assets/_Project/Scripts/Status/Effects/{NewEffect}.cs` 생성.

```csharp
using UnityEngine;
using Colosseum.Player;

namespace Colosseum.Status.Effects
{
    [CreateAssetMenu(fileName = "NewEffect", menuName = "Colosseum/Status Effect/NewEffect")]
    public class NewEffect : StatusEffectDefinition
    {
        // 효과 전용 수치는 SerializeField로 노출
        [SerializeField] private float _customValue = 1f;

        public override void OnApply(PlayerStatusController target, ref StatusEffectInstance instance)
        {
            // 적용 직후 1회. modifier 등록·시각 변경 등 즉시 반영.
        }

        public override void OnTick(PlayerStatusController target, ref StatusEffectInstance instance)
        {
            // tickInterval 마다 호출. DoT 데미지 발행 등.
        }

        public override void OnExpire(PlayerStatusController target, ref StatusEffectInstance instance)
        {
            // 만료 시 1회. modifier 복원·시각 원복.
        }
    }
}
```

### Step 2. 선택적 인터페이스 구현

효과 성격에 따라 인터페이스 추가 구현 (한 클래스에서 복수 구현 가능):

| 인터페이스 | 의미 | 사용 예 |
|---|---|---|
| `IMovementModifierEffect` | 이동 속도 modifier 노출 | Frost (둔화), Charge Up (가속) |
| `IStunEffect` | 입력 잠금 (수평 이동·점프 무시) | Electric (감전) |
| `IVisualTintEffect` | 캐릭터 색 tint 노출 | 모든 효과 (선택) |

### Step 3. .asset 인스턴스 생성

Unity Editor:
1. `Assets/_Project/Data/StatusEffects/` 폴더 우클릭 → Create → Colosseum → Status Effect → NewEffect
2. Inspector에 노출된 필드 입력:
   - `effectKey` — 영문 소문자 식별자 (예: `bleed`, `slow`). 다른 효과와 중복 금지.
   - `baseDuration` — 전체 지속 시간 (초)
   - `tickInterval` — DoT 주기 (초). 0이면 OnTick 호출 안 함.
   - `isStackable` / `maxStack` — 스택 정책
   - `visualTint` — 캐릭터 색 tint (Color) — 비주얼팀과 협의

### Step 4. 카드와 wiring

#### 옵션 A — Inspector에서 PlayerStatusController 4 슬롯에 직접 드래그 (현재 구조)

`Assets/_Project/Resources/Player.prefab` 또는 PlayerStatusController가 부착된 prefab을 열고, Inspector의 4 슬롯(`_freeze` / `_burn` / `_poison` / `_electric`) 중 매핑할 enum에 SO를 드래그한다. 기존 enum 4종 외 새 효과는 옵션 B 사용.

#### 옵션 B — CardData에 statusEffectDef 필드 추가 후 SO 직접 참조 (확장 구조, 후속 작업)

`CardData.cs` 에 `public StatusEffectDefinition statusEffectDef;` 필드 추가 + Card.asset에서 SO 직접 참조. 본 인프라는 옵션 B를 지원할 준비가 되어 있으나 카드 .asset wiring은 김범승이 결정.

### Step 5. 검증

DevMode 디버그 트리거(`Scripts/Status/StatusEffectDevTrigger.cs`)에 새 키 매핑 추가하거나, 카드 wiring 후 실제 매치에서 카드 따서 효과 발동 확인.

## 2. 효과 패턴 4종 (참고용)

본 MVP 4종이 인프라의 첫 사용자이며, 새 효과를 만들 때 가장 가까운 패턴을 참고하면 된다.

### Pattern A — DoT (Damage over Time)

`BurnEffect` / `PoisonEffect` 참고.

- `tickInterval > 0` 설정
- `OnTick`에서 `target.GetComponent<PlayerHealth>().TakeDamage(damage, instance.Source, BulletController.StatusEffect.None)` 호출
- `status` 인자는 반드시 `None` — 재귀 적용 방지 (Burn이 또 Burn을 적용하지 않게)

### Pattern B — Movement Modifier

`FrostEffect` 참고.

- `IMovementModifierEffect` 구현
- `GetMoveSpeedMultiplier` / `GetAirControlMultiplier` 에서 Multiplier 반환 (1f = 영향 없음, 0.5f = 절반)
- `tickInterval = 0` (주기 동작 없음)
- PlayerMovement.ApplyMovement가 매 tick 자동 곱연산

### Pattern C — Stack + Stun

`ElectricEffect` 참고.

- `isStackable = true`, `maxStack = N`
- `IStunEffect` 구현
- `IsStunningNow(instance)` 에서 `instance.Stacks >= _threshold` 검사
- 임계 도달 시 baseDuration 동안 입력 잠금 유지

### Pattern D — Buff (양수 효과, 자기 적용)

본 MVP 외. 새 카드 추가 시 같은 시스템으로 buff도 가능. `IMovementModifierEffect.GetMoveSpeedMultiplier` 에서 1.5f 같은 양수 배율 반환하면 가속 효과.

## 3. 정책 결정 사항 (사전 합의 필요)

새 효과 추가 전 김범승 본인이 다음 정책을 결정 후 SO 인스턴스에 반영:

| 정책 | 영향 |
|---|---|
| 지속 시간 (baseDuration) | UX. 너무 짧으면 카드 가치 없음, 너무 길면 게임 흐름 막힘 |
| 강도 (damagePerTick / multiplier) | 카드 평균 가치. `85_밸런스_프리셋` 와 연동 |
| 스택 정책 (isStackable / maxStack) | 카드 누적 효과. 같은 카드 두 번 따면 효과가 누적되는가? |
| 같은 키 재적용 시 동작 | 스택형 = `Stacks +1` + Timer 갱신 / 비스택형 = Timer만 갱신 (refresh) |
| 사망 시 cleanup | 즉시 active 효과 모두 제거 — 후속 결정 사안 |

## 4. 가드레일 (필수 준수)

근거: [50_기술_구조_기준/04_Fusion_구현_가드레일.md](../../50_기술_구조_기준/04_Fusion_구현_가드레일.md)

- ❌ `OnApply` / `OnTick` / `OnExpire` 안에서 `Time.deltaTime` 금지. `instance.Timer` / `Runner` / `TickTimer` 사용.
- ❌ `OnTick` 안에서 BulletController.StatusEffect.None 외 status 인자 전달 금지 (재귀 적용 방지).
- ❌ Definition가 PlayerHealth 등 외부 컴포넌트에 `+=` 이벤트 직접 구독 금지. PlayerStatusController가 hook 호출로만 매개.
- ✅ `target.GetComponent<...>()` 1회 캐시 OK. 매 tick 다시 GetComponent 호출 비효율.
