# 첫 Playable Slice 검증 패킷

이 문서는 첫 playable slice에서 무엇을 넣고, 무엇을 빼고, 무엇을 관찰할지 정의한다.

정확한 체력, 피해량, 탄속, 재장전, 이동 속도, 구간 크기, 리스폰 위치 같은 수치는 이 문서에 고정하지 않는다. 해당 값은 `GameplayProfile`, 무기/카드 프리셋, 구간 프리셋에서 관리한다.

## 목적

첫 playable slice의 목적은 재미있는 전체 게임을 한 번에 만드는 것이 아니라, ddakbomb의 핵심 루프가 네트워크 구조와 전투 설계 위에서 깨지지 않는지 확인하는 것이다.

| 검증 목적 | 의미 |
|---|---|
| 핵심 루프 확인 | 이동, 공격, 피격, 사망, 선택, 리스폰, 재교전이 이어지는가 |
| 위치 킬각 확인 | 체력 삭제뿐 아니라 벽 몰이와 위치 손실이 의미 있는가 |
| 카드 차별 확인 | 선택 이후 다음 전투 양상이 실제로 달라지는가 |
| 계약/표현 확인 | 판정 사건이 Contracts로 관찰 가능하고 Presentation이 이를 소비해 피드백을 보여주는가 |
| 네트워크 경계 확인 | 입력/이동 결과가 Fusion 권위 구조와 충돌하지 않는가 |
| 확장 기준 확보 | 이후 무기/구간/구조물을 추가할 비교 기준이 생기는가 |

## 1차 포함 범위

첫 playable slice는 아래 범위만 우선 포함한다.

| 영역 | 1차 포함 범위 |
|---|---|
| 구간 패턴 | 기본 결투 구간 |
| 전투 압박 | 정면 교전, 재장전 빈틈, 짧은 엄폐, 위치 손실 |
| 탄환 후보 | 후보 수를 고정하지 않고 탄환 성질 중심으로 등록 |
| 카드 풀 | 탄환 성질 중심. 발사 리듬 후보도 허용하되 이동/액션 확장 카드는 분리 |
| 카드 효과 분류 | 투사체 변형, 위치 압박 강화, 발사 리듬 변경 관찰 |
| 계약/표현 연동 | 발사/피격/반사/사망/카드 선택 사건의 payload와 feedback 연결 관찰 |
| 구조물 | static Collider2D 기본, 이후 낙사/추 중 하나를 소규모 검증 |
| 네트워크 검증 | 입력/이동 우선, 발사/피격/사망은 다음 단계 전환 준비 |

후보 수는 제한하지 않는다. 대신 첫 playable slice의 검증 목적은 카드 개수를 많이 보여주는 것이 아니라, 카드 적용 파이프라인과 전투 양상 변화가 관찰 가능한지 확인하는 것이다.

## 1차 제외 범위

| 제외 항목 | 제외 이유 |
|---|---|
| 이동기 카드 | 구간/카메라/경계 규칙을 흔들 수 있어 별도 트랙으로 둠 |
| 압사 장치 | 사망 원인 로그와 사전 신호 기준이 준비된 뒤 P2로 추가 |
| 이동 발판 | kinematic/NetworkObject 동기화 기준이 준비된 뒤 추가 |
| 승리감 연출 | 카드 효과 후보로 두지 않음. 딱밤/혹/이모트는 별도 기믹 또는 presentation 트랙에서 검증 |

제외는 폐기가 아니다. 첫 slice에서 원인 분리를 위해 뒤로 미루는 것이다.

## 구간 선택 기준

첫 구간은 `구간 패턴 카탈로그`의 기본 결투 구간을 사용한다.

- 기본 결투형만으로도 이동, 공격, 피격, 사망, 리스폰이 성립해야 한다.
- 넉백 산탄은 같은 구간 안에서 벽 몰이와 위치 손실이 보이는지 검증한다.
- 반사탄은 같은 구간 안에서 엄폐와 각도 싸움이 보이는지 검증한다.
> 반사탄 스키마는 [50/02](../50_기술_구조_기준/02_네트워크_truth_표.md) 정본 (Option A 채택, 2026-04-20). 검증 대상은 ReflectCount·ReflectOwner·ReflectVelocityMult·MaxReflectDepth·ReflectLayerMask의 네트워크 동기화 상태.
- 구간 자체가 특정 무기 하나를 답으로 만들면 안 된다.
- 구조물은 전투 양상 확인을 보조해야 하며, 구조물이 주인공이 되면 안 된다.

## 카드 풀 선택 기준

첫 playable slice에서는 총기 교체형 카드가 아니라 탄환 성질 변화를 우선 검증한다. 후보 개수는 제한하지 않지만, 이동/액션 확장 카드는 같은 선택 풀에 섞지 않는다.

| 풀 | 1차 기준 |
|---|---|
| 탄환 변화형 | 기본탄, 충격/넉백탄, 반사탄, 곡사탄 등 전투 양상 후보. 저격탄 운용은 TTK 단축 리스크가 커 1차 slice 필수 풀로 강제하지 않는다. |
| 발사 리듬형 | 장전/탄수/연사 리듬 후보를 허용하되 과도한 TTK 붕괴 여부를 따로 관찰 |
| 승리감/감정 표현 | 카드 풀에서 제외하고 별도 기믹/presentation 트랙으로 검증 |
| 이동/액션 확장 | 별도 액션성 확장 트랙으로 보류 |

이렇게 분리하는 이유는 첫 테스트에서 "총알 성질이 달라져서 양상이 바뀐 것인지", "이동 액션이 바뀐 것인지"를 분리하기 위해서다.

## 통과 관찰

첫 playable slice는 아래 질문에 답할 수 있어야 한다.

| no | 관찰 질문 |
|---|---|
| 1 | 기본 결투형만으로도 최소 전투가 성립하는가? |
| 2 | 넉백 산탄이 체력 삭제보다 위치 압박을 만들어내는가? |
| 3 | 반사탄이 단순 피해량이 아니라 각도 싸움을 만드는가? |
| 4 | 선택 후 다음 전투에서 플레이어의 위치 판단이 바뀌는가? |
| 5 | 사망/돌파/선택/리스폰 흐름이 끊기지 않는가? |
| 6 | 결과 원인이 직접 피격, 위치 이탈, 표현 부족 중 무엇인지 구분되는가? |
| 7 | 발사/피격/반사/사망/선택 완료 사건이 표현 레이어에서 소비 가능한 데이터로 남는가? |
| 8 | VFX/SFX/HUD/카메라 피드백이 판정 결과를 보조하되 게임 결과를 바꾸지 않는가? |

위 질문에 답하지 못하면 후보 개수를 이유로만 판단하지 않는다. 먼저 로그, 피드백, 프리셋, 구간 구조 중 어느 문제가 원인인지 분리한다.

## QA R/A 기록

첫 playable slice 통과 판단은 QA 실행과 최종 승인을 분리한다.

| 항목 | 책임 | 남길 증빙 |
|---|---|---|
| Gate 실행 | 김범승(R) | 실행 빌드/커밋, 통과 관찰 1~8 결과, 실패 원인 분류, 후속 이슈 |
| 최종 승인 | 유민재(A) | 빌드/실행 환경 확인, 최종 승인 여부, 승인 보류 시 BLOCKED 사유 |
| 문서 정리 | 박병준(S) | 플레이테스트 리포트와 기준문서 반영 필요 항목 |

## 실패 신호

| 실패 신호 | 우선 조치 |
|---|---|
| 기본 결투가 재미없음 | 카드 후보를 늘리기 전에 이동/피격/재장전 체감을 확인 |
| 넉백이 확정 사망임 | 구간 경계, 리스폰, 넉백 피드백, 회피 창구를 분리 점검 |
| 반사탄이 억울함 | 반사각 가독성, 사전 신호, 피격 로그를 먼저 확인 |
| 카드 선택 후 일방 승리 | 후보 풀 분리, 누적 제한, 구간 편향을 확인 |
| 원인 분리가 안 됨 | 후보 태그, 관찰 로그, 테스트 묶음을 먼저 보강 |
| 표현은 보이나 원인 로그가 없음 | Contracts payload 또는 관찰 로그를 먼저 보강 |
| 이펙트가 결과처럼 보임 | Presentation이 판정 결과를 암시만 하는지, 실제 결과를 바꾸는지 분리 점검 |

## Contracts/Presentation 검증 기준

첫 playable slice에서 모든 VFX/SFX를 완성할 필요는 없다. 다만 아래 수준의 연결은 확인해야 다음 작업으로 확장할 수 있다.

| 항목 | 1차 통과 기준 |
|---|---|
| 발사 | 발사 주체, 투사체 식별자, 적용 카드 태그 또는 snapshot을 로그나 디버그 표시로 확인 가능 |
| 피격 | 맞은 대상, 위치, 방향, 피해/넉백 결과, 사망 여부를 원인 분류에 사용할 수 있음 |
| 반사 | 반사 위치, normal, 반사 후 방향, 남은 반사 횟수 또는 반사 가능 여부를 확인 가능 |
| 사망/리스폰 | 사망 원인과 리스폰 전이가 구분되고, 표현이 일반 사망과 카드 선택을 혼동시키지 않음 |
| 카드 선택 완료 | 선택권자, 선택 카드, 적용 결과가 UI 표시와 전투 상태에 같은 의미로 반영됨 |

Presentation 검증은 완성도 평가가 아니라 경계 확인이다. placeholder 이펙트라도 판정 사건을 소비해 재생된다면 통과 가능하다. 반대로 예쁜 이펙트가 있어도 체력, 탄약, 승패, 카드 적용 결과를 presentation 코드가 직접 확정하면 실패로 본다.

## 다음 확장 순서

첫 slice가 통과하면 아래 순서로 확장한다.

1. 곡사탄을 추가해 거리, 고저차, 엄폐 뒤 압박 양상을 검증한다.
2. 벽 몰이 구간 또는 반사/각도 구간을 별도 구간 패턴으로 분리한다.
3. 낙사 또는 추 중 하나를 추가해 간단한 구조물 위험을 검증한다.
4. 저격탄 운용은 TTK 단축 리스크를 검토한 뒤 후순위로 실험한다.
5. 추가 발사 리듬형 카드는 탄환 변화형 풀과 분리한 상태에서 실험한다.
6. 이동/액션 확장 카드를 별도 액션성 트랙으로 검증한다.
7. 구조물 상호작용은 로그와 truth 기준이 준비된 뒤 추가한다.
