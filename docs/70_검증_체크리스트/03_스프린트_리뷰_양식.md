# 스프린트 리뷰 양식

이 문서는 한 주 또는 한 작업 단위가 끝났을 때 결과를 정리하는 양식이다.

목적은 많이 했다는 보고가 아니라, 빌드 상태, 남은 리스크, 다음 결정이 무엇인지 명확히 남기는 것이다.

## 양식

```markdown
# 스프린트 리뷰: <주차 또는 기간>

## 이번 목표
- 목표:
- 성공 기준:

## 완료 항목
| 항목 | 담당 | 결과 | 검증 |
|------|------|------|------|
| | | | |

## 미완료 / 이월
| 항목 | 사유 | 다음 처리 | 블로커 |
|------|------|-----------|--------|
| | | | |

## 빌드 상태
- 빌드 버전:
- 커밋 또는 빌드 식별자:
- 실행 가능 여부:
- 알려진 문제:
- smoke 결과:

## 기준문서 영향
- 새로 확정된 결정:
- 바뀌어야 하는 기준문서:
- 보류된 결정:

## KPT
- Keep:
- Problem:
- Try:

## 다음 목표
- 다음 작업의 가장 중요한 질문:
- 반드시 줄여야 하는 리스크:
- 다음 기능 스펙:
- 다음 플레이테스트 질문:
```

## 작성 규칙

- 완료 항목에는 검증 결과를 같이 적는다.
- 미완료 항목은 비난이 아니라 다음 처리 방식으로 적는다.
- 기준문서 변경이 필요한 경우 문서명과 변경 이유를 남긴다.
- 다음 목표는 작업 목록보다 "무엇을 검증할 것인가" 중심으로 쓴다.

## 리뷰 판정

스프린트 리뷰의 결론은 아래 중 하나로 남긴다.

| 판정 | 의미 |
|---|---|
| Continue | 다음 목표로 진행 가능 |
| Narrow | 스코프를 줄이고 핵심 루프 또는 안정화에 집중해야 함 |
| Blocked | P0/P1 결정, 기술 블로커, 인력 병목 때문에 진행 불가 |

`Narrow` 또는 `Blocked`가 나오면 다음 스프린트 목표보다 먼저 줄일 리스크를 적는다.
