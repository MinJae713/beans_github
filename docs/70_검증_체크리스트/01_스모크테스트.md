# 스모크테스트

이 문서는 기준문서 관점의 smoke gate다. 기존 구현 문서나 프로토타입 smoke 항목은 reference로만 사용하며, MVP 기준과 충돌하면 이 문서의 기준을 우선한다.

## 목적

기본 브랜치, 통합 브랜치, 또는 공유 빌드는 항상 한 판 플레이 가능해야 한다.

컴파일 성공만으로 완료로 보지 않는다. 플레이어 이동, 공격, 피격, 카드 선택, 리스폰, 구간 진행이 최소한 끊기지 않아야 한다.

## 검증 종류

| 종류 | 용도 |
|---|---|
| EditMode tests | 카드/수치/순수 규칙 검증 |
| PlayMode tests | Unity 런타임 상호작용 검증 |
| Manual smoke | 사람이 직접 한 판 흐름을 확인 |
| Standalone build smoke | 빌드 결과물이 에디터와 동일하게 동작하는지 확인 |

## 작업 유형별 최소 검증

| 작업 유형 | 최소 검증 |
|---|---|
| 전투/이동/피격 | PlayMode 또는 manual smoke + 이동/공격/사망 확인 |
| 카드/밸런스 | EditMode 또는 PlayMode + 스탯 적용과 수치 변경 요약 |
| UI/VFX | manual smoke + 스크린샷/영상 + 입력 방해 여부 확인 |
| 레벨/맵 | manual smoke + 리스폰/카메라/구간 돌파/낙사 확인 |
| 기술 구조 | 컴파일 + 관련 EditMode/PlayMode 또는 build smoke |
| 문서/기획 | 관련 기준문서 충돌 여부와 미결정 사항 표시 |

## Manual Smoke 최소 항목

아래 항목은 MVP 기준 최소 smoke다. legacy 구현 체크리스트가 별도로 있더라도, 대시/더블점프처럼 MVP 보류 항목을 필수 smoke로 끌어올리지 않는다. MVP 기믹 행동은 딱밤만 의미하며, 슬라이딩 태클은 확장 후보로 둔다.

| ID | 확인 |
|---|---|
| SMK-01 | 런타임 부팅, 두 플레이어 표시 |
| SMK-02 | P1 이동/점프/기본 발판 이동 |
| SMK-03 | P2 이동/점프/기본 발판 이동 |
| SMK-04 | P1 발사/딱밤 기믹 행동 |
| SMK-05 | P2 발사/딱밤 기믹 행동 |
| SMK-06 | 피격/사망/리스폰 |
| SMK-07 | 카드 선택 UI 클릭과 적용 |
| SMK-08 | 구간 또는 방 전환 |
| SMK-09 | 승리 조건 |
| SMK-10 | HUD와 스크린샷 |

## 산출물 위치

raw 결과물은 레포에 직접 넣지 않는다.

```text
<local-artifacts-root>/<YYYYMMDD-HHMM>-<short-task>/
- logs/
- screenshots/
- traces/
- temp/
- notes.md
```

공유가 필요한 경우에만 `docs/`에 짧은 요약을 남긴다.

## 자동 테스트 증빙 규칙

Unity 배치 테스트는 프로세스 종료코드만으로 충분하지 않다. 가능한 경우 테스트 결과 XML과 로그를 함께 남긴다.

| 상황 | 처리 |
|---|---|
| XML 생성 성공 | XML 경로, 로그 경로, 프로세스 종료코드를 함께 기록 |
| XML 미생성 | 로그 경로, 종료코드, XML 미생성 사유를 기록 |
| 종료코드 0 + 경고 | 경고가 플레이/빌드 차단인지 판단해 계속/중단 기록 |
| 종료코드 비정상 | 실패로 기록하고 기본/통합 브랜치 병합 또는 accepted 승격 금지 |

`DirectoryNotFoundException`, package import warning, URP import warning처럼 환경 또는 패키지 문제로 보이는 로그가 있으면 아래 중 하나로 분류한다.

- `continue`: 테스트 대상 기능과 직접 관련 없고 플레이/빌드를 막지 않는 경고.
- `isolate`: 원인 분리는 필요하지만 이번 기능 검증은 독립적으로 가능한 경고.
- `blocked`: 패키지, 렌더 파이프라인, 입력, 물리 초기화 문제로 기능 검증 신뢰성이 깨지는 경고.

## 실패 처리

- smoke 실패 시 기본/통합 브랜치 병합 또는 accepted 승격을 하지 않는다.
- 실패 결과는 숨기지 않고 Handoff Summary의 `남은 리스크`에 기록한다.
- 실패가 게임 규칙, 아키텍처, 공유 에셋, 네트워크 구조 충돌 때문이면 `BLOCKED`로 보고한다.
- 단순 구현 디테일이면 가정을 명시하고 수정 또는 후속 작업으로 넘긴다.
