# 마일스톤 게이트

이 문서는 일정표가 아니라, 각 개발 단계가 다음 단계로 넘어갈 수 있는지 판단하는 게이트 기준이다.

날짜, SP, 개인별 태스크는 여기서 고정하지 않는다. 실제 일정은 팀 운영 도구에서 관리하고, 이 문서는 단계별 통과 조건만 관리한다.

## 게이트 원칙

- 게이트는 "얼마나 만들었는가"보다 "다음 단계 리스크를 감당할 수 있는가"를 판단한다.
- 실패한 게이트는 숨기지 않고 스코프 축소, 폴백, 추가 검증 중 하나로 처리한다.
- 수치 목표가 필요하면 기준문서가 아니라 플레이테스트 리포트 또는 밸런스 프리셋에 둔다.

## 판정 방식

| 판정 | 의미 |
|---|---|
| Pass | 다음 단계로 넘어가도 되는 상태 |
| Conditional | 조건부 통과. 남은 리스크와 보완 작업을 명시하고 진행 |
| Fail | 다음 단계로 넘기면 리스크가 커지므로 스코프 조정 필요 |

게이트 판정은 스프린트 리뷰, 플레이테스트 리포트, smoke 결과 중 하나 이상의 근거와 연결한다.

## 게이트 구조

| 단계 | 질문 | 통과 의미 |
|---|---|---|
| G1 | 코어 전투가 성립하는가 | 이동, 공격, 피격, 사망, 승패가 한 판으로 연결 |
| G2 | 카드가 재미를 바꾸는가 | 패배 보상 카드가 전투 양상을 실제로 변화 |
| G3 | 네트워크 데모가 가능한가 | Fusion 구조에서 입력/피격/리스폰 동기화 가능 |
| G4 | 발표 가능한 빌드인가 | 크래시 없이 설명 가능한 완성도 확보 |

## G1: 코어 전투

진입 조건:

- Unity 프로젝트가 팀 기준 기술스택으로 열리고 실행된다.
- 최소 전장 또는 테스트 씬이 존재한다.

통과 조건:

- 두 플레이어가 같은 전장 안에서 이동, 점프, 공격을 할 수 있다.
- 피격, 사망, 리스폰 흐름이 끊기지 않는다.
- 승패 조건이 최소 한 가지 이상 동작한다.
- 조작감 또는 카메라가 전투 판단을 방해하지 않는다.

실패 시 처리:

- 전투 기능을 줄이고 이동/공격/사망 루프부터 고정한다.
- 카드, VFX, 온라인 작업은 보류한다.

## G2: 카드와 타격감

진입 조건:

- G1이 Pass 또는 Conditional 상태다.
- 구간 돌파 패배 이후 카드 지급 흐름을 테스트할 수 있다.

통과 조건:

- 카드 선택이 전투 복귀 흐름 안에 자연스럽게 연결된다.
- 카드가 단순 수치 증가가 아니라 전투 양상을 바꾼다.
- 타격, 사망 원인, 구간 돌파 패배, 카드 획득 피드백이 플레이어가 이해할 수 있는 수준이다.
- 기준문서의 밸런스 철학과 충돌하는 카드가 없다.

실패 시 처리:

- 카드 수를 늘리지 않고, 기존 카드의 역할 구분과 피드백을 먼저 고친다.
- 구체 수치는 프리셋 실험으로 분리한다.

## G3: 네트워크

진입 조건:

- 로컬 전투 루프와 카드 적용 루프가 단독 실행에서 깨지지 않는다.
- 네트워크에 올릴 상태와 시각 연출로만 처리할 상태가 구분되어 있다.

통과 조건:

- 1차 시연 목표인 Host Mode에서 매치가 시작된다.
- 입력, 위치, 피격, 사망, 리스폰, 카드 적용이 양쪽에서 같은 의미로 보인다.
- 네트워크 문제와 게임 규칙 문제가 구분되어 기록된다.
- 온라인 완성이 어렵다면 로컬/LAN 폴백 기준이 명확하다.
- Server Mode 전환은 1차 시연의 필수 통과 조건이 아니라 2차 릴리스 준비 조건으로 분리한다.

실패 시 처리:

- 온라인 범위를 줄이고 로컬 2P 데모 안정성을 보장한다.
- 네트워크 구현이 게임 규칙을 바꾸지 않도록 한다.

## G4: 데모 빌드

진입 조건:

- G3이 Pass 또는 Conditional 상태다.
- 발표에서 보여줄 핵심 루프와 폴백 루프가 정해져 있다.

통과 조건:

- Windows Standalone 빌드가 시작부터 매치 종료까지 설명 가능한 흐름을 제공한다.
- 알려진 치명 버그가 남아 있지 않다.
- 플레이테스트 결과와 남은 리스크가 문서화되어 있다.
- 발표자가 게임의 핵심 재미와 기술 선택을 설명할 수 있다.
- Photon Cloud Host Mode가 실패할 경우 LAN Host Mode 또는 로컬 2P 폴백으로 발표 흐름을 유지할 수 있다.

실패 시 처리:

- 새 기능 추가를 멈추고 안정화, 연출, 설명 가능성에 집중한다.

## 2차 릴리스 후보 게이트

G4 이후 공개 베타나 외부 배포를 검토할 때 아래 항목을 별도 게이트로 둔다.

| 항목 | 통과 기준 |
|---|---|
| Server Mode | Host Mode 코드와 게임 규칙 차이 없이 전환 가능 |
| WebGL | Photon WebSocket 접속과 Standalone 크로스플레이 검증 |
| 리더보드 | 게임 루프와 분리된 최소 영속 데이터 경로 확인 |
| 공개 베타 폴백 | WebGL 실패 시 Standalone 배포 경로 유지 |

## 완료 판정

마일스톤 게이트 기록은 아래 조건을 만족하면 완료로 본다.

- 각 게이트에 Pass, Conditional, Fail 중 하나의 판정이 있다.
- 판정 근거가 smoke, 플레이테스트, 스프린트 리뷰 중 하나 이상과 연결되어 있다.
- Conditional 또는 Fail의 경우 줄일 스코프, 폴백, 추가 검증 중 하나가 적혀 있다.
- 기준문서에 구체 수치를 새로 고정하지 않았다.
