# Colloseum 게임개발 기준문서

이 문서 묶음은 Colloseum 팀이 같은 게임을 만들기 위해 공유하는 게임개발 기준문서다. `Colloseum`은 현재 프로젝트 코드명이며, 최종 게임명은 `90_백로그/04_미결정_질문_레지스터.md`의 Q32에서 별도 확정한다.

단순 요약본이 아니라, 기획 판단, 구현 금지선, 협업 방식, 검증 기준을 함께 담는 상세 명세서로 사용한다. 팀원이나 AI 도구가 이 문서만 읽어도 현재 게임의 핵심 맥락과 작업 기준을 복구할 수 있어야 한다.

## 현재 SOT 선언

| 구분 | 기준 |
|---|---|
| 팀 공유 기준문서 루트 | `docs/` |
| 구현 GitLab | `https://lab.ssafy.com/s14-final/S14P31A303` |
| 현재 binding 기준 | `accepted` 문서. `accepted_candidate`는 `05_문서관리_규칙/08_문서_상태_인덱스.md` 또는 작업 브리핑에 명시된 경우만 binding |
| 현재 accepted 문서 | `10_게임플레이_기준/02_라운드_상태머신.md`, `50_기술_구조_기준/01_Unity_프로젝트_구조.md` |
| 참고 가능 문서 | `candidate` 문서. 작업 브리핑에 가정과 중단 조건을 적은 경우에만 구현 참고 |
| 참고 전용 문서 | 기존 `docs/게임개발_기준문서/`, `docs/planning/`, `docs/development/`, 회의 원문, 프로토타입 관찰 기록. 접근할 수 없어도 현재 SOT 탐색을 위해 찾지 않는다 |
| 사용 금지 기준 | `90_백로그`, `99_아카이브`, raw 회의 메모, legacy 구현 상태를 현재 SOT처럼 인용하는 것 |
| Git 운영 상태 | Jira/Git 컨벤션은 현재 `candidate` 운영안이다. 실제 GitLab 설정과 담당자 지시가 우선한다 |

충돌이 있으면 이 디렉토리 안의 `accepted` 문서와 `05_문서관리_규칙/06_의사결정_로그.md`에 반영된 결정이 우선한다. 회의 원문이나 프로토타입에서 나온 내용은 이 기준문서 또는 의사결정 로그에 반영되기 전까지 현재 구현 기준이 아니다.

## 공유 사용 안내

- 이 폴더만으로 게임 방향과 작업 기준은 복구 가능해야 한다.
- `accepted`와 명시된 `accepted_candidate`는 구현 기준으로 사용할 수 있다는 뜻이지, 브리핑 없이 코드 수정 권한이 생긴다는 뜻이 아니다.
- 실제 코드, 에셋, 공용 프리팹, 네트워크 설정 수정은 Jira 이슈 또는 작업 브리핑이 있을 때만 착수한다.
- 작업 브리핑에는 참조한 `accepted`/`accepted_candidate` 문서, 임시 가정, 중단 조건, 검증 기준을 적는다.
- plain `candidate` 문서는 참고 후보이며, 구현하려면 작업 브리핑에 임시 가정, 소유자 승인, 중단 조건을 적는다.
- 직접 링크로 개별 문서만 받았더라도 먼저 이 README와 `05_문서관리_규칙/08_문서_상태_인덱스.md`를 확인한다.
- 과거 reference/source 경로가 공유본에 포함되지 않거나 접근할 수 없어도 현재 SOT가 누락된 것으로 보지 않는다.

## 문서가 해결하려는 문제

| 문제 | 기준문서의 역할 |
|---|---|
| 팀원마다 게임을 다르게 이해함 | 전장, 구간, 전투, 카드, 승리조건의 공통 정의를 제공 |
| 구현자가 임의로 게임 규칙을 확정함 | 확정, 임시 가정, 보류, 금지 상태를 분리 |
| AI 도구가 세션마다 다른 방식으로 작업함 | 작업 브리핑, 중단 조건, 검증 보고 기준을 제공 |
| Unity 협업에서 씬, 프리팹, 네트워크 설정 충돌이 남 | 소유권, MR, 검증 기준을 문서화 |
| 수치 조정이 기준문서를 계속 흔듦 | 원칙은 문서에, 수치는 BalanceProfile 계열 프리셋에 분리 |

## 상태 규칙

문서에는 세 가지 상태축이 있다. 서로 섞어서 읽지 않는다.

| 상태축 | 값 | 의미 |
|---|---|---|
| 문서 상태 | governance | 문서 루트, 상태, 변경 절차, 의사결정 로그처럼 SOT 사용법을 정의 |
| 문서 상태 | accepted | 현재 구현 기준. 충돌 시 우선 준수 |
| 문서 상태 | accepted_candidate | 임시 구현 기준. 작업 브리핑에 가정과 중단 조건을 적고 사용 |
| 문서 상태 | candidate | 참고 후보. plain candidate만으로 구현하려면 영역 소유자 확인 필요 |
| 문서 상태 | reference | 배경, source, handoff. 현재 구현 기준을 대체하지 않음 |
| 문서 상태 | backlog | 후순위 작업, 미결정 질문, 제안. 구현 지시가 아님 |
| 문서 상태 | archive | 폐기, 대체, 기록 보존. 현재 기준으로 인용 금지 |
| 결정 상태 | 확정 | 현재 MVP 구현 방향 |
| 결정 상태 | 임시 가정 | 구현 가능하나 재확인 시점이 필요 |
| 결정 상태 | 보류 | MVP 이후 또는 별도 회의에서 재검토 |
| 결정 상태 | 금지 | 현재 게임 방향과 충돌 |
| 질문 상태 | open | 구현 전 답이 필요할 수 있음 |
| 질문 상태 | assumed | 임시 가정으로 진행 가능 |
| 질문 상태 | blocked | 답이 없으면 구현 중단 |
| 질문 상태 | closed | 결정이 기준문서 또는 프리셋에 반영됨 |
| 질문 상태 | deferred | 지금 구현 기준이 아님 |

충돌이 있으면 `accepted` 문서, `accepted_candidate`로 명시된 임시 가정, `05_문서관리_규칙/06_의사결정_로그.md`에 반영된 최신 결정을 순서대로 확인한다. 회의 원문, 프로토타입 상태, legacy docs는 이 기준문서에 반영되기 전까지 현재 SOT가 아니다.

## 기준문서와 수치 데이터 분리

| 구분 | 기준문서가 다루는 것 | 프리셋이 다루는 것 |
|---|---|---|
| 전투 | TTK가 너무 짧으면 안 된다는 판단 기준 | 체력, 피해량, 탄속, 장탄수 |
| 카드 | 카드 지급 조건, 티어 제한, 효과 축 | 실제 카드별 수치와 가중치 |
| 구간 | 전장 구조, 이동 주도권, 최종 승리 흐름 | 구간 길이, 카메라 속도, 리스폰 좌표 |
| 구조물 | 대응 가능해야 한다는 원칙 | 구조물 피해량, 주기, 속도 |

기준문서에 수치가 등장하면 확정값이 아니라 예시 또는 프리셋 후보로 본다. 최종 수치는 `85_밸런스_프리셋`과 Unity 구현체에서 관리한다.

## 변경 원칙

- 기준문서는 논의 없이 즉흥 수정하지 않는다.
- 게임 규칙, 네트워크 truth, 공용 프리팹 소유권, 카드 지급 조건을 바꾸는 변경은 먼저 담당자 확인을 거친다.
- 문서를 바꾸면 변경 이유와 영향을 받는 구현 영역을 같이 남긴다.
- Jira/Git 컨벤션은 실제 팀 GitLab 설정과 다를 수 있으므로, 충돌하면 담당자 확인 후 갱신한다.
- 서비스 식별자, 비밀값, 계정 정보, 개인 PC 경로는 기준문서에 기록하지 않는다.
