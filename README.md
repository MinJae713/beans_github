# 쿡싸피 (Cook SSAFY)

> 레시피 DAG와 주문 타임라인을 바탕으로, 학생이 작성한 `decide(state)` 코드가 주방을 운영하는 알고리즘 학습형 시뮬레이션 게임

## 프로젝트 소개

쿡싸피는 학생이 직접 캐릭터를 조작하는 요리 게임이 아닙니다.  
학생은 `cook.py` 파일에서 `decide(state)` 함수를 작성하고, 시뮬레이터는 이를 매 틱 호출하여 주방의 다음 작업을 결정합니다.  
실행 결과는 리플레이, 로그, 성능 지표를 통해 확인하며, 사용자는 자신의 로직이 어떤 운영 결과를 만들었는지 분석하고 개선할 수 있습니다.

## 핵심 학습 목표

- **위상정렬 기반 사고**
  - 레시피 DAG에서 현재 수행 가능한 작업 판별
  - 선행조건을 만족하는 유효한 작업 순서 구성
- **시간 제약 기반 우선순위 판단**
  - 주문 도착 시각, 마감 시각, 작업 시간을 함께 고려
  - 여러 유효한 작업 중 무엇을 먼저 처리할지 결정
- **확장 학습**
  - 공유 선행작업의 전략적 가치
  - 복수 직원 환경에서의 assignment 문제

## 핵심 구조

- 학생은 `cook.py` 에서 `decide(state)` 구현
- 시뮬레이터는 틱 기반으로 영업 시간을 진행
- 각 주문은 레시피 DAG를 가짐
- 현재 가능한 작업만 선택 가능
- 잘못된 작업 지시는 무시되고 로그에 기록
- 결과는 점수, 로그, 리플레이 UI로 제공

## MVP 범위

현재 MVP 범위는 다음과 같습니다.

- Chapter 1 ~ 5
- 단일 직원(`worker-1`)
- `decide(state) -> Assignment | None`
- Pyodide 기반 브라우저 실행 환경
- React + Dagre + Zustand 기반 리플레이 UI
- 결정론 시뮬레이션
- 기본 참조 정책 내장
  - FIFO
  - ShortestCurrentDuration
  - ShortestRemainingWork
  - EDF
  - SharedFirst

## 기술 스택

- **Frontend**: React, Vite, Zustand, Dagre
- **Runtime / Sandbox**: Pyodide
- **Language**: Python
- **Core Logic**: 틱 기반 시뮬레이터, DAG 기반 상태 모델

## 실행 흐름

1. 학생이 `cook.py`에서 `decide(state)`를 작성
2. 시뮬레이터가 매 틱 현재 상태를 전달
3. 학생 코드가 다음 작업을 반환
4. 시뮬레이터가 유효성 검증 후 작업 반영
5. 실행 종료 후 리플레이와 KPI 제공

## 기대 효과

쿡싸피는 단순한 조작형 게임이 아니라,  
**“가능한 작업을 읽는 능력”과 “그중 무엇을 먼저 할지 정하는 능력”**을 함께 훈련하는 프로젝트입니다.

학생은 한 번의 플레이를 통해 다음을 학습할 수 있습니다.

- 내 코드가 DAG 구조를 제대로 이해했는가
- 어떤 작업이 병목이 되었는가
- 마감과 작업 시간을 고려한 정책이 왜 중요한가
- 더 나은 우선순위 로직으로 어떻게 개선할 수 있는가
